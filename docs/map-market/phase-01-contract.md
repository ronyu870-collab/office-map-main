## 范围与执行路径

契约版本 `map-market/1`。API 的身份校验继续使用 `resolveEffectiveRequestIdentity`；viewer/editor/admin 当前共享读取范围，未知角色拒绝。库存继续限定 active、tracked、非 future。没有修改权限、审计、正式提交、草稿或历史数据。

| 集合 | 含义与消费者 |
| --- | --- |
| authorized_market | 身份校验后的完整库存，不以坐标作为成员资格 |
| filtered_market | MapDataStore 按搜索、区域、LEED、类型、数值及对比条件筛选的库存；首页 KPI、气泡、详情核心指标和项目列表共同使用 |
| mappable_market | 筛选结果中有有限且合法经纬度的项目，仅用于定位／绘点；不作为市场分母 |
| quarterly_market | 同一个真实季度的已发布观测，按需读取；研究趋势固定使用完整授权子市场，不随地图筛选改变 |
| future_supply | 独立未来供应，排除已入市和 pending；有独立数量、已知面积、面积样本数 |

首屏：`/api/map/data` → 启动转换 → MapDataStore → 当前筛选 → `aggregateMarket`／`submarketSummary` → KPI、气泡、详情。启用中的 V3 与备用 native 渲染器均使用传入集合，不再隐式替换成控制器完整缓存。

历史：打开子市场 → `/api/map/submarket` → 同口径授权库存 ID → 分批读取正式季度记录 → `computeSubmarketTrends`。不新增默认请求、每子市场首屏请求、AI 请求或拖动／缩放数据库查询；首屏与兼容读取均使用每楼最新正式记录，不预载全部历史。

## 正式季度治理与 Q3 边界

唯一事实来源继续复用 `building_metrics`，与既有 AI 5.0 `20261120095500_ai5_quarterly_sources.sql` 一致：`is_locked = true AND is_draft IS NOT TRUE`。`quarterly_submissions` 是正式提交的业务记录，并不等于已审核发布的市场观测；它的空置率单位为百分数，而 building_metrics 为 0–1 比例，禁止直接混用。

生产只读结果：

- 2026Q2：594 条 building_metrics，全部 locked=true、draft=false，租金和空置率均已收录。
- 2026Q3：732 条 submissions（705 条有租金，708 条有空置率）；只有 6 条 building_metrics，全部 locked=false、draft=false，其中仅一条有租金及空置率。
- 已发布 building_metrics 的同楼同季度重复组为 0；新契约仍定义确定性版本排序，以处理未来重复候选。
- 已检查的提交 RPC 将输入写入 submissions 和幂等／来源台账，不写入 building_metrics；生产 submissions 的触发器为身份归一、updated_at 和审计，没有季度发布同步触发器。未发现可将这批 Q3 自动认定为公开行情的发布证据。外部人工审核／发布流程仍需业务方核实。

因此正式季度仍显示 Q2 有真实依据；不能把 Q3 填报直接当作发布成功，也不能用 Q2 数据补成 Q3。历史旧 relabel 迁移和新 provenance 的含义沿用季度治理文档，不以时间戳推断旧行是否真实新观测。撤回提交不自行转成市场事实；若要撤销已发布观测，应通过现有管理权限撤销其发布资格，再失效缓存。

正式候选排序：有效季度 → 已锁定且非草稿 → updated_at → created_at → 稳定记录 ID（bigint 按数值）。同季度与最新状态共用比较器。服务端先过滤发布资格再按此顺序 limit，避免先取到草稿而丢失较早正式事实。

- 当前状态：每楼最新正式记录，保留其真实 record_year/record_quarter；聚合对象返回 periods 分布及 `latest_formal_per_building` 方法，允许混合最新状态，但不命名为统一季度行情。
- 正式行情：指定同季度有效观测，不跨期取值。趋势返回每个指标是否有观测、样本数量／面积、覆盖率、来源、连续性、样本变化和各自最新有效期。
- 现有源没有历史区域／等级成员快照，全部历史序列注明 `membershipTime=current_catalog`；本次没有虚构历史分类。

本阶段没有迁移、回填、批量锁定或生产写入。若业务要求发布 Q3，应另行形成审核清单、来源与单位映射、重复／身份核验、保留前后快照的可回退发布方案，再按明确生产授权执行；本 PR 不自动执行。

## 指标与缺失值

`aggregateMarket` 是 KPI、子市场及趋势的共用计算入口。首页 KPI 为筛选存量（含产业园）；子市场租金／空置率明确为甲乙级，其中 P 计入甲级，产业园另计，不能按相同名称隐去范围差别。

| 指标 | 规则 |
| --- | --- |
| 租金 | 非负有限净有效租金 × 同观测有效正面积 / 租金有效面积之和；单位元/㎡/月，不改写既有 36 月净租金业务模型 |
| 空置率 | 有效空置面积之和 / 对应观测总面积之和；输出百分数。空置面积已知且 0≤vacant≤area 时优先，否则使用有效 0–1 观测比例乘该行面积，仅在聚合中推导 |
| 存量面积 | 同范围每楼选中正式记录的有效非负 total_area 之和；同时保留已知面积项目数。未知面积不造为 1 或 0 |
| 覆盖率 | 每指标有效样本数 / 对应范围项目数；有效样本面积 / 已知存量面积。未知分母返回 null；面积覆盖不能证明缺失面积项目已覆盖 |
| 分类 | 精确别名字典识别 A、B、P、Grade A/B、Premium Grade A、甲乙／超甲、BP/Business Park／产业园；其他字符串保持 unknown/other |
| 可定位数量 | 合法经纬度项目数，独立于库存、有效租金／空置样本 |
| 环比／同比 | 必须分别存在相隔 1／4 个真实季度的观测；各期至少两有效样本。租金提供绝对变化与百分比，空置率变化用百分点 |
| 同样本变化 | 同期真实成员 ID 交集，分别对租金、空置重算两期加权值，至少两共同样本；返回交集数量，区别于普通市场样本变化 |

null、undefined、空白、NaN、无穷和非法数值不进入有效样本；真实 0 租金与 0% 空置保留，0 面积可作为已知面积但不作为加权分母。读取失败由 API／组件错误状态承接，不伪装为零项目；未收录观测以 null、0 样本表示，尚未发布不能根据系统日历猜测。单一样本仍提供观测和 sampleQuality，但不计算市场变化；没有新增人为插值或补零。

子市场别名统一入口 `marketIdentity.ts`，覆盖望京—酒仙桥和亦庄历史名；玉渊潭、四季青、通惠河传媒走廊、上地、北清路、丰台科技园保留各自身份。零甲乙级但有园区的气泡显示产业园数量。

## 参考值与缓存

150／140 两个旧参考租金只保留为结构化历史证据，含 reference_estimate、原代码来源、适用区域、单位、未知日期／维护人、unverified、allowDisplay=false、allowAggregation=false。气泡不再用前端星号混入参考租金；没有证据时显示未收录。它们不进入任何 market metrics 集合。

浏览器快照按凭证、身份、模拟用户、路径隔离，增加契约版本；保留 30 秒 TTL、失败删除与退出清理。管理端 building_metrics／building_current_data 写入和楼宇／供应更新会清理地图读取缓存；地图楼宇编辑继续刷新控制器与当前选择。不新增跨用户服务端缓存。其他会话或外部发布后的新读取最多复用 30 秒，已打开地图的内存快照仍须刷新／重新进入；不宣称有生产实时推送。
