# Pitch Studio 1.1 模板生态

本轮在 main `644606e31b554fc449244f89541774fad3fed2da` 的六阶段能力上扩建，未重建素材、权限、可信查询、任务或导出体系。完整收到的任务止于“保持已有 colliers-pitch/1 和历史项目可读性”；不推断附件缺失尾部。模板清单见[业务与布局目录](template-catalog.md)，许可及精确来源见[开源迁移记录](template-sources.md)。

## 五层结构与版本

| 层 | 责任入口 | 约束 |
| --- | --- | --- |
| Design Tokens | `design/theme.ts` | 两套可替换主题；品牌色、字体、字号、安全区、图表与表格由主题提供 |
| Visual Components | `layout/components.ts`、`layout/table.ts` | 共用字体度量、原生文本／表格／图表、照片、人员、案例、时间节点与形状 |
| Layout Patterns | `layout/patterns/catalog.ts`、`engine.ts` | 48 个新增受控声明式结构，归一化插槽与背景关系；无 URL、脚本、字体和业务事实 |
| Business Templates | `templates/ecosystem.ts`、`business/recipes.ts` | 80 个新增业务用途、字段顺序与内容容量，复用原有 15 个业务配置和 9 个可用数据模板 |
| Deck Kits | `templates/deckKits.ts` | 8 套、各 10 节；版本化章节组合，与业务数据、布局、主题分离 |

新增布局版本 2、业务模板及套装版本 1，使用稳定 ID。内容协议仍为 `colliers-pitch/1`；旧 12 个 `legacyLayoutIds`、原模板配置和已存 scene 不改写。`layoutIdSchema` 改为受控注册校验，不能由用户注册可执行配置。新结构当前只支持 standard 变体；alternate 明确拒绝，不静默切成无关布局。已有业务配置的历史 revision、场景主题快照、页码及来源继续可读。

同一布局由多个业务模板复用。普通业务配置仍可选既有布局；新增已验证业务模板锁定其已审查的布局和有序字段，避免管理员仅换 ID 后把不兼容内容标记为正常可用。

## 容量和原生对象

插槽使用同一 SlideScene 生产网页 SVG、缩略图、PNG 和 PPTX。文字按捆绑 Noto Sans SC 的真实字形测量换行；固定可读字号，保留全文分页，最多 50 页。表格按列宽及行高分页，图表过密、不同单位单轴、超大数值、未知类型和必填字段缺失明确失败，不把错误数据强行塞入页面。常规文本、表格、图表、关系图形保持原生可编辑对象；三角、梯形、chevron 共享结构，预览不使用独立整页设计。

照片需已有获权媒体，保持原始裁切与像素检查。特殊地图、Stacking Plan 等既有不可用数据能力仍不可用，不因示例存在而扩大权限。对不可见信息、隐藏对象、备注和内嵌数据继续执行现有导出清洗及授权。

## 示例、套装与正式内容

模板中心所有可用条目的缩略图来自 `fixtures/business.ts` 调用真实业务内容构建器及布局引擎，包含当前主题和数据库 recipe revision 的缓存键。新入口“示例与套装”提供模板筛选、单页复制、8 套章节选择、独立演示项目及逐节正式素材配置。手机复用同一控件和持久化路径。页面继续支持私人编辑、顺序调整、保存、重开、历史及导出。

示例使用明确标识的合成项目、成员、数据和图片，不伪称高力业务。复制示例走既有 sample 原件／哈希／私有存储与 business_generate_commit：原件为私人草稿，生成副本仅供本人内部使用，`isTestData=true`，禁止对客及外部 AI。用户文本编辑不会把其变为正式企业事实。正式套装必须为各节选择已发布、有效、获权的结构化业务素材；保存为同一持久任务，继承项目期间、语言与主题，失败不会替换原页。

80 个新增配置不新增数据源，不自动计算正式预算、评分、目标、政策影响或回报。正式使用条件是素材维护者提供相应有序字段的 custom 业务档案并发布；普通模板面板展示必需字段，并选择获权资料。复杂档案目前沿用管理中心高级结构化编辑入口，尚未提供任意版式自由绘制或自动理解所有历史 PPT 的承诺。

任务复用真实工作台执行器、租约、有限重试、取消、版本冲突和生成凭据。`workspacePartSchema` 只增加 example、bundle 两个受控模式，保留旧 static/semi-dynamic/dynamic；服务端重新校验模板状态、套装版本／成员、作用域、素材及媒体。管理员撤回模板或账号撤权后拒绝生成；已生成文件下载仍重新验证数据和素材权限。

## AI 与扩展方法

确定性理解按内容类型和真实插槽容量筛选最多 6 个兼容配置，优先匹配同名业务用途。自然语言可使用当前已启用模板的中文名、英文名或 ID；缺少素材、过量素材、模板停用和未知约束均要求澄清。此路径不调用模型，不继承任意文档内指令；实际生成仍复核发布和披露权限。原有受控模型理解与资料授权不变。

新增布局：在 catalog 定义结构和容量，添加独立 fixture，验证两语言、两主题、几何及原生对象，再新增只插入该版本的迁移。新增业务模板：定义稳定 ID、业务目的、有序字段及已有布局；添加真实合成示例和生成测试。新增套装：仅引用已注册业务模板，定义版本、顺序及参数继承。不要把一个颜色变体计为新结构，也不要用不可用连接器充数。

## 迁移与上线边界

新增 `20261126083359_pitch_studio_template_ecosystem.sql`，由 Supabase CLI 创建，插入 48 个布局版本及 80 个业务配置；不改生产开关、grants、企业资产或旧注册定义。本地 PG17 验证了新增注册、历史 12 模板不变及允许／拒绝路径。生产本轮迁移尚未应用；不得重放前六阶段的生产迁移。

发布需先合并／部署兼容代码并应用这一份新迁移，再核对当前账号 catalog、缩略图、私人示例任务及内部文件。示例不能用于验证对客导出成功；原有外部 AI／对客生产正向验证状态见[生产记录](production-rollout.md)，不得以本轮隔离检查冒充完成。

## 可复现生成与验证

```sh
npm ci
node scripts/verification/generate-pitch-pattern-fixtures.mjs
node scripts/verification/generate-pitch-ecosystem-fixtures.mjs
npm run typecheck
npm run lint
npm test -- --maxWorkers=2
npm run build
PITCH_TEST_ALLOW_LOCAL=disposable PITCH_TEST_PG_PORT=<隔离PG17端口> node supabase/tests/pitch-studio/ecosystem.mjs
```

文件在 `tmp/pitch-ecosystem-fixtures`：104 模板 × 中文／英文 × 2 主题 = 416 份真实 PPTX，8 套 × 2 主题 = 16 份套装；另有实际 SVG／PNG 和 manifest。`CI=true` 仅跳过 PNG 栅格生成，PPTX 原生对象检查仍全量执行。单模板合成样本 47,905–185,971 bytes，平均 1.058 页、最多 3 页。

修改前基线为 15 个业务配置、9 个可用／3 个不可用动态能力及 12 布局；隔离生成 12 个布局基准样本，平均 1 页，原生文本、图片、表格和图表可验证。原业务配置共用 5 种默认布局，故没有将其计作 24 种视觉结构。修改后 60 种按真实组件几何区分，192 份双语双主题基础场景检查通过，长文精确保留、极端数值及缺失输入有执行测试。

真实 PG17 执行覆盖：全部 80 个新增正式业务模板、8 套正式素材组合、8 套私人示例、选页／分页、任务持久化与重开、内部原生文件导出、测试素材对客拒绝、未知／撤回模板及撤权。旧基础、素材库、业务、工作台、AI 路径同时回归。HTTP 场景已接入现有 GoTrue/PostgREST/Storage/生产构建 Next 验证，自动浏览器覆盖 1440／390／320 宽度的新套装入口；实际运行结果以 PR 精确 head 的 CI 为准。

本机 Office 复核：招商代理套装被 LibreOffice 实际打开并转换为 11 页 PDF（随后将两个短行动节点合为一页），原生图表与中文来源可提取；通过显式 FONTCONFIG_FILE 加载捆绑 Noto Sans SC 后检查实际页面。仅设置 SAL_FONTPATH 会在本机选到错误回退字体，不作为成功视觉证据。全仓首次执行 427 文件／3,256 测试通过；新增 AI 目录及套装拒绝路径随后单独通过。全量 Lint 为 0 error，现有 warnings 保留。真实本地 Auth 检查因 Docker 启动时磁盘耗尽及镜像 I/O 失败未执行，转由已接入的 PR CI 验证，不记为本地通过。
