## 对象定位实现与验证边界

- 在项目页面打开「调整画布对象」。选中后拖动，或用方向键微调（Shift 增大步长）。点击「应用位置」后进入原有带版本校验的保存事务；应用前移动只存在当前编辑面板。
- 服务器按已授权且未改变的 Scene 应用并验证坐标，图片、图表数值、素材引用、来源和披露不改；普通预览、下载和原生 PPTX 不携带编辑器 DOM 元素。自动布局重置须明确确认；现有 AI 工具没有调整或清除位置的权限。
- 没有迁移。单元回归检查层标记、受保护对象、重复 ID、边界及实际 PPTX DrawingML 坐标；工作台回归检查交互与重开。真实 Auth/HTTP 验证脚本另测 Postgres 持久化、拒绝越界、显式重排和实际导出，结果见 CI。

- 单页标题和唯一对应非数据段落可以双击、按 F2 或使用工具栏编辑；引用、页脚、跨页文字和正式数据正文不给予直接编辑入口。画布草稿可组合文字与移动，应用前支持撤销重做；应用后沿用项目历史。服务器以原对象边界重新度量并同时保存正文与图层，用户输入标未核验，保留原有来源并阻止转为对客稿。

- 选中图片或非背景形状后，可拖动右下角控制点，或以按钮、键盘等比缩放。缩放仍进既有保存事务与同一渲染 Scene；保留图片等比适配，图表、表格、来源、品牌和背景仍不开放缩放。移动与缩放可以一起撤销/重做。

- 当前会话中已保存的画布操作也可按页撤销、重做。服务端从己有的项目历史修订取回同一页并校验当前版本、素材版本和主题，其余页面不回滚。切换账号、关闭网页或遇到不兼容修改后不承诺保留操作栈；仍可检查项目历史。

- 图片和非背景形状可以按 15° 左右旋转、输入整数角度并归零，可和移动、缩放一起应用、撤销。编辑器和正式渲染均以对象中心为旋转轴；服务端拒绝出界，保守检查包围盒遮挡，仍不支持任意重叠。原生 PPTX 输出的是对象角度，不是把旋转后的页面拍平。

- 可在图层面板选中对象、向上或向下移动，保持 SVG、PPTX 的相同绘制顺序和长期对象 ID。背景、页脚、来源、品牌和版式线条不可重新排序。仅双方都明确开启时允许图形／图片叠放，文字、数据图表、来源等原质量校验仍生效。

- 在图层列表可以多选可编辑且尚未组合的对象，形成持久组；拖动或方向键移动任一成员会按同一增量移动整组，保持相对位置，撤销、重做与解组不改变原始内容。PPTX 导出保留最终位置和每个原生对象；暂不写出 PowerPoint 原生组。

- 工作区的提案结构先显示章节、实际素材名、版本与未包含内容。确认后由一个持久生成任务完成全部章节，支持取消、同任务重试与重新打开项目查看；素材在审阅后换版则拒绝，不自动改用新版。沿用已有项目保存事务，任一章节未完成时不把半套结果提交到目标项目。当前只编排确认素材，不自动编造实地项目或动态数据。


## 正式楼宇数据加入审阅提纲

- 项目设置关联 1–5 栋跟踪楼宇，填写一个季度。提案结构建议中点击「核对并加入正式数据」，先看每栋楼宇的数据、口径单位和缺失。之后确认是否和正式素材同批写入；只用所选楼宇、所填季度，至少每栋有该期正式记录，不用草稿、不自动回填，不发出模型请求。
- 确认时绑定审阅的实际数据、记录版本及权限状态，不使用随机查询收据当作版本。后台比较项目选项、重查授权，数据或资料变化时不追加整套章节。混合生成整批沿用正式数据的正文编辑约束及非对客导出规则；不会开放新的权限。未增加数据库迁移。
- 支持单楼概况、同季多楼对比，以及可选的租金与空置率环比、同比。历史连续趋势图、AI 决定分析范围及逐页开放独立素材章节的非数据正文编辑尚未完成。HTTP 回归新增真实登录下的换版拒绝、原稿不动和复核后成套追加；以相应提交的 CI 为准。


### 环比与同比

- 只对明确选择的同一栋楼比较指定季度、上一季度（Q1 回溯至去年 Q4）和上年同季；一次数据库快照读取。租金为相对变化率（%），空置率为两期比率之差（百分点），不混用、不折年。空档保持无有效值，不用其它季度填充。
- 审阅表和原生 PPTX 使用同一计算逻辑，发布前锁定三期证据。修改任一基准记录后需要重新审阅，不能把旧预览作为新数据提交。非所选季度的权限、非公开导出、项目编辑与整批写入规则不变。


### 文字修订的查看与采用

- 在工作台「辅助理解所选资料」或 AI 管理中心，已完成且仍获权的文字修订显示「查看修改前后」。对照列出标题及实际变化的段落、来源版本和未改块数；表格、图表和证据字段不由文字任务改写。纯脱敏处理只展示获批片段的建议，不展示完整原文。
- 保存验证同一任务、当前授权和与预览一致的内容指纹，只创建原素材范围内的私有草稿，不自动发布，不覆盖当前画布，也不触发新的模型调用。


- 在对照中逐项选择标题及段落。选项变化后必须重新核对，后端校验指纹与勾选范围一致，只采用选中的文本。部分采用跨语言建议时保留原语言标记，不将混合语言稿标为完整翻译。
- 预览采用正式默认主题、同一版式引擎，展示完整可渲染的前后素材。含图或地图、有降级转换或超过三页的素材不显示 SVG，保留文本对照；不擅自省略图片、数据或后续页。此预览不是当前项目画布副本。


- 对「从素材创建」后的未编辑单页，素材 ID、版本、正文和项目范围必须全部匹配。点击「对比当前画布」采用该页原主题、版式与已授权图片；拟稿不能溢出为多页。确认时绑定项目版本和前后对照指纹；保存事务再次确认模型处理许可，写入 AI 修订来源、保留历史且只替换目标页，仍为内部资料。
- 需要迁移 `20261126163000_pitch_workspace_revision_apply.sql`；本分支只在隔离 PostgreSQL 验证，不部署。仅针对不可对客导出的内部原素材；采用流程不增加模型调用。独立保存私有素材草稿仍可用。


- 当前页设置的「修订本页文字」不再要求先搜索素材。只对项目原样引用的一个已授权内部素材起草标题和正文修订；服务端确认原版、版本和当前项目，只有完整文字授权的任务能调用模型。处理完成后复用逐项审阅和真实画布预览；网络超时时查询同一任务，未确认前不重复提交。没有额外数据库迁移。

## PR #323 提纲到可编辑 PPTX

- 实际入口从 `/intelligence/pitch` 的「你想制作什么？」开始。点击「进入提案助手」，在新建项目的更多设置里明确选择楼宇、填写季度，创建后直接进入提案结构。可改章节标题、上移、移除，先核对资料版本和正式季度，再一次确认生成。
- 提交结果不明确时保留任务编号。先查原任务并显示工作区顶部状态。服务器暂时找不到任务时，恢复请求只能重用原编号和原提纲。资料版本或正式数据变化后，任务保留原稿并提示重新核对。混合提案的正式数据页在预览和 PPTX 中标注仅限内部，沿用服务器端对客导出拒绝。
- 生成并回读后切回页面导航，保留同一个项目，可编辑并保存，然后从项目工具栏选择「导出可编辑 PPTX」。入口默认全套、PowerPoint 和内部使用，仍支持在导出面板调整范围和格式。

### 复验入口

- 类型检查 `npm run typecheck`，改动的 TS／TSX／MJS 逐文件运行 ESLint，组件和领域行为运行 `npx vitest run --maxWorkers=2 src/components/pitch src/lib/pitch`。
- PostgreSQL 17 隔离实例内运行 `PITCH_TEST_ALLOW_LOCAL=disposable PITCH_TEST_PG_PORT=<隔离端口> node supabase/tests/pitch-studio/ai.mjs`。范围包括已有文字修订、授权、草稿及素材撤权，也核对正式素材缺项。
- 浏览器回归沿用 Verify 中 Pitch Studio 的隔离 Supabase 步骤。准备一次性本地栈及其状态 JSON 后，运行 `PITCH_TEST_ALLOW_LOCAL=disposable PITCH_WORKSPACE_BROWSER=true PITCH_AUTH_STATUS=<状态JSON> PERF_PLAYWRIGHT_MODULE=<playwright-core路径> node scripts/verification/verify-pitch-studio-http.mjs`。如已构建本版本可设置 `PITCH_TEST_REUSE_BUILD=true`。输出在 `tmp/pitch-workspace-browser/reviewed-outline.pptx` 和同名 JSON。使用两个模拟断网场景、已发布合成研究素材及图片、隔离季度记录，并在浏览器下载后解包检查原生对象。

### 本轮证据与边界

- 接手时 PR HEAD 为 `5c5d117f`，比较的远端 main 为 `d9de4947`。本轮沿用原 PR 分支，桌面浏览器从工作台创建项目，实测改名、调序、删章、正式数据变化后的原项目零页、重核后整批生成、保存研究页标题及加入已发布配图。两种断网故障分别覆盖响应丢失与请求未到达，回读确认数据库只有两次有意提交的任务。
- 浏览器下载的合成提案为七页。下载件含原生文字、两张表、一个带电子表格的折线图和一个原生图片；解包复核了页序、日期和来源，租金环比为 +25%，空置率环比为 +2 个百分点，去年同期缺值保持标记。具有对客导出资格的测试身份也无法导出该提案。将一个原生标题改写后保存并重新读取得到同一文字。
- 同一份提案在 LibreOffice 加载项目自带 Noto Sans SC 后已渲染复核。修复前两个基准季度被断开，修复后在浏览器和 PPTX 表头中都独立成行。未在不同机器的 PowerPoint 字体替换环境中验证。
- 最终差异通过类型检查、改动 Lint、110 项 Pitch 测试、24 组 PostgreSQL 场景及 33 组 HTTP 场景。浏览器包含桌面主流程以及 390 和 320 像素工作区保存、重开与导出回归。
- 本机 Docker 无响应。本地浏览器和 HTTP 回归使用常规 Next 构建、真实 PostgreSQL 17.11 与 PostgREST 16.5。GoTrue 和 Storage 由一次性本地测试替身提供。真实 GoTrue／Storage 的复验仍使用原 GitHub Verify 工作流。生产、真实企业资料和真实外部模型调用均未纳入本轮验收。
