# Pitch Studio 3.0 房地产提案编排

[业务入口](../../src/lib/pitch/proposals/index.ts) `buildProposal(snapshot, evidence, options)` 消费 Agent 08 的 `PitchContextSnapshot`、已获权内容投影和一个完整的 `DesignTheme`。它输出 `ProposalPlan`、与现有 `BusinessPage` 兼容的页面、选用的主题和建议风格。AI 与工作台使用 `PROPOSAL_RECIPES` 中稳定的场景及 `pageKind`，按 `plan.slides` 顺序执行。缺少证据和主动省略的意图在 `plan.gaps` 返回。配方的页数区间用于构思，实际输出由资料覆盖和现有版式分页决定。

| 场景 | 必需条件 | 页面顺序与取舍 |
| --- | --- | --- |
| `leasing-agency` | 一个选定的目标项目和明确的正式季度 | 从委托和项目出发，呈现同一子市场、同期竞品、租金和空置率相对位置，接到空间、客群、产品与执行。获权 Stacking Plan 和已发布团队、案例随资料加入 |
| `office-comparison` | 两个及以上显式选择的项目和明确的正式季度 | 客户需求、候选、项目和空间、商务比较、评分与踏勘。无需求资料时列待确认条件。照片支持任意候选名单，不内置项目或预算 |
| `market-report` | 明确城市和正式季度汇总 | 市场指标和趋势、子市场及等级、授权成交、空间及专题、展望或后续观察、方法。全市指标使用汇总结果。新增供应和净吸纳量未作为配方指标 |
| `building-promotion` | 一个项目和明确的正式季度 | 外立面、楼宇概况、交通和参数、真实空间照片、市场与获权楼层资料、适用条件及下一步。各照片类别沿用上游资料，联系人随已发布资料加入 |

## 调用及授权

- 用解析后的 ID 和 `YYYY-Qn` 构建 Brief。`projectUnifiedProposalContext` 从 Agent 01 的正式 `unified-pitch-context/1` 读取同城楼宇、季度指标、全市／子市场汇总及获权成交结果，接收 Agent 02 的版本化媒体及已发布材料，返回程序入口的两个输入。Agent 01 传递真实字段和版本化 `BusinessDataBinding`。既有路径可用 `projectQuarterBuildings` 从获权 `PitchDataSnapshot` 投影同季楼宇参数，单独传入空置对比结果取得数据引擎计算的空置率。每个结果定位到原查询凭据。全市、分组、历史与成交通过同一 `ProposalData` 投影接入，交出原始来源和绑定。
- Agent 02 提供 `VisualAssetReference`。`proposalPhoto`、`proposalMapImage` 和 `proposalStackingImage` 将精确版本投影为现有图片块。地图也可使用现有 `map` 块。Stacking Plan 可输入已获权的项目级图像或结构化楼层表，保留原始楼座、楼层、资料日期及来源，以既有引擎呈现。读取媒体及同一会话内的授权、许可和导出复核由各来源与工作区调用方继续执行。
- 仅消费快照清单中匹配的绑定及素材版本。对客页面需要每份实际使用的事实和素材都允许对客展示，团队、案例、联系信息、专题和预测还须来自已发布资料。测试快照生成的所有页面保留测试标记，对客调用拒绝。此入口接收可信服务端投影，业务读权限、原件许可和最终分享权限由现有授权边界核实。
- `options.theme` 传完整设计主题。配方给出 `professional`、`research` 或 `premium` 风格建议，主题由调用方选择和校验。`targetBuildingId` 可在已选项目中指定。`pages[pageKind]` 支持省略可选页和指定兼容构图，默认构图根据实际内容选择。`brief.start` 可限定历史下界。
- 各页保留来源 ID、版本、日期、查询凭据和测试状态。类别为事实、分析、建议或预测。Agent 06 可按原参数重新取得当期授权快照，并将新计划与 `contextFingerprint` 同时纳入审阅及版本控制。生成函数无数据库或存储写入。

## 选址评分

需要调用方提交有来源的权重。净有效租金、已披露步行分钟数以较低值优先。季度空置率以较高值作为排查供应的线索，实际可租条件由业主确认。零权重维度不参与。有任一正权重项未知的项目为未评级，完整候选不足两栋时整体不排序。

以完整候选的最高和最低值按偏好方向线性转换为 0–100 分。同一维度候选值相同，均取 50 分。总分为正权重归一后的加权和。已选样本、权重或季度变化后重算。评分只在当前候选集内解释。没有权重时保留参数和商务对比供人工决策。

## 执行验证

`npm test -- src/lib/pitch/proposals --maxWorkers=1` 运行独立测试夹具，通过四类业务入口生成真实场景和原生 PPTX，并检查两套完整主题、原生表格与图表、真实媒体绑定形状、缺失回退与可见性。夹具位于测试目录，全部与正式资料库隔离。和 Agent 01、02、03、05、06 的正式端到端路径由集成分支在真实授权环境验证。
