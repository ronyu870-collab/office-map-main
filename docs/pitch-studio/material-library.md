# 企业素材库、解析协议与历史页面标准化

阶段 03 依赖阶段 02 已验证提交 `ab6b9b157881fd476333db6d625885a68bbc4611`（PR #310）。分支 `codex/pitch-studio-03-material-library`。不改变内部研究报告的输出契约，不调用外部模型，不包含生产迁移或 main 合并。

## 实际入口与生产闭环

Pitch Studio → 企业素材库，使用紧凑列表切换「原始文件／来源页面／内容资产／媒体」。维护者可填写范围、来源、分类、标签、语言、真实资料日期、有效期及使用权限后批量拖入文件。上传后保存不可变原件与 SHA-256；逐页拆解、提取图片与业务结构，生成草稿；管理员核对、修正或批量确认后发布。普通用户搜索获权已发布页面与资产，再选择主题生成私人项目，通过现有共享 SlideScene 预览和导出引擎输出真实可编辑 PPTX。

列表支持关键词、区域、城市、业务线、标签、语言、类型、分类、业务日期、有效期、状态及游标分页（每批 30）。中文复用知识解析器的 NFKC 规范化与双字关键词，GIN 索引辅助关键词匹配，ILIKE 保留任意连续中文查询。媒体格式筛选按媒体 MIME，资产格式筛选按来源文档 MIME。目录在数据库中维护，可创建自定义分类；规则不确定时仅保存候选分类，不强行猜测。

管理员可维护标题、段落、分类、标签、图片、披露范围、有效期与发布状态；完整表格、图表和复杂结构通过高级结构编辑器修改，Zod 验证后保存。撤回为草稿立即使普通用户及已存在导出失去使用权限。相同范围／语言／业务日期的资产可合并；原版本与来源保留，合并关系和归档动作入审计。区域／语言版本生成关联草稿，语言字段变化不声称已经翻译。

## 解析支持与诚实边界

| 格式 | 实现与来源定位 | 明确限制 |
| --- | --- | --- |
| PPTX | 按 presentation.xml 的 slideId 与真实关系顺序拆页；EMU 尺寸；标题、副标题、正文框与位置；图片真实关系、裁切、分组；原生表格、常见图表缓存；母版／主题引用；只记录备注存在 | 不读取备注正文；隐藏对象排除，隐藏页不自动建资产；组内保留局部坐标；SmartArt、OLE、自定义矢量及不可靠图表标记部分解析；不复制旧页作为新页 |
| PDF | pdfjs-dist；真实页号、文字与可获得的位置，支持的独立 RGB／RGBA 图像 | 扫描页无受控 OCR 时为人工处理；不猜图片业务事实；部分复杂图像无法提取；有 JS 动作的文件拒绝；注释和表单不当正文 |
| DOCX | 标题、段落、表格、嵌入图片；真实 body 单元索引，按标题／30 单元分组 | 不是 Word 页码；隐藏段落排除，修订须核对；脚注／批注只记录存在；没有完整 Word 版式重建 |
| XLSX | 工作表名、真实范围、表头、单元格类型、缺失、零值、公式及缓存；每 150 行一个逻辑单元 | 不执行公式／外部连接；候选公式结果留空；隐藏行列不进入业务值；隐藏表不自动发布；合并表头须核对；未提取 Excel 内嵌图片 |
| PNG／JPEG／WebP | sharp 验证实际格式和像素；原件不变，独立缩略图；页与媒体关联 | 不做 OCR／识别事实；动画和需 EXIF 旋转的原图需先提供安全副本；不支持 SVG 输入 |
| UTF-8 TXT | 精确字符范围与完整文本，12,000 字符逻辑分段 | 拒绝二进制控制符、无效 UTF-8；文档内指令只是数据 |

旧 PPT、含宏、加密、不安全结构、损坏文件及其他扩展名给出明确失败状态。原件与已完成页不因失败被删除。未知业务日期允许保存原件、结构与人工状态，不填上传当天或假日期；维护者在人工草稿中输入经核对的真实日期，源文件身份与原始未知状态保持不变。

来源缩略图是**实际提取结构与媒体的重建预览**，有清楚标识，绝非原始 Office 页截图。完整结构／坐标／原件供维护者核对；截短缩略文字不改变存储正文和资产。PDF 图像暂不重建原始变换矩阵，不将其预览声称为准确排版。

## 协议、表与不变量

`pitch-source/1` 在 `src/lib/pitch/library/protocol.ts` 版本化，解析器版本 `pitch-structure/1`。每个 SourcePage 含 ordinal、locator、kind、size、texts、images、shapes、tables、charts、notesPresent、hidden、hiddenObjects、references、warnings、status。不同解析版本可以保留独立页快照和任务；当前执行器明确拒绝未知解析器版本，未来升级须新增经过验证的解析器及重解析命令，不原地覆盖历史页。

- `pitch_source_documents`：不可变文件身份／业务日期触发器；新版本使用新记录与 root_document_id，分类与发布元信息独立 revision。原件在私有 Storage 永久保留其真实版本，没有覆盖或删除入口。
- `pitch_source_pages`：真实顺序、全文、结构、部分／人工状态、分类候选、缩略图和草稿资产关联；唯一键 `(document_id, parser_version, ordinal)`。
- `pitch_media_assets`／`pitch_media_occurrences`：精确 SHA-256、原件页关联、像素、格式、原始位置／裁切／组、固定媒体版本、范围及发布状态。物理 blob 按上传者＋范围＋可见性加盐命名，单文档哈希精确去重；相同文件跨权限域不共享可见资产，不通过命中信息泄露文件存在。
- `pitch_parse_jobs`／`pitch_upload_parts`：真实持久化状态、游标、页数、进度、租约、worker token、次数、错误和不可变上传分块。
- `pitch_content_assets`／`pitch_asset_versions`／`pitch_source_references`：统一 `colliers-pitch/1` 草稿及不可变版本，精确文件版本／哈希／页码证据；编辑不能静默删除现有来源。
- `pitch_asset_links`：合并及区域／语言版本关系。
- `pitch_projects.normalization_report`：输入哈希、父资产版本、所有原始 block 索引、布局、转换原因与来源页。

所有新表启用 RLS，普通客户端不能直接写。唯一领域 RPC 保持原子业务写入及 `private.pitch_events`；新鲜账号、会话、试点、范围与能力授权每次重核。私有 bucket 无浏览器直接读写策略，上传、预览、下载经受控 API 和前后权限复核。

发布某页资产不等于批准整个原件的所有页。普通用户只读有权使用且已发布的页面与媒体；维护者能核对本范围企业草稿，私人历史草稿仍仅本人可读。原件可能含备注或其他未确认页，原件下载限上传者和本范围维护者。对客导出还要求当前资产与版本已批准、非测试数据、来源允许对客且仍在有效期内。区域版本始终保留原始来源的权限依赖；不能通过复制版本绕过来源撤权。

## 可运行的任务执行与容量

Node 路由 `/api/intelligence/pitch/library` 使用 Next 16 的 `after` 在响应后执行解析，不用内存假队列。

1. POST prepare 校验扩展名／MIME／元信息与维护权，按拥有者＋文件名＋SHA＋元信息幂等返回任务。重复请求和相同导入不重复解析。新文件版本显式选择原件。
2. PUT 上传每片 768 KiB（最多 16 片）；客户端最多两文件并行，原生 XHR 上传进度与取消。服务端限制流式请求体并再次检查身份，片路径不可变。
3. POST finish 按顺序读取所有片，检查总长度和原始 SHA，保存不可变原件，返回 202 并真正执行首批解析。
4. 每次 executor 最多 3 页／25 秒工作预算，I/O 整体 40 秒中止，路由 maxDuration 60 秒。每页结构、媒体关系、候选与游标原子提交；重启从游标继续，已提交页不重写。
5. 数据库领取限制全局 4／上传者 2 个活跃任务，50 秒租约及 worker token 阻止重复领取与取消后写入。失败／取消的已完成上传支持最多 3 次重试。超时在授权 status／库列表访问中以有审计的有界事务收敛为 queued／failed。
6. 上传面板每 2.5 秒轮询并启动下一批；离开页面不会删除任务。重新进入列表的「继续／重试解析」调用相同真实执行器。**当前没有无人值守定时 worker：关闭页面后队列保留，下一次授权访问继续处理；不承诺离线自动清空队列。** 未完成上传重新选择相同文件即可恢复已保存分块；取消的未完成上传释放去重键，可重新选择文件。

状态：queued → processing → completed／partially_completed／failed／cancelled。原件就绪和解析状态分别记录，不把上传进度当解析成功。失败原因持久化为安全错误码，保留已完成页；不输出私有正文作为错误。

资源上限：12 MiB／文件、20 个未完成上传／人、120 页或逻辑单元、2,000 ZIP 条目、16 MiB／单条目、64 MiB／展开总量、200 倍压缩比（1 MiB 小条目豁免）、XML 8 MiB／150,000 节点／深度 64、图片 32M 像素（PDF 单图 4M，超限不解码）、来源预览只组合已降采样的媒体缩略图、50,000 Excel 单元格／100 列。ZIP 中央目录与本地头双重检查，独立 inflate 上限、精确长度与 CRC 抵御伪造展开量；拒路径穿越、重复名、宏与实体。共享安全基础也用于现有知识文本解析器，保留其返回契约。

任务与文件保存在 PostgreSQL／私有 Storage，内存仅用于有界批次；不在 Vercel 临时目录长期保存文件。孤立失败派生对象和上传分块当前保留在私有 bucket，未启用自动清理；后续容量治理须保留所有原件及受引用媒体，另行实现审计清理策略。

## 标准化与再生成

注册模板 `history-standardizer/1` 使用既有 `structured-content/2` 适配器，没有新的布局副本。规则将完整段落／图片、指标、团队、案例、表格、图表、时间线匹配共享布局；内容量选择变体和实际字体度量分页。常见图表无需虚构 insight，直接生成原生图表；标签过密时转可编辑表格，再按容量转逐字段完整正文，转换原因入报告。超容量／空表／不完整结构需人工处理，不无条件缩字或静默删业务数据。特殊地图不伪造成完整结构。

生成的子页固定父资产版本、来源快照、主题版本与 normalization_report；展示来源文件与真实页码。重生成和换主题只重新计算场景，不改历史事实。PPTX 文本／表格／支持图表为原生可编辑对象；图片保留独立原始媒体。备注、隐藏对象与未获权数据不嵌入导出文件或工作簿。

素材库标题显示正在查看的版本。从「资产历史版本」打开已发布版本后，标准化请求以 `assetVersion` 固定该版本的正文、来源页和业务日期。服务端在生成和入库时复核该版本及媒体的授权；原件或权限撤回后，既有导出也须重新通过授权。连接中断时可在同一素材页面以原请求重试，已保存的项目会返回原回执。旧接口调用省略 `assetVersion` 时沿用当前版本。
