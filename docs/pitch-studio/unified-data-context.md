# Pitch Studio 3.0 房地产业务数据接口

服务端从 `business/adapter.ts` 调用 `loadUnifiedPitchContext(ctx, request)`。调用方使用已有 Pitch 请求身份，由 `authorizePitch` 获取 `ctx`。跨模块以 `requestFromProposalBrief` 将已审阅 Brief 转成请求。对外参数只接收楼宇 ID、名称、合法范围和正式期间。

`loadPitchDemoContext(ctx, demo, options)` 提供四个入口。

| 入口 | 返回 |
| --- | --- |
| `xiaoyun-agency` | 通过真实目录及治理别名解析霄云路33号。主档、获权楼座关系、燕莎候选、项目和子市场的同期指标、同环比和成交 |
| `cbd-grade-a` | 默认在 CBD 甲级及超甲级中选五栋同期具备租金、面积及空置率的楼宇。可传实际 ID 维持用户选择顺序 |
| `beijing-quarterly` | 北京获权跟踪甲乙级写字楼样本中的市场指标、子市场对照、历史变化、成交行业及面积段。保留分母和覆盖情况 |
| `building-promotion` | 从一个明确 ID 或可唯一解析的名称读目录、楼书、正式季度和相关已发布研究 |

## 事实与权限

- 目录主键以 `buildings.id` 为准。历史别名复用目录旧名和治理映射。项目级、同名或部分匹配时返回候选供确认。只读生产抽样核对，霄云路33号是燕莎的一个楼宇主档，A、B 座均关联该主档。季度沿主档归属。楼座关系复用既有空间模块许可并从楼座表批量读取，包含暂无单元的楼座。
- 静态字段用 `static`，正式同季指标用 `quarter`，历史用 `history`。目录与楼书的名称、子市场、等级分开保留。面积区分季度面积、办公面积、标准层面积、总建筑面积和目录可租面积。楼龄是参考季度年份与目录建成年份的差，为年粒度。楼书多候选冲突保留各原值。补充楼书字段通过既有业务授权独立启用，迁移不修改任何账号现有授权。未获权字段为 `unauthorized`。
- 未指定季度时从获权正式记录查找期间，显式季度原样保留。缺值、未填报、无权、冲突和零值有独立状态。正式租金、空置率、环比／同比复用可信查询引擎及现有公式。楼宇空置率单位为 0–1 比例，变化为百分点，租金变化为百分比。范围里的楼宇来自当前目录，历史不推断进出库。
- 竞品从同子市场获权目录筛选。顺序先看同等级组，再看可从已有资料验证的匹配条件和距离。匹配条件包括 2 公里内、同季净有效租金差不超过 25%、同季总面积差不超过 50%。租金与体量以目标的实际有效值为分母，缺项按原因报告。排序是供核对的规则结果。候选过滤的 `quarterArea` 单位为平方米，`rent` 为元／平方米／月，`vacancy` 为 0–1 比例。
- 成交复用已有身份映射、核验去重、期间精度和最小组样本限制。一份成交读取供趋势、行业、面积分组和具备明细权限的案例共用。面积按 500、1,000、3,000 平方米切分，左闭右开，缺失和无效量单列。案例按获权样本面积排序，逐项保留匿名来源记录引用及记录版本。成交仍区分已获权的当前与历史来源。
- 研究通过原子市场业务授权和发布校验。市场定位等正文结果携带原记录；已发布的人口、政策及团队观点条目保留原期间、来源与条目位置。研究资料的发布或更新日期不替换其业务事实日期。

返回 `buildings`、`candidates`、`results`、`research`、`gaps`。字段的 `sources` 提供物理记录与版本，分析结果按单元格来源 ID 关联 `result.sources`，`receipts` 补充模块政策版本、权限修订、数据版本及内部披露状态。共用 `BusinessDataBinding` 的 `bindings` 当前覆盖季度和成交，楼书、楼座和研究用 `receipts` 并保留业务结果证据。未重新授权的数据不进入新捕获。同一活动请求的未完成读取可去重，后续捕获重新授权。用于更新、持久化或导出时，按原请求重新读取并对比 `fingerprint`，运行调用方的项目级权限校验；用已审阅数据和选中来源生成文档。

## 执行验证

`unified-context.test.ts` 经过实际适配入口、可信查询解析与计算，使用隔离合成数据。现有 PostgreSQL 17 业务回归新增迁移前后与显式授权检查，保留其他原查询和旧授权场景。发布时应用已有迁移流程，无需生产写入验证数据。
