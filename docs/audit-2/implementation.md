## 事件与可信边界

注册表正文：[auditRegistry.ts](../../src/utils/auditRegistry.ts)，schema version 3，兼容旧记录。

| 等级 | 范围 | 交付与结果 |
|---|---|---|
| A | 账号、安全、权限、模拟、重要配置、业务增删改、正式提交、导入、敏感文件及数据导出 | 复用原事务；明确列举的关键字段触发器；跨服务操作先持久化意图，再原子确认结果。无采样或时间窗口合并 |
| B | 查看楼宇、分析、报告、资料预览、AI 非敏感摘要、浏览器写响应观察 | 客户端有界批量队列；Next 16 `after` 托管尽力投递。故障不改变普通业务成功响应 |
| C | 地图移动、缩放、悬停、滚动、逐字输入、指针移动 | 持久化前直接抑制，不打开 IndexedDB |

未知的 DELETE、PERMISSION、GRANT、REVOKE、IMPORT、PASSWORD、BACKUP、CONFIG、ROLE、EXPORT 类动作保守归 A；显式普通报告和空白模板覆盖该规则。筛选与注册表使用相同回退。风险分级不赋予可信身份。

客户端事件标注 `frontend / client_reported`；可信 API 记录实际认证调用者；数据库变更标注 `transaction_committed`。角色是**入库时**目录快照，历史空值不重构成发生时角色。服务身份无法解析实际用户时保留 unknown，不冒充 system；CLI 导入先核验指定管理员并记录工具执行信息。

## 可靠交付及故障处理

- 季度提交原有请求账本与 provenance、成交 UPDATE、到期核实、Stacking Plan、AI 加密审计与受控导出契约保留。
- `withCriticalAudit` 在跨服务副作用前创建持久化凭据。凭据写入失败则不执行业务。最终审计行和凭据终态在 PostgreSQL 同事务确认；部分业务结果独立保留，列表、筛选及导出不将其显示为全部成功；重复确认幂等，矛盾终态拒绝。
- 跨服务业务已成功而终态写入失败时保留 pending，不把业务伪报失败，也不自动重放业务。管理员健康页列出超过 5 分钟的待核查凭据；按对象、服务实际状态及凭据 ID 人工核查后才能确认。pending 本身不等于成功。
- 审计、成交文件导出严格等待最终凭据，数据库再次锁定并检查实际管理员资格；失败或撤权不交付文件。浏览器生成的 Excel、备份、地图及对比文件在交付前取得可靠服务端授权。该凭据明确只证明授权，范围与数量标为客户端报告，不声称服务器生成或用户已保存文件。
- OSS 上传先取得逐文件持久化授权与限定 exact-key / size 的短时签名，再由服务器 HEAD 核验真实对象、大小、ETag 与更新时间。确认失败保留待核查状态，不重放上传。普通预览保留 B 类请求后投递。
- `after` 已通过实际 Next 16 生产构建验证。它在 Vercel 使用请求生命周期支持，受执行时限约束，属于尽力投递，不能用于 A 类可靠交付。

### 页面业务阅读补齐（2026-11-21）

- 新增 B 类 `VIEW_BUILDING_CONTACT`、`VIEW_BUILDING_TREND`、`VIEW_BUILDING_SECTION`：分别观察联系方式弹窗展示、成功初始化／切换的租金或空置率图表，以及用户实际切换的详情分区。联系人只保存楼宇关联，不记录电话或联系人正文；同一趋势指标再次点击不重绘、不发事件。
- 新增 B 类 `VIEW_BUILDING_MATERIALS`、`VIEW_MATERIAL_ORIGINAL`：资料读取成功后记录当前房源／佣金／项目资料分区、资料 ID，以及打开原件的具体 ID 和入库版本时间。资料 ID 列表最多 30 项并明确标注截断；原件事件只证明查看器打开，不证明原件下载、加载完成或人已阅读。不保存资料正文、签名链接或原件哈希。
- 共享客户端队列同步捕获真实会话；楼宇／联系人／趋势／资料的相同对象与状态 10 秒内去重，详情分区 5 秒内去重，沿用普通高频事件每分钟 120 条预算。资料自动刷新或重新渲染不重复记作阅读，示范模式和身份模拟沿用原保护。这些是辅助访问证据，离线、存储压力等情况下仍可能丢失，不能宣称全点击轨迹。
- 新事件进入“访问轨迹”，资料事件同时支持“文件”视图，保留客户端报告结果语义。无新增数据库迁移、轮询、普通读取拦截或点击后的同步审计网络往返；ECharts 和资料查看器仍按需加载。
- 持续回归执行真实控制器／组件、原生 IndexedDB 队列、实际生产构建的桌面与手机视口闭环；同一套新增用例在旧实现出现 6 项行为断言失败。浏览器回归包含首批审计 503、重试确认、列表与地图标记去重、趋势指标、联系人及资料原件；性能脚本通过实际共享阅读入口测量同步耗时。

白名单字段及具体表见迁移中的明确 trigger 定义。没有给全部业务表安装通用触发器；草稿自动保存、普通 SELECT、列表滚动和地图逐帧事件不新增审计写入。关键批次用事务 ID、对象 ID 和逐行变化追溯；跨服务请求用 receipt UUID。客户端观察不能代替这些来源。外部人工 SQL/工具不在应用事务内运行时，需要由执行者提供真实身份及可靠批次凭据，不能仅以浏览器观察补证明。

## 队列、拦截与查询

队列在调用时捕获账号和 Auth session，20ms 合并持久化，批次最多 20 条/30KiB。容量只按批读取，B 类容量上限 1500；A 类辅助观察不因磁盘容量丢弃。内存最多 200 个有界快照，故障时优先保留 A 类辅助数据；辅助记录损失有单独诊断计数，A 类权威来源不依赖浏览器。显式 accepted/discarded ID 才能删除对应在途事件；HTTP 200 本身不是确认。旧账号数据单独清理，不计作服务器接受。退避封顶 60 秒并含抖动，在线与可见性恢复，没有高频轮询。

Fetch 拦截保留原请求与响应、传输异常和比较缓存失效。不克隆大响应、不在普通 GET 生成变更、不按表名短窗口合并修改。客户端自动观察统一表示“收到写请求响应”。覆盖检查区分可靠来源、已有事务、受控 `after` 及明确豁免，并用负向测试防止关键词假覆盖；静态检查不能代替执行回归。

审计中心首屏只查询当前视图的 51 条明确摘要字段，以 `(occurred_at,id)` 游标取 50 条，不执行全量或多个分类 COUNT。大 JSON 仅展开详情时查询。组合检索、时间、用户、角色相关视图、表、对象、关联 ID、IP、设备、session、结果与风险均在服务端过滤；过期请求取消并防止迟到覆盖。楼宇时间线关联实际 building_id，季度专用来源独立分页，不虚构历史。

管理员导出复用同一过滤器，最多 500 条/2MiB，CSV、XLSX、JSON 仅摘要投影，不返回普通日志大 JSON 或 AI 专用原文。CSV 防公式注入；明确生成状态和范围。普通用户不加载这些查询或新增审计状态 UI。

健康页仅管理员打开或刷新时查询。最新 24 小时/1000 条样本提供失败、拒绝、未知执行者、删除、导出、权限变化、异常重复、延迟及待确认凭据。Auth 登录异常单独读取近 15 分钟最多 1000 条现有 Auth 记录；缺失来源不推断安全。存储仅管理员访问时每日 UTC 一次采样，至少两天才展示变化，最多最近 30 个样本；浏览器队列诊断不代表全站。阈值提示需人工复核，不作为自动处罚。

保留策略可配置 30–3650 天，仅规划普通事件归档。数据库约束禁止启用自动清理；本轮没有删除任务，不删除或改写现有生产证据。关键安全记录需要独立批准、备份与范围核查后才能归档或删除。

## 发布、回滚及未执行事项

1. 先在隔离/预发布应用完整兼容迁移，确认权限、索引、原有 SQL 函数与新 RPC；迁移带 5s 锁等待、45s 语句超时并在事务内执行，失败会回滚，不在高峰盲目重跑。生产须另行授权。
2. 再部署服务端和客户端；保留既有 Auth、AI、季度和成交契约。旧 OSS 通用签名入口返回 410，更新后的客户端使用逐文件授权；部署时提示刷新旧页面。
3. 发布后由管理员按需核查健康、pending、存储样本与有限真实业务；不能把 CI 或部署 Ready 当作迁移或业务已验收。
4. 应用回退到兼容版本前先停用新上传/导出入口，保留新增凭据、审计列、表与已产生记录；不要 DROP 证据或回写历史身份。必要时在维护窗口单独回退指定新增触发器/索引并记录授权，原季度、成交、AI 的可靠来源不能撤除。
5. 如处理 pending，先查实际 Auth/OSS/业务对象，只有证据充分才调用服务端完成函数；不能通过重放删除、用户创建或上传来补日志。

生产迁移、生产部署、真实供应商地图/GPU、生产高峰 CPU 和吞吐测试均未执行。公网承载能力与上线效果需发布授权及受控观测，隔离数据不代替生产证据。远端 PR CI 仍需确认；任何失败须修复后再交付。
