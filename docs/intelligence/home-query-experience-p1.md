## 2. 单实例工作空间与模式过渡

### 展示与状态边界

`HomeQuerySession` 继续拥有草稿、全部当前会话问答、conversation ID、parent request、签名恢复引用、地图传入的楼宇范围、结果和请求控制器。账号隔离仍由 `queryScopeKey(scope)` 的组件 key 承担；模式不参与该 key，也不进入查询提交参数。

`useQueryWorkspace` 只控制同一容器的几何位置与展示状态，不切换路由，不创建第二个 `HomeQuery`，不把旧实例卸载后挂到另一个 portal。主页保留占位高度，全屏使用同一个 DOM 树及视口尺寸；普通展开／收起不提交问题、不调用模型、不改变幂等键或父轮，也不写入新的正式查询审计流。

当前会话取消原来的最近 10 轮裁切，保留全部已完成问答。复杂的此前回答仍按需展开，已挂载的内容在收起时保留，避免用展开／收起重建已显示结果。此处是当前挂载会话的连续性，不新增问题正文、回答、完整结果或恢复凭据的浏览器持久化；`sessionStorage` 仍只保存原有不透明 request UUID。

### 340ms 专用空间过渡

本批采用原生 Web Animations API，从切换前真实矩形过渡到目标矩形，动画属性限定为 top、left、width、height 与圆角，时长 **340ms**。该值属于用户本次明确要求的全屏空间变化变体，不修改普通 120／180ms 微交互的长期默认值，也不引入动画依赖。

反向收起使用同一容器和反向几何过程。连续快速点击取消旧动画，只允许最新 transition ticket 收尾；卸载、账号变化和视口变化清理或结束对应几何动画。`prefers-reduced-motion` 或浏览器没有 `Element.animate` 时，使用同一组件树直接完成模式变化，不调用动画 API，不影响功能。

切换前记录当前可见问答及其相对偏移；切换后的尺寸变化尽可能恢复同一阅读锚点，无法定位该问答时使用原滚动位置。这个机制独立于提交、权限及网络状态。

## 3. 全屏布局、输入与键盘行为

全屏由顶部工具区、中间独立滚动的对话区和稳定底部输入区组成。正文保持约 800px 阅读宽度，不将普通段落横跨整个宽屏。桌面可显示约 260px 历史侧栏；约 288px 研究资料区仅按需开启。中窄屏改为单栏及可收起面板，不保留固定三栏挤压主内容。

输入框保持原节点与受控草稿，保留自动多行、Enter 发送、Shift+Enter 换行、中文输入法组合状态以及旧式 keyCode 229 保护。请求期间仍可编辑下一条草稿，返回结果不清空后来输入的文字。新对话清理原父轮及当前问答，保留用户尚未发送的草稿；账号或资格变化则清除旧身份全部内容与草稿。

等待反馈来自实际请求状态；停止等待仍只终止客户端等待，不声称服务端已取消。原键重试、失败／超时说明、检查状态与恢复、重新查询的原语义保留，没有模拟逐字流式输出或虚构推理步骤。

滚动仅在读者跟随末尾或主动发送时定位新消息。读者正在查看上方内容时，回复到达不强行拉回底部，提供“回到最新消息”。展开来源等局部操作沿用自己的焦点和局部可滚动区域。

全屏浮动阶段使用有名称的 `dialog`／`aria-modal`，同步将工作空间祖先路径之外的内容设为 inert，限制背景滚动并维持焦点环。Esc 先遵守当前控件处理及输入法组合状态，再关闭全屏；收起后将焦点恢复到展开入口。所有新增动作均为语义按钮并具有可访问名称。共享 `Button` 仅补充 React 19 的 `ref` 类型传递契约，原样式、按钮变体和业务行为不变。

视口尺寸监听 `visualViewport` 及 resize，输入区计入底部 safe-area，窄屏工具按钮保留 44px 命中区。CSS 覆盖 320／390／768／1280px 的目标布局；自动浏览器检查与真实手机软键盘、系统输入法验收是不同证据，后者本次未执行。

## 4. 结果与研究资料的渐进组织

`HomeQueryResult` 新增可选 `presentation`、`onExpand`、`visible`，默认保留原完整展示行为。Complex 判断使用结果行数及研究结构：当前为超过 8 行、超过 4 个研究序列或超过 6 项研究发现。它只决定 Compact 的预览密度，不强制用户进入全屏，不用提问字数推断任务复杂度。

Compact 保留结论、核心指标、样本与口径说明、限制、来源入口及完整分析按钮。小表格、短趋势和单指标直接可用。复杂图表／明细首次需要时挂载，此后切回 Compact 只隐藏，保持已加载图表、当前页、选中来源及在途图表请求。结果组件使用 `React.memo`，稳定结果不因每次草稿输入重新执行大结果排版与汇总。

完整结果按结论和核心数据、图表、分析与楼宇、明细、来源与必要操作组织。明细和长图表在自身容器滚动，既有分页、未知值、样本、分母、原始来源、CSV／XLSX／SVG、复制及地图入口继续复用。来源关闭后恢复原控件；原控件已被 Compact 隐藏时回到完整分析入口。

`HomeQueryResearchPanel` 从当前最近一条可用、已获权的结果中读取范围、季度、统计口径、来源类别、相关楼宇和快照时间，不另查业务数据。来源概览明确候选记录可能未参与计算；逐项原始值继续通过回答中的原来源入口查看。面板不将内部 ID 当首要信息，不把结果生成时间改称业务截至日期，也不把历史回答称为最新市场数据。

### 展示回执

`useQueryPresentationReceipt` 增加可见性开关。被收起的表格／图表不产生新的 `client_dom_committed` 回执；进行中的图表可以在隐藏时完成，但要真实显示后才报告其 DOM 展示。

已确认的同身份、同响应对象、同 view 回执在普通隐藏再显示时去重；页码、来源选择、结果或身份发生变化时仍报告相应 view。失败／取消的回执不标记为成功，重新实际展示时可重试。原接收回执、交付 token 校验、服务端正式审计与权限检查均保留，没有通过取消审计获取性能。

## 5. 本人历史整合与迟到保护

历史复用 `HomeQueryHistory`、`trustedQueryHistoryClient` 及原 `/query/history`，不创建第二套存储。支持列表、搜索、日期分组、选中状态、重命名、归档、打开原快照和签名父轮继续分析。归档只整理本人列表，不删除正式回答或审计；恢复不重新执行原问题，“重新查询”仍为显式的独立动作。

历史组件首次打开后保留同一实例，模式切换不改变其请求依赖。搜索与重命名输入维持原节点和组合输入状态。正式查询忙时禁止打开另一条历史覆盖当前工作，历史搜索仍可连续编辑。

另外修复原有竞争：历史 open 开始后，若用户又发起了新问题，旧 open 响应即使晚于新问题完成也不能覆盖当前对话。`queryEpoch` 仅随新查询进入忙状态前进，与模式无关；旧响应在调用 `onOpen` 前核对 epoch。

原 P2 文档记载过生产历史元数据迁移尚未执行。本批没有申请或执行该迁移，也没有据应用代码推断其当前生产状态。历史后端不可用时保留既有真实错误及重试路径，不能把界面整合称作生产历史持久化已核实上线。

### 性能测量口径

本批不增加动画库、不增加依赖包。相同锁文件、Next.js 16.2.12 与生产 webpack 编译条件下，首页 client-reference manifest 引用的 JS gzip 清单从 **172,521 字节**增至 **176,710 字节**，增加 **4,189 字节（约 4.1 KiB）**，低于本批新增代码 12 KiB gzip 上限。原始分块与限制见 [编译阶段包清单](../verification/colliers-ai-experience-p1/bundle-compilation.json)。这是编译产物清单，不是浏览器真实首屏传输；两次完整本地构建均受宿主页面收集限制，原生完整构建仍由 CI 验证。已加载结果通过 memo 和按需细节限制输入时的重渲染，图表及大依赖的原加载边界保留。

新增工作空间探针使用原隔离 GoTrue 登录、PostgreSQL、PostgREST 与实际 Next 生产构建，在原 Auth／HTTP／P2 检查全部成功后复用其受限 hold-open 预览。测试合成数据和临时资格只存在于 disposable 环境，清理恢复；不拦截业务 HTTP 伪造回答，也不访问生产业务库。

目标为桌面／手机两组既有性能配置，每种配置对首次展开、收起、再次打开各采样 20 次，共 **120 个计划过渡样本**；另有 320、390、768、1280px 四组实际操作闭环。首次展开指该文档的第一次 Expanded 布局，查询结果已经加载，服务端／数据库为暖状态；每轮新建浏览器上下文并实际登录。P0 没有等价全屏入口，所以这些过渡不伪造旧版 A/B。原 P1／P2 功能与性能门槛继续执行。

起点为可信用户按钮操作；首次反馈为实际空间过渡可见；可操作终点要求动画结束、同一输入框可编辑、结果与草稿／选区保留、全屏几何和输入框位置正确。预算为 P90 首次反馈 ≤100ms、已载内容切换后可操作 ≤500ms。记录 P50／P90、长任务、错误、缺样和失败；不把动画开始、占位、响应返回或模式标记当完成，也不删失败样本。脚本存在及 self-test 通过只能证明统计／门槛机制，120 样本和四视口必须实际运行后才能写为通过。
