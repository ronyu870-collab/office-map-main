# 历史结果恢复：存储解码阶段

状态：本地实施，未提供恢复HTTP接口或用户界面，未启用生产AI。原99项范围保持不变。本记录只证明恢复链路的存储解码部分，不能将V09、A03、A07或AUTH07计为完成。

## 当前实现

`src/lib/intelligence/query/resultArchive.ts` 复用已有内联/分块格式，与先前持久化内容兼容。写入入口仍为 `createRpcAuditPort`；结果大于80KiB时按48KiB字节分块，最多16MiB，末尾清单记录组号、分块数、字节数及SHA-256。编码不重新计算业务数值，不查询当前数据库，不把缺失变为零。

服务端解码按可信调用方提供的实际/有效身份、请求和事件ID验证AES-GCM上下文，按密钥版本验证每块HMAC，再校验事件顺序和唯一ID、组号、连续块号、规范Base64、长度、清单和整份摘要。中文在字节拼接后严格UTF-8解码。任何缺块、损坏、混组、缺失密钥或超限均报错，不返回部分结果、不排序修复、不选择最后一份看似完整的清单。

返回值保留原存储序列化正文、结构化结果（unknown类型）、字节数、摘要和脱敏类型。调用方必须继续验证具体结果版本/schema；明确凭证已脱敏时不能声称恢复了脱敏前原文。此处不构造可渲染HTML、不暴露密钥，不接受客户端自报权限。

## 权限与完整性边界

解码器不是授权接口，也不是全事件链校验器。它不能证明一整份流或尾部未被删，也不能证明服务器生成的结果已经发送/展示。调用方在提供密文前必须执行以下剩余工作：

1. 验证当前真实会话、请求归属及实际/有效身份，重新检查查询、记录、字段和来源当前访问权；普通用户读自己的结果与审计员读他人问答采用独立授权路径。
2. 从有界、受保护的数据入口取得完整事件流，检查事务终态、事件链及独立检查点；不能仅筛出某个完整清单绕过失败、撤权或缺段。独立检查点尚未实现，不能声称单库绝对防篡改。
3. 记录恢复读取和拒绝事件，输出前复查当前权限；历史结果的数值保持原快照，不能用重跑最新查询替换。权限或来源已撤回时拒绝相关旧结果；权限扩大不应擅自扩大原结果范围。
4. 实现结果状态/恢复API、客户端接收/展示回执、重连与崩溃对账，以及独立密钥保留/轮换治理。当前解码支持显式密钥环，不等于已实现密钥生命周期。

当前没有向普通角色开放审计RPC，也没有为了恢复授予普通管理员全量问答权限。
