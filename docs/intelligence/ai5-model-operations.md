# Colliers AI 5.0 阶段 11：模型运行与运营治理

本包基于阶段 10，共用既有 admin 本人限制、独立业务资格、正式查询、结果工作集、加密审计及可信下载。没有新增 SQL 权限、生产授权、公开文件地址或生产配置。OpenAI 默认不启用；现有用户继续使用原 DeepSeek 配置。

## 模型与工具协议

`modelProtocol.ts` 定义供应商无关的消息、`calls / callId`、工具规格、用量与完成对象。执行器只接收该协议，DeepSeek 的 `tool_calls` 通过兼容边界转换；OpenAI 由官方 `openai@7.62.0` SDK（Node >=22）调用 Responses API。工具仍由注册表 Zod 校验，正式数值仍由原数据工具计算；模型没有 SQL、原件读取或新增字段权限。

OpenAI 固定使用 `https://api.openai.com/v1`，禁止重定向和自定义网关，关闭 SDK 自动重试、调试日志、后台任务及服务端响应存储，使用 `store:false`。只开放平台注册函数，不开放供应商内置浏览、代码执行或文件工具。现有工具包含可选参数，因此显式 `strict:false`，以平台服务端校验为最终约束。函数结果以原 `call_id` 返回；推理项目使用请求内不透明句柄保存并原样续接（包含加密推理），不会写入会话事实、审计正文或发送给其他供应商。

参考开发时官方文档：[Responses 快速开始](https://developers.openai.com/api/docs/quickstart)、[函数调用](https://developers.openai.com/api/docs/guides/function-calling)、[流式响应](https://developers.openai.com/api/docs/guides/streaming-responses)、[官方 Node SDK](https://github.com/openai/openai-node)。测试中的模型名仅是合成协议样本；生产必须配置账号实际可用模型。

## 配置与运行策略

所有配置仅在服务端。API 请求可选择 `mode`，不能提交提供商、模型 ID、价格、密钥或额外数据源。省略时按任务意图选择模式；恢复专题研究沿用 deep 能力上限。

| 模式 | 典型场景 | 模型轮次／工具上限 | 提供商配置（默认 deepseek） |
| --- | --- | --- | --- |
| quick | 简短提问 | 3／4 | `AI_PROVIDER_QUICK` |
| professional | 正式查数、比较、图表、导出 | 7／10 | `AI_PROVIDER_PROFESSIONAL` |
| deep | 多步骤研究、报告、综合成果 | 9／12 | `AI_PROVIDER_DEEP` |

各提供商配置只接受 `deepseek` 或 `openai`。DeepSeek 保留 `DEEPSEEK_API_KEY`、`DEEPSEEK_CHAT_MODEL`／`DEEPSEEK_MODEL` 及原官方端点限制；不会改动所有用户的既有模型选择。

DeepSeek 保留原环境变量作为旧配置的默认入口。已验证账号可按需显式配置 `DEEPSEEK_CHAT_MODEL_QUICK`、`DEEPSEEK_CHAT_MODEL_PROFESSIONAL`、`DEEPSEEK_CHAT_MODEL_DEEP`，例如依次选用 `deepseek-flash`、`deepseek-flash`、`deepseek-v4-pro`。已发布运营配置优先，启用 Thinking 的模型须同时声明推理和工具续接能力。快速模式关闭 Thinking，专业模式用 low，深度模式用 high，语义抽取用 low。未显式配置的旧环境沿用原请求行为。移除模式环境变量或撤回对应模型能力可恢复旧配置。

DeepSeek Thinking 实际发送 `thinking` 和 `reasoning_effort`。工具调用所需的 `reasoning_content` 只留在本轮服务端适配器，续接时按原样返回给同一模型，预算计入原生字段序列化的字节数。前端、普通历史和业务审计只获取模型、状态、用量及扣入预算的数值。加密尝试审计在实际发送时另记推理档位。默认沿用同一输出和超时上限，实际 Thinking 表现待经批准的供应商试验确认。[DeepSeek Thinking API](https://api-docs.deepseek.com/guides/thinking_mode/)

OpenAI 需同时配置：

- `OPENAI_API_KEY`：服务端密钥；`OPENAI_AGENT_MODEL`：账号实际可用的官方模型。
- `OPENAI_AGENT_MODEL_QUICK / PROFESSIONAL / DEEP`：可选模式覆盖。
- `AI_OPENAI_ENABLED=true`，以及 `AI_OPENAI_ACTOR_IDS`：逗号分隔的批准账号 UUID。此名单表示允许将同一受控 Agent 请求及已批准可披露的工具观察交给该供应商，不新增任何业务访问资格。普通私有原件仍不发给模型。
- `OPENAI_AGENT_INPUT_USD_PER_MILLION / OPENAI_AGENT_OUTPUT_USD_PER_MILLION`：必填的运营方美元费率上界；支持 0–1000 的有限数值。配置者应覆盖实际所选模式模型的最高价格；不是供应商账单或自动价格同步。

OpenAI 未启用的账号不会因配置了模式而自动改用 OpenAI。提供商切换还需 `AI_MODEL_FALLBACK_ENABLED=true`，默认不回退。一轮只允许切换一次，后续模型调用保持备用供应商，避免反复击打已失败服务。缺少配置、超时、模型不可用、供应商不可用及流中断可在剩余预算内回退。业务拒绝、401／403、限流、配额、参数配置错误、格式错误、取消不回退。每次发送、切换和成功流文本交付前均重新检查当前身份、资格与已加载的数据域权限。

## 有界预算、取消及恢复

| 配置 | 默认 | 合法范围 |
| --- | --- | --- |
| `AI_AGENT_MAX_TOKENS` | 60000 | 1000–60000 |
| `AI_AGENT_MAX_ESTIMATED_USD` | 0.25 | 0.000001–5 |
| `AI_AGENT_MAX_OUTPUT_TOKENS` | 1800 | 256–4096 |
| `AI_AGENT_PROVIDER_TIMEOUT_MS` | 18000 | 1000–18000 ms |

保留原 54 秒请求期限和数据库跨实例每账号 12 次／分钟、120 次／日入口限制。上述 token／费用是每次受控执行的累计上限；不宣称为账号月账单硬封顶。每次付费前，以消息／本轮工具定义的 UTF-8 字节、原生续接状态与协议余量保守预留输入 token，再加输出上限。只按意图提供相关已注册工具目录，避免每次重复发送四份大型图表规格；这不改变授权或服务端注册表。预算不足明确停止，不静默截断数据或自动无限续接。

供应商返回完整用量时按其记录结算执行预算；失败或无用量时保留全额预留，不能成为零成本无限重试。尚未发送的配置失败记录零消耗。费用估算未折减缓存，推理 token 与缓存 token 独立记录。供应商用量异常超过预留时仍记真实报告用量并停止后续步骤。

既有身份绑定幂等回执防止重试重复执行。取消通过同一个 AbortSignal 传播至 SDK、流和工具。研究任务遇到取消、超时、预算或供应商错误时，仅在全部当前来源重新核验通过后保存已有正式进度；保存成功不代表任务完成。恢复复用阶段 10 的任务／结果快照与步骤依赖，不重查已完成合法步骤。任务不转为脱离请求的后台无限循环；继续研究仍需新的有界请求。普通失败没有正式研究工作集时不假装具备可恢复成果。

## 长期上下文与撤权

普通历史保留最近 8 轮，单独存储 `agent-memory/1` 确定性摘要，无额外模型调用：累计轮次、研究主题枚举、语言和文件格式偏好、研究任务状态、最多 8 个结果版本引用、最多 8 个已生成文件格式引用。摘要不复制业务数值、客户名称、文档全文、密钥或下载地址。任务计划、正式数据与文件仍留在原受控工作集和审计中。

历史 assistant 业务断言不直接重放给供应商；仅继承服务端验证的意图，业务事实必须使用本轮重新授权的快照或重新查询。摘要引用不是授权令牌，不自动导入旧结果。沿用原 owner／会话／修订／有效期和域权限复核；撤权后旧摘要、旧结果、旧文件不能恢复敏感内容。摘要尚不提供任意偏好自由文本、独立跨会话事实记忆或过期结果长期存活。

## 成本与故障观测

每次实际尝试写入既有加密审计的 `agent-model-attempt/1`：模式、提供商／模型、调用顺序、成功／失败、错误类别、切换路径、耗时、输入／输出／缓存／推理 token、供应商响应 ID、保守预留、计入预算 token、估算金额及依据。未发送、未知用量和供应商报告用量明确区分。普通日志不新增用户问题、合同、工具原始资料或密钥。

实际账单字段始终为 `null / not_reconciled`；响应 ID 供有权限运营人员与供应商记录核对。没有实现供应商账单拉取，不把估算或保守预留显示为实际收费。原 DeepSeek 费用区间仅保留单供应商兼容记录，多供应商执行不套用 DeepSeek 总费率。

现有审计管理台增加单请求统计及显式读取的本页抽样（最多 10 个不同请求），按提供商展示尝试、失败、token、耗时、估算与错误类别。每次读取仍需独立审计资格并留访问痕迹；不新增默认资格。仅为本页样本，不能推断整段时间／整账号账单；老协议记录缺失不能认作零调用。拒绝、换账号、隐藏页面及既有超时清除同时清空统计。

## 验证与发布边界

模拟供应商矩阵验证正常 DeepSeek／OpenAI、缺配置、401／403、限流／配额、超时、不可用模型、服务错误、畸形完成、真实 SDK SSE、缺少完成事件、取消、一次回退、预算、撤权和费用未知状态。管理台回归验证显式读取、独立审计拒绝及状态清除。真实 Auth／HTTP 脚本接入必需 CI，使用本地 GoTrue／PG17／加密审计，供应商 HTTP 使用合成响应：同工具正式数值一致、幂等不再付费、历史摘要续接、跨账号／撤权拒绝、流可信完成与中断、预算付费前停止。

前阶段的真实文件回读、研究中断恢复、授权及审计回归继续执行。人工浏览器、截图和独立人工视觉按本轮明确豁免；自动功能门槛保留。未读取／设置生产密钥，未向真实供应商发送客户资料，因此不宣称完成真实 OpenAI 或 DeepSeek 密钥联通测试。实际检查结果以 PR 精确 head CI 为准。
