# 审计导出中断补记与对账（本地隔离工作包）

基线 `0ab9a84315a900318eb5cc50437f8b7bdabd720e`。前轮完成单条/本页 JSON 导出，但读完后解码失败或进程消失时，没有持久的待处理状态与补记。本包补齐该运行路径；所有 AI 仍仅供当前 admin 本人使用，独立审计查看/导出资格保持。没有生产迁移、真实账号授权、调度启用或 main 发布。

## 状态与事实

`ai_audit_export_operations` 是当前状态投影，`ai_audit_export_lifecycle` 是追加的状态历史；原 `ai_audit_export_events` 继续保留加密请求、文件摘要/字节与客户端报告。读取、准备与报告插入时，同一事务登记投影和历史。任何一项写入失败，整个对应事件回滚，文件不能越过失败的 prepare 交付。

| 证据 | 投影状态 | 含义 |
| --- | --- | --- |
| read allowed，尚无 prepare | pending_generation | 等待解码/生成与准备凭据 |
| read 拒绝或资料不可用 | denied / unavailable | 本次受控读取未放行 |
| prepare allowed | pending_report | 文件已准备，不证明响应被接收或文件被保存 |
| 应用捕获生成路径失败，且尚无 prepare | generation_failed | 本次生成处理失败，不改写此前业务问答 |
| 生成窗口超时，由系统补记 | generation_unconfirmed | 没有确认的准备记录，不能猜测具体崩溃原因 |
| 报告窗口超时，由系统补记 | delivery_unconfirmed | 没有有效下载报告，不能断言用户未收到/未保存 |
| 有效客户端报告 | client_dispatch_reported | 软件发起下载，不证明磁盘保存或人类已读 |

新读操作给生成流程3分钟；文件准备后给客户端报告10分钟。当前客户端报告签名最长5分钟，因此自然到达10分钟补记后，原令牌通常已过期，不重新延长凭据。数据库允许仍满足原权限/会话/签名契约的迟到报告追加状态更正，保留此前 unknown 历史；隔离测试通过调整到期时间覆盖这条竞争路径，不把它说成10分钟旧令牌仍有效。

应用失败补记只接受可信服务提供的原导出编号、实际账号与会话，且必须匹配同一原始 read；它没有读正文、准备文件或扩大角色的能力。只关闭 pending_generation，不覆盖 pending_report/已交付报告。补记本身写不进去时不阻塞原业务、不编成功，保留持久待处理行，由后续独立进程补为未确认。用户权限撤销后仍允许服务记录失败事实，但不允许交付文件。

## 独立补记与并发

`ai_audit_export_reconcile(worker,limit)` 每批1—100项，默认运维命令20项；按数据库时钟选过期未结记录，`FOR UPDATE SKIP LOCKED` 防止多实例重复处理。一批操作及追加历史在同一事务，进程/连接终止或历史写入失败全部回滚，下一次可以安全接管。无需易丢失的内存计数，也不重跑业务查询、解密档案、重建文件、调用模型或冒充用户提交。

准备动作与补记锁同一投影行：补记已结束、准备期限已过或已有 prepare 时，迟到 prepare 会被拒绝；正常准备先完成则补记按新的报告期限处理。客户端报告只能绑定投影的准确 prepare_id。补记前核对原 read/prepare/已有报告及历史存在，明显不一致返回 integrity_unavailable，不能将受损记录认证为正常结束。

`ai_audit_export_overview(since)` 在最多31天窗口比较原 read 账本与状态/历史，返回总数、缺投影、缺历史、未结、过期、生成/交付未确认、生成失败、软件报告、拒绝/不可用计数，不返回问题、答案或人员名单。缺投影/历史与已知异常会令 CLI 非零退出，供后续告警接入。以上仍在同一数据库，**不是外部独立计数或防数据库所有者篡改的锚点**；接收边界尚未成功持久化前的进程消失也不能据此恢复正文。

私表开启 RLS，取消 anon/authenticated/service_role 直接表访问；触发器只给拥有者执行，受控服务函数在 private，public 只有 invoker 外壳。普通 admin JWT 不能调用补记/统计，不能把普通管理员角色当运维密钥。浏览器客户端不接触这些维护凭据。

## 运维与升级

一次性本地入口：`node scripts/intelligence/reconcile-audit-exports.mjs`。必须显式提供 `AI_EXPORT_RECONCILE_ALLOW_LOCAL=disposable`、仅本机的 `AI_EXPORT_RECONCILE_URL` 和独立 `AI_EXPORT_RECONCILE_SECRET`，可设 `AI_EXPORT_RECONCILE_WORKER`。拒绝非本机地址及带用户名/密码/查询/片段/非根路径URL；不读取环境中的生产项目作为默认值。输出仅受控导出编号和计数，不需正文加密密钥，不输出密钥或正文。生产调度、专用秘密和告警仍须后续获权配置，本包没有启动常驻任务。

迁移 `20261113135841_ai_audit_export_reconciliation.sql` 先锁原事件表，等待旧写事务结束并阻止新写入落在回填/触发器安装之间，再为历史read建立观察投影，按已有准备/报告分类；保留原事件时间，当前 migration_observation 明确是迁移时观察，给未结历史10分钟宽限，不虚构过去的失败时间。应用现在要求服务端 `audit-export/2` 协议，旧库返回v1时拒绝文件；JSON文件格式与签名版本不变。迁移/应用需协调发布，回退不能删除已经追加的导出和生命周期证据。
