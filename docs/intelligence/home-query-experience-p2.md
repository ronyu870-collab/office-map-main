## 2. 主页重新分组

| 区域 | 本次处理 | 保留的能力 |
| --- | --- | --- |
| 主页工作区 | 使用既有浅灰工作区；首页容器遵循 1240／1360px 命名规则 | 原账号菜单、Broker 搜索、团队信息、全部角色入口 |

键盘发送提示只在桌面输入聚焦时显示；审计提示保留在输入区下方。手机键盘压缩可视区域时遵循原 P1 的紧凑输入布局，辅助说明让出空间。此处的真实软键盘效果须由 MOB-05 单独验收。

## 3. 全屏与研究结果

全屏继续使用 P1 的同一 DOM 树和 340ms 原生空间过渡。空对话将欢迎与输入集中在中间；已有回答时保留固定输入区与独立滚动正文。正文最大阅读宽度约 800px。桌面历史与研究面板使用柔和背景；窄屏保留原可收起和互斥策略。

首次 PR 生产截图的独立复核发现，窄屏历史头部占满 320px 面板，首条记录不可见。因此将窄屏导航并排、压缩头部和日期间距，将重复快照说明移入已有帮助，保留搜索、归档和 44px 操作面积。桌面布局与历史状态逻辑不变；首条记录的实际可见交集由新版浏览器回归确认。

结果按直接结论、范围与核心数值、图表／分析／楼宇与明细、来源和口径组织。单个答案保持连续阅读面，多个指标合用一条低强调数据带。每项分析不再重复显示长按钮标题，具体名称保留在可访问标签中。必要样本、分母、未知值、限制和原始来源均保留，不能因折叠复杂结果造成虚假完整性。

图表、Excel／CSV／SVG、复制、地图跳转、历史恢复、分页与来源焦点回退均沿用原链路。已挂载结果在模式切换时继续保留，展示回执的 visible 条件没有改变。

## 4. 行为保护与针对性回归

受影响路径包括首页首次渲染、建议填入草稿、能力说明展开、键盘循环、Compact／Expanded 切换、历史输入与研究结果阅读。间接依赖是原权限刷新、本人历史、交付回执和导出；这些正式服务均未重写。

独立代码审查发现：CSS 隐藏整个辅助 footer 时，旧焦点过滤器只检查节点自身，仍将隐藏 summary 作为循环目标。新增实际 HomeQuery 父组件回归，以短视口的同等祖先 `display:none` 条件验证 Shift+Tab 应到最后可见发送按钮；旧过滤器失败并聚焦隐藏 summary，修复后同一用例通过。焦点候选使用文档顺序，检查祖先可见性，保留 IME／229／defaultPrevented 保护。

建议词的可访问名称包含可见短标签和完整问题，语音与读屏均能定位；动画 compact 圆角读取同一语义令牌。键盘移动允许浏览器将长回答中的当前控件滚入内部视口，避免有焦点却看不到目标；工具栏继续保留至少 44px 操作面积。没有添加模式 key、第二个输入框、路由切换或会话持久化。

后续独立审查补出既有来源／摘要区域程序聚焦的实际路径：它们使用 `tabIndex=-1`，不能将“不在常规控件数组”一律当作工作空间外部。两条真实组件用例在旧循环中都误跳顶部主页按钮；按 DOM 相对位置继续正反 Tab 后，关闭与焦点返回、同一输入／结果节点及单次查询均通过。该纯交互修正晚于设计截图矩阵，两个版本指纹在验证记录中分别保留，最终浏览器证据由精确 head CI 重新生成。

现有测试按用户批准的信息架构变化更新三处预期：三个默认示例、按需身份说明、Intelligence 在导航末尾。原业务和权限断言保留，另外检查示例不虚构获权范围、只填草稿、无自动查询、同输入节点及完整草稿。
