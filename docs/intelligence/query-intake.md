# 入口与原文原子保存：本地检查点

基线 `8c728f9`。本包推进 A01/A06/A07/A10、AUTH07/AUTH10 和 R10/R14/R17；99项及T01–T60继续保留。没有生产迁移、后续main合并、AI启用、模型调用或新增账号权限。

## 问题与实际改动

旧HTTP先提交无正文的入口事件，再调用问答审计接收。两次事务之间中断，会有“已记录一次接收，但原文未保存”的缺口。旧数据库回归确认：入口行存在，问答流不存在，无法恢复用户所问。

现在复用原 `ai_query_ingress_events`，为每次有界、身份已验证的提交同时保存入口元数据和加密原文。新的 `ai_query_record_intake` 单事务插入同一行，成功即有完整受保护内容；失败则整行回滚，HTTP不执行新业务查询。原有问答状态机、执行观察记录和结果档案继续负责后续阶段，不把入口接收当作查询授权或业务成功。

- 接入查询、结果恢复、图表/导出和客户端回执。拒绝权限、功能关闭、格式错误、非法模拟等提交也先留存；不采集输入框草稿。
- 入口event_id标识每次HTTP尝试，request_id保留现有业务幂等关系。相同请求的不同尝试分别留存；一次传输事件的重放要求元数据和密文完全一致。服务端重新加密产生新nonce时不能伪装为同一传输重试。
- 同键不同问题的原文也保存在该请求的独立入口行；现有冲突处理另建拒绝审计流，`rejectedRetryOf`关联原请求。不能用请求数代替尝试数，也不能把该关联说成所有阶段已完整outbox化。
- 完整JSON在识别明确凭证后脱敏；保留业务文字、脱敏类型及原始正文的HMAC摘要。未脱敏时保留原始格式。密文AES-GCM绑定入口事件、请求、实际/有效身份；会话、入口、原文、策略和未评估状态在密文内。
- 控制字符可能让24KiB正文在JSON中膨胀六倍；超过80KiB时使用`query-intake-envelope/1` gzip-base64后再加密，不截断。读取先验证AEAD，再由`decodeIntakeDocument`按512KiB解压上限解析。普通正文仍使用原JSON文档格式。
- 回执是技术协议，不是业务提问：有效回执保存脱敏报告和令牌SHA256，不复制可用deliveryToken；非法技术回执保留有效性、长度及摘要，不保存任意附加文字。
- 匿名、超大、非法编码、接收中断保持有限安全元数据，不将截断内容冒称完整。身份未验证不假造账号。旧无正文记录不猜写、不回填。

## 权限、升级与故障语义

原私有表保留RLS及原始表读写撤销，包括service_role；新公开RPC是invoker，私有实现是definer且空search_path，只授予service_role执行。入口凭据不等于业务/审计读取权。普通管理员不因此获得他人正文。

升级后旧`ai_query_record_ingress`只接受未归属身份的有界安全事件，拒绝`request_received`，防止旧调用继续产生无正文的正式接收。新应用与新迁移必须协调发布：旧应用遇新迁移会拒绝AI提交；新应用遇旧库也拒绝执行。生产尚未应用，不能称无缝兼容发布；回退不能简单恢复会丢原文的旧接收路径。

对账额外报告`orphan_content_retained`及样本中的`content_retained`/入口类别。内容已保存但未生成执行流，与旧版本丢失正文分别统计。此包不自动重跑孤立入口、不虚构查询结果，也不自动给它补业务成功。

两阶段之间仍可能没有问答执行流，但已保存的入口原文可供后续获权审计恢复。完整审计台的跨账本检索/阅读、孤立入口处理流程和独立检查点仍待完成；当前不新增可绕过审计资格的正文读取RPC。入口与执行记录同库，不构成库外独立计数证明。

HTTP尚未读完、身份验证或密钥配置失败、数据库接收事务未提交时，不能承诺每次网络到达都留存原文。代理级独立安全计数、数据库不可用时的可靠接收队列，以及原文/索引/备份生命周期仍属后续范围。数据库超级用户不在此权限模型的绝对防篡改保证内。
