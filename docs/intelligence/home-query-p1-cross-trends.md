## 1. 实现契约

新增固定维度的 `cross_trend` 计划：`scope`、可选 `filter`、`metric`／`metrics`、`start`、`end`、`mode`。维度固定为当前目录的子市场 × 等级，不能提交任意字段、SQL 或第三个分组维度。期间为包含起止的连续 2–40 个季度，指标继续限于净有效租金、空置率和季度总面积。

复用原获权快照 RPC，先检查所有指标及筛选字段的授权，再读取一次完整事实快照。两个分类轴的来源、全集、版本及跨期稳定性沿用现有目录分类校验。正式指标复用 `quarterSeries` 与精确数值引擎，不另外计算一套平均值。

- **各期样本**：每个子市场 × 等级组合，按每期、每项指标各自有效记录计算。
- **共同样本**：每个组合、每项指标内部取全部查询季度的有效楼宇交集；不是相邻两期轮流换样本，也不强迫不同指标共用样本。
- **空组合与缺期**：先在获权目录建立两个完整分类轴，再筛选；空组合、缺期、未知分类不因无有效值而消失，未知指标不补零。
- **历史范围**：当前分类不代表历史等级或历史市场全集。新增／退出有效样本不自动等于新入市／退市，不从均值变动推断市场原因。
- **分母与口径**：净有效租金继续按有效总面积加权，空置率继续使用同指标有效记录的空置面积合计／总面积合计，季度总面积沿用原合计；空置率变化保持百分点。

长表按子市场、等级、季度分别保留维度列，稳定行键为交叉组合键／季度键。结果参数使用 `cross-trend/1`、明确的起止季度、样本模式、两个分类轴及各项指标。每个组合独立形成趋势、样本差异和异常证据，不能先把格均值汇总后冒充市场指标。

## 2. 自然语言与继续追问

本批实现的闭环包括：

1. `2026Q3 CBD、金融街不同等级写字楼的净有效租金和空置率` → 原单季交叉结果。
2. `再看最近四季度变化` → 保留两个维度、两个指标和范围，转为双维趋势。
3. `共同有效样本呢` → 改为各格、各指标的全期间共同样本。
4. `再加上季度总面积` → 保留原条件并增加第三个指标。
5. `按子市场看呢` → 明确覆盖为子市场单维趋势；不再暗中保留等级。

明确选择一个季度时回到单季交叉；明确按等级时同样覆盖原分组。模型候选必须完整保留确认的指标、两个维度、期间、样本模式和筛选，不能降成总体均值或仅执行一个季度。未知、冲突、历史分类和未获权第三维仍澄清。

仅比较两个不相邻季度，不等于查询中间全部季度；不能为套用趋势操作而自动扩充期间。对应不支持的组合要说明并给出可执行的连续趋势选项，由用户选择后才扩为连续区间。

## 4. 查询复杂度与性能预算

在计算前限制每个分类轴最多 50 类、双维趋势最多 50 个交叉组、交叉组 × 季度 × 指标不超过 1000。超过时拒绝同步查询并提示缩小范围，不截断组合，不假称已排队后台处理。单季度交叉原有 400 格限制不变。

继续保留既有共享研究补充、异常明细、来源引用和 15 MiB 正式结果归档前上限。补充分析超限与正式查询被拒绝分别说明，不能把缺失分析写成完整结论。

实施前固定以下验收条件：

| 路径 | 样本与终点 | 预算 |
| --- | --- | --- |
| 原单指标 P1 A/B | 当前已发布 `69f51a6…` 与本批，同条件 640 样本 | 桌面可操作 P90 ≤2.5 秒；手机配置 ≤3.5 秒 |
| 原多指标分组 | 保留既有 80 样本，数值、切图与来源继续核对 | 同上 |
| 新双维趋势 | 两设备 × 各期／共同样本 × 每条件 20 次，共 80 样本；三指标、四季度、实际追问和两次指标切换 | 内容与每次切图同设备 2.5／3.5 秒预算 |
| 首次反馈 | 浏览器实际绘制，非 API 返回时间 | P90 ≤100 ms |
| 已载入来源再次打开 | 实际来源面板绘制及回执 | P90 ≤500 ms |

桌面条件为 1280×900、60 ms、30/10 Mbps、CPU 1×；手机配置为 390×844、150 ms、10/5 Mbps、CPU 4×。服务器和数据库预热，不冒称冷启动、生产外网或物理手机实测。保留失败、原始样本、实际 HTTP 及有限端点分类，预算不因增加复杂度而放宽。

原真实 Auth/HTTP 和 640＋80 性能 job 保留；新增独立 runner 执行双维趋势实际 HTTP 与 80 浏览器样本，避免串行新增工作导致原 job 超时。suite 必须是明确定义值，报告记录 suite、PR head 与实际测试 merge SHA；两个 job 均是本批合并门槛，不能只检查其中一个绿色。新增双维趋势在完整报告写入后对 `budgetsMet` 作硬断言；原两份报告的所有预算继续作为合并前检查条件。

第三轮实测定位到大型 JSON 传输开销后，对获权成功的查询、恢复和图表响应增加 `Accept-Encoding` 协商 gzip。16 KiB 以下或明确不接受 gzip 时保留普通 JSON；缓存仍为 `private, no-store`，`Vary` 同时保留身份与编码。解压后的原始 JSON、全部来源、归档及 SHA-256 交付摘要不变。压缩在最后一次实时权限／来源复核之前完成，不用跨用户缓存或跳过审计换取速度；CSV／XLSX／SVG 下载协议不变。
