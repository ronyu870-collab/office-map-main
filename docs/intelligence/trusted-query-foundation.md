## 已核对的数据契约

| 来源 | 本次核对的实际入口/字段 | 新查询处理及尚未解决的范围 |
| --- | --- | --- |
| 楼宇身份 | `src/types/index.ts`、初始 schema 的 `buildings.id/name/submarket/grade` | 保留独立楼宇 ID；名称同样需要记录来源。当前主档地域不冒充历史地域。完整目录读取/别名消歧仍需接入 |
| 季度指标 | `building_metrics` 的 `(building_id,record_year,record_quarter)` 唯一约束；`total_area/net_effective_rent/vacant_area` | 精确季度，逐指标有效样本；不采用最新季度补缺。原存储为 double precision，新引擎对取得的十进制表达精确计算，不能恢复入库前已经丢失的精度 |
| 季度状态 | `is_draft/is_locked/data_source/updated_at` | 最大季度不等于审定，锁定不等于业务审定；真实读取适配器仍需隔离验证草稿排除及版本一致性 |
| 楼书参数 | `20260910160000_add_building_brochure_compare_data.sql` 的 `building_height/building_floors/parking_total` | 建筑高度、楼层数、车位数分开；不以层数替代高度。层数保留来源口径。多版本优先级/项目楼座归属需明确，不能将全部历史版本直接塞入“同期候选”解析器 |
| 既有统计 | `src/utils/calculations.ts`、`src/utils/debugStats.ts` | 租金复用正租金、正面积的数学口径；精确实现由性质测试与既有公式对照。零租金保留原值但不自动作为有效市场租金。旧 debugStats 对缺失空置面积计零，新查数不使用该辅助实现，也不改变线上地图 |
| 既有 AI 推荐读取 | `src/lib/intelligence/recommendationServer.ts` | 指标 5000/楼书 3000 上限不可用作统计全集。新快照检查不完整/计数不符/重复实体时拒绝汇总，但真实完整读取服务尚未接通 |
| 现有权限 | `impersonationAuth.ts`、地图 RLS、`lease-transactions/read/access.ts` | 实际与有效身份分别保存；普通角色历史成交仍禁止。本包不修改既有数据权。未来新查询额外资格默认拒绝，不能把公开预览标志当授权 |

本包没有查询生产覆盖率，没有宣称任何真实楼宇已有高度或原件来源。来源登记目前为 6 个数值字段的第一批明确契约；其余数据域仍保留在完整计划中，未改为不支持或取消。

## 实际代码

- `src/lib/intelligence/query/decimal.ts`：有界十进制解析、精确分数计算。未知、非法类型、非有限数不转零；计算值与图表近似投影分离。
- `registry.ts / contracts.ts / facts.ts`：字段/单位/期间/记录版本绑定，原件未关联和未核验状态，字段级三值条件、快照完整性和重复楼宇检查。来源必须由后续可信读取适配器提供，模型/客户端不能自报。
- `analytics.ts`：已知有效样本排名及边界并列、逐指标分母/贡献/排除原因、各期与配对样本比较。空置超面积为无效，空置变化用百分点。
- `plan.ts / admission.ts`：严格查询结构、函数与字段资格；筛选字段也查权限；先持久审计，后权限复查和执行，交付前再次复查。普通管理员身份不自动补齐 grant。行/来源权限仍必须在读取层执行，本文件不替代 RLS。
- `result.ts / exports.ts`：不可变结果、字段来源、表格、柱/散点绑定、CSV 与配套 manifest、四工作表 XLSX。图种不带数值，不能重编数据；当前楼宇表拒绝伪装成时间趋势。Excel 数值列保留数值类型，另保留精确分数；不可信文本不能成为公式。
- `auditCrypto.ts`：AES-256-GCM，问题/回答与请求、事件、实际及有效身份绑定；支持按 keyId 读取历史密钥、独立 HMAC 指纹、有界 UTF-8 正文。仅识别明确凭证模式，不宣称能发现所有秘密。

`admission.ts` 当前通过注入的审计/执行端口验证顺序，尚未连接数据库适配器或 HTTP 路由；不能将这些测试当真实 API 已完成。`response_generated` 与执行 `succeeded` 不等于用户看到答案；最后一刻撤权追加“不交付”修正，不覆盖已经记录的执行事实。

## 审计数据库

迁移：`20261113003933_ai_query_audit_foundation.sql`，仅创建于本地，在一次性 PostgreSQL 17.11 中验证。

- 为现有审计体系增加私有的加密问答事件存储，普通 `audit_logs` 不放全文。实际角色快照从 `user_roles` 读取；不依赖客户端自报角色，不自动为任何姓名/账号授予审计权。
- 请求接收和首条事件同事务；失败回滚。每请求锁定事件序列，并发追加无丢失；同事件重试幂等，不同身份/正文指纹复用请求拒绝。
- 事件及正文只允许追加。修改和结算为新事件；终态不能重新进入运行。保留收取后拒绝的问题及无效模拟身份。
- 未暴露 schema 内使用 security definer，空 search_path；公开 RPC 只是 invoker 壳，仅 service_role 可调用。服务角色没有私有表直接读写或给自己授审计权的权限；应用必须先验证实际会话，不能让客户端直接指定 RPC 的 actor。
- 问答读取使用独立资格和有效期；普通管理员被拒绝，模拟身份不能借用真实账号审计资格。允许/拒绝读取均先写访问审计，失败不返内容。
- 哈希链覆盖事件及身份/策略上下文，核验接受独立保存的头哈希和序号，能发现正文修改、中间/尾部删除。**尚未接入独立检查点存储/签名、备份恢复或全局接收清单，不声称数据库管理员绝对不能篡改。**
- 目录身份有效只说明角色存在及模拟关系合法，不代替 JWT/session 撤销验证。没有 seeded grants、保留期限默认批准、生产启用或新增用户权限。
