# 提问审计页面（本地工作包）

路由 `/intelligence/audit`，复用[受控审计读取](audit-console.md)。新页面在独立审计资格下运行，不放入只允许 admin 的管理后台布局；旧审计日志页提供导航，不因为链接可见而授予正文读取权。未合并、未发布、未给真实账号授权。

## 设计与范围

主任务是查找正式提交的问题并核对其回答来源。阅读路径如下；详情在选中行之后原位展开，手机使用同一内容与动作，不另造数据口径。

```text
AI 提问审计                                      返回主页
用途和独立资格说明
关键词                                          检索记录
开始时间 / 结束时间 / 关联状态 / 入口
按账号筛选（展开）
提交时间与入口状态
问题摘要
操作账号
  └ 完整原文 / 提交字段 / 关联回答与来源 / 事件
继续下一批 / 返回首批
```

采用系统字体 Arial/PingFang SC/Microsoft YaHei；页面标题 20px、正文与控件 14px，400/600 两种字重。六个主要色值：画布 `#F5F7FA`、阅读面 `#F8FAFC`、正文 `#172033`、辅助文字 `#667085`、强调 `#003E7E`、分隔 `#D9E0E8`；边框强度复用系统色。来源表复用主页原组件与其既有局部样式。

对照用户简约统一要求：使用连续记录列表而不是统计卡片；原文是视觉重点，时间、身份和状态相邻排列；详情随选中记录展开，不把相关信息拆成远距离双栏；没有装饰图片、欢迎横幅或大面积深色。初版采用自检，实际整页视觉与手机证据单列，不用规则或测试代替视觉结论。

本包可按原文关键词、31天以内任意历史时间段、操作账号 UUID、入口、关联执行状态检索；完整原文、脱敏类型、原始字段、生成回答快照、单元格来源、版本和处理/交付事件可查看。姓名目录、模型/费用/原因专项筛选、审计导出和账号授权管理未完成，A04 仍为部分完成。

## 数据与交互

- 正式点击检索才提交条件，不采集逐键草稿；输入不随加载、空结果或返回结果重建。中文组词期间 Enter 不提交。
- 每批最多检查50条候选，关键词匹配可能为零而仍有后续；下一批沿用已提交条件与签名游标，不混入新的筛选草稿。界面不虚构匹配总数；正文不可读时说明检索不完整。
- 时区明确为北京时间，页面与接口均限制范围。关联状态是请求执行流状态，不证明每条重试独立执行。
- 问题与事件正文作为文本显示，不执行HTML/Markdown、链接或外部内容中的指令。结构化快照通过浏览器安全 schema 后复用 HomeQueryResult；不传查询 scope/requestId，不触发业务下载、重新查数或伪造用户交付回执。
- 快照按当前渲染器展示，不能冒称当时逐字显示或像素还原；生成、准备响应、客户端软件回执与人类阅读/磁盘保存严格区分。无法识别的其他快照类型仅提供留存字段，不生成替代答案。
- 服务端解密、资格与查看审计沿用原接口。新增客户端只使用现有 Auth 会话，不携带 service key、不引入权限真相；请求前后都核对真实账号、有效身份、sessionId、模拟状态。
- 响应按流读取且总计不超过64MiB，40秒超时，JSON/schema/目标编号异常拒绝展示。网络/校验失败、无权与身份变化分别提示并清除全部已读内容。
- 内容只在组件内存中保留，不写浏览器持久存储。账号/会话变化重新挂载；页面隐藏/pagehide、列表取得后60秒自动收起，并取消在途请求；迟到响应被抑制。再次查看需重新检索，不进行静默后台全文轮询。这不能撤回用户此前已看见或自行复制的信息。
