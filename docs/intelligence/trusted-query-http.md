# 可信查询第三工作包：实际 HTTP、拒绝审计与真实 Auth

2026-11-13。承接本地提交 `de33f6e`，分支 `codex/ai-trusted-query`。本包只在专用本地 Supabase 栈、合成账号/数据和真实 Next 构建中验证。未合并 main、未执行生产迁移、未启用主页输入、未调用模型。

## 接口契约

`POST /api/intelligence/query` 仅接受 Bearer 登录，复用现有 Auth 和模拟身份解析。输入为 `{ idempotencyKey: UUID, question: string, plan: QueryPlan }`，只允许这三个字段。`question` 保留正式提交的业务问题，**当前执行依据是结构化 plan，尚未实现自然语言理解**，不能因附带一段中文问题就宣称已经理解它。

- 按实际流字节限制 24 KiB、问题最多6000字符；不相信 Content-Length。UTF-8跨块字符正常解码；超大、无效编码、中断和停滞读取均有明确状态，不能把截断正文冒充原文。
- 每次 HTTP 到达形成独立 ingress 事件；实际已认证操作者与 session_id 来自服务端验证，不能由请求正文冒报。匿名/恶意/超限事件仅保留有界元数据及带密钥摘要，不存认证Header、IP、问题前缀或虚构身份。摘要明确完整或前缀，长度只表示实际观察到的字节。
- 有效身份的正常、无查询资格、非法字段、格式错误、深层非法条件和模拟拒绝均先保存加密正式提交，再准入或拒绝；合法输入的完整业务文字保留。明确凭证脱敏，JSON内转义的多词密码先解析后脱敏；需要脱敏时原始JSON转为明确的脱敏表示，入口摘要仍对应原始字节。
- 原业务地图/填报接口不依赖此存储。新入口审计失败只让本次新查询失败，不以未落审计的问题继续读数据。
- 成功200返回 `requestId + result`；重复已接收202不重跑；未认证401；无权/非法条件403；内容冲突409；过大413；服务或审计不可用503。此版202尚无用户恢复页面或结果轮询API，不能视为完整异步工作流。
- 返回 `private, no-store` 并按 Authorization/模拟头区分；不开放跨源浏览器访问，不接受客户端自报权限、SQL、成功结果或费用。

## 幂等与身份

客户端只提供随机幂等键。服务器将实际身份、有效身份和该键映射为确定的内部 request_id；同一个键跨用户不指向同一审计流，不允许用全局请求UUID探测他人是否提过问题。

同一问题的幂等摘要不把刷新后的 session/当前资格当作新正文；实际首次上下文仍受AEAD和数据库链保护，每个重试的实际 session 记录在独立入口事件中。真实重新登录后重复提交也不重跑。授权变化仍在重放前检查，撤权不会借重复请求返回旧结果。

同键不同正文会创建新的受控拒绝审计，关联冲突的内部请求号并返回409；不能只留一个摘要而漏掉这条正式问题。此版本的幂等HMAC密钥轮换、旧结果恢复与跨密钥对账仍需后续生命周期实现，不能宣称已经支持无缝轮换。

## 执行与交付

路径为：有界接收 → 验证实际/有效身份 → 入口账本 → 完整问题审计 → 当前查询资格 → 字段/范围/结构校验 → 一致快照 → 同源结果 → 加密生成结果 → 响应准备记录 → 最后权限版本比对 → 返回。

首次接收标注 `authorization-pending`，不是伪造已经授予资格。真正运行事件再保存当时完整资格与策略版本。当前拒绝事件尚未在所有分支补齐具体配置版本和细分业务拒绝原因，完整A02台账仍需后续完善。

`response_generated` 记录生成结果，执行成功仍为 `not_yet_sent`；`delivery_receipt` 的 `response_prepared` 只记录准备好的结果ID、HTTP正文摘要和 `clientReceipt=unconfirmed`。**没有客户端确认，不记已读。** 后续用户界面、实际接收/展示回执、流式段和重连恢复尚未完成。

最终交付检查不仅要求仍有查询资格，还要求权限版本与实际读取时一致。只缩小字段/楼宇范围但保留部分能力，也不交付旧范围结果。该检查发生服务故障时返回503并记录“权限无法确认”，不编造“用户已撤权”。服务端执行期限与用户主动取消分开记录。

## 配置和数据库

- `AI_QUERY_HTTP_ENABLED` 默认不为true；数据库总开关默认关闭且不预置用户资格。两层及当前会话/字段/行范围必须同时满足。主页仍显示尚未开放，没有新增前台自动请求。
- 需要独立的 `AI_QUERY_AUDIT_KEY_ID`、32字节十六进制 `AI_QUERY_AUDIT_ENCRYPTION_KEY` 与 `AI_QUERY_AUDIT_DIGEST_KEY`；两把密钥不得相同。只从服务端配置取得，不进入客户端包、日志或测试结果。未配置完整审计时接口503，不开放用户提问。
- `20261113032515_ai_query_http_security.sql` 新增私有只追加入口账本和服务端RPC；匿名/普通用户不能直接读写，服务角色也没有表直接权限。该入口账本提供独立于问答事件的接收核对依据，**尚无自动对账后台、独立外部检查点、保留/删除治理或故障恢复系统**。
- 服务调用、入口读取和整个执行均有有限应用期限；不把HTTP中断当成数据库或供应商肯定停止。此接口没有模型/供应商调用，费用账本和跨实例限流尚待实现，不能据此授权正式试用。
