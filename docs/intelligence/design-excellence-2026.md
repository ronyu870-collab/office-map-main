## A. 诊断与取舍

从现行组件调用链、既有规范、两个独立只读审查和实际页面出发，优先处理下面的问题。优先级综合用户影响、使用频率、一致性与实施风险，属于设计判断，不是客观打分。

| 优先级 | 现象与原因 | 本轮处理 |
|---|---|---|
| 高 | 单楼宇摘要没有渲染 `ResultBoundary`，历史、未核验和未知值限制在此表达类型中缺席 | 直接结果之后统一承接重要限制，保留来源入口 |
| 高 | 单指标的范围和季度需要回看问题或来源 | 核心指标旁复用规范化 `resultScopeText()`，不从模型文字猜范围 |
| 中 | 完整楼宇列表的五个字段各有边框底色、数值普遍加粗，身份和经营指标混在一组 | 楼名、区位等级、三项指标分组，以行边界和共同列线组织 |
| 中 | 直方图区间主要依赖鼠标标题，无法像趋势图一样直接用键盘读取和追溯 | 点击或 Enter/空格选择区间，显示精确边界、数量与来源入口 |
| 中 | 地图四个指标各套小卡片，与导航、工具条叠加边界 | 同一行组呈现；手机两列保留紧凑行距，给地图和摘要让出空间 |
| 中 | AI 结果 CSS 多次追加相同选择器；完整列表楼名样式被地图全局按钮规则覆盖 | 按最终有效值合并样式；让楼名在所属身份组内恢复 16px/600 |

当前 main 已具有单一输入区、答案类型选择、图表默认策略、可展开数据工作区、来源面板、地图真实侧栏、区域阅读模式、标记形状区分及恢复机制。本轮核对并复用，未因任务标题要求而再次开发。详情、子市场和地图相机也沿用最新实现。

## C. 设计系统

- 沿用 `workspace #f5f7fa`、`surface #ffffff`、`surface-alt #f8fafc`、`text-primary #172033`、`text-secondary #667085`、`brand #003e7e` 等现有语义 Token。没有新建色板。
- 本轮正文、字段、图例、说明复用 14px，楼名和既有关键读数复用 16px；常规字重为 400/600。标题和数值不各建一套尺度。
- 间距沿用 4/8/12/16/24/32px 系统。手机顶部指标的纵向间隔为 4px，横向为 16px；不能直接把桌面组距套到短屏。
- AI 保留 50rem 连续阅读轴，表格等数据面可展开；地图为高密度空间工作区，完整列表使用稳定三列指标。媒介差异通过布局表达，不增加字体系统。

实际截图用于检查文字成组、对齐、留白和手机完整性，自动化检查覆盖溢出、几何、焦点及真实图形绘制；不是自动审美评分。现有固定宽度复杂 SVG 在手机使用有名称的横向滚动和原始明细，未缩小文字或改动导出几何。

### Skill 使用边界

Impeccable 用于诊断、降噪、排版、响应式和精修，`improve-ui` 仅做只读评审；frontend-design、ui-ux-pro-max、Web Interface Guidelines、React best practices 与 dataviz 用于相应判断。缺失指南从官方仓库加载 Markdown，没有执行安装脚本或更改产品依赖。

Impeccable CLI 的 context/detect 因本机缺少 engine 且缓存目录不可写未能运行，不能声称检测器通过；改用现有规范、源码、独立审查和真实渲染证据。ui-ux-pro-max 的通用搜索结果与本项目不匹配，未套用其模板。
