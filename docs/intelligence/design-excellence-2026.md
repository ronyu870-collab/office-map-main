## A. 诊断与取舍

从现行组件调用链、既有规范、两个独立只读审查和实际页面出发，优先处理下面的问题。优先级综合用户影响、使用频率、一致性与实施风险，属于设计判断，不是客观打分。

| 优先级 | 现象与原因 | 本轮处理 |
|---|---|---|
| 高 | 单楼宇摘要没有渲染 `ResultBoundary`，历史、未核验和未知值限制在此表达类型中缺席 | 直接结果之后统一承接重要限制，保留来源入口 |
| 高 | 单指标的范围和季度需要回看问题或来源 | 核心指标旁复用规范化 `resultScopeText()`，不从模型文字猜范围 |
| 中 | 完整楼宇列表的五个字段各有边框底色、数值普遍加粗，身份和经营指标混在一组 | 楼名、区位等级、三项指标分组，以行边界和共同列线组织 |
| 中 | 直方图区间主要依赖鼠标标题，无法像趋势图一样直接用键盘读取和追溯 | 点击或 Enter/空格选择区间，显示精确边界、数量与来源入口 |
| 中 | 地图四个指标各套小卡片，与导航、工具条叠加边界 | 同一行组呈现；手机两列保留紧凑行距，给地图和摘要让出空间 |
| 中 | AI 结果 CSS 多次追加相同选择器；完整列表楼名样式被地图全局按钮规则覆盖 | 按最终有效值合并样式；让楼名在所属身份组内恢复 16px/600 |

当前 main 已具有单一输入区、答案类型选择、图表默认策略、可展开数据工作区、来源面板、地图真实侧栏、区域阅读模式、标记形状区分及恢复机制。本轮核对并复用，未因任务标题要求而再次开发。详情、子市场和地图相机也沿用最新实现。
