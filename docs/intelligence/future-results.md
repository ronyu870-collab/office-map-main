# 未来供应不可变结果与来源交付检查

本包在[未来数据基础](future-observations.md)上增加实际 QueryResult、同源表图文件与服务端来源复查。仍为本地内部集成，不代表主页未来供应问题、公共恢复/下载接口或试点已经开放。下一步要接通原主页及统一请求/恢复流程，特别是只有未来权限而无存量权限的 admin，不能为兼容旧入口补授存量资格。

## 结果与表图文件

一个获权未来快照生成一个不可变 result_id，保留实际 request_id、数据库快照、数据版本、范围、所查季度及配置依据。所有单元格沿用实际未来记录 ID 和来源 ID，不转换为存量楼宇身份；无关联时明确未关联，不按同名推断。

十一种投影包括目录、预计时间精度、任务覆盖、季度记录、未提交、未分配、人员任务、本人未提交、质量、缺项及异常。预计季度/半年/全年/未知/无效互斥统计，半年和全年不拆成确定季度。人员数量使用“任务/项”，目录使用“记录/条”，避免同名项目、多负责人或未关联记录被称为已核实不同楼宇数。任务覆盖保留分母为零时未知，不能显示0%。

目录表包含当前记录名称、分类、预计时间、子市场、等级、原总面积和是否关联楼宇。质量表展示最新整条的实际八字段，缺少提交时间时明确不能判定最新，缺值不从旧行补充。pending、分类未知与已录入future分别表达，数据库分类不能冒充现实核验。

主表可生成绑定同一单元格的柱状图，预计时间精度图不冒充入市时间轴；质量数值图保留0.5表示0.5%。Excel增加未来目录、时间精度及获权的任务/人员/质量页，保持数值类型；CSV与SVG配合同一结果manifest，记录原始来源和限制。超过1000条未来记录的汇总来源沿用完整ID分段，不截断证据。只有目录时不产生人员/质量页，只有进度时不产生质量页；内部投影函数也拒绝从缺失权限的数据模式生成这些视图。

本包没有面积汇总、地图或预计时间区间图。坐标只做已有数值范围检查，未证明坐标系或地址，不能直接当作已核实位置。PNG/PDF、所有图种和对话改图仍在完整计划中。

## 来源复查与撤回

新增 `ai_query_future_sources_allowed`，私有definer/公开invoker均固定空search_path，仅服务端角色可执行。复用当前admin本人、真实会话、未来资格及独立实体范围；必须存在本人成功请求、有效身份与完整审计链，检查本身写入结果访问记录。没有成功审计、错误身份/修订、未知表或额外字段均不放行。

逐条检查未来记录、分配、提交和配置来源：名称等目录字段属于实际future记录；任务/提交必须仍归属同一未来ID及原年季；质量字段额外要求质量资格；配置仅允许实际采用的两个键。已入市、入市状态未知、关联楼宇已转存量/停用/合并、来源移出范围或被删除时拒绝。普通角色即使持全部资格也拒绝，浏览器不能直接调用RPC。读取旧结果不要求业务数值仍等于旧值，合法更新不改写加密旧快照；是否可以读取由当前权限与来源归属决定。

应用调用方必须同时复查原始查询条件和当前资格，不能只依赖一份空sources数组；公共首次响应、恢复及下载的接线尚未完成，当前没有宣称这些未来用户路径已受此检查保护或已经可用。

验证纠错：动态导入Excel后，测试bundle需要明确单文件输出；按安装版本Rolldown文档设置codeSplitting:false，仅影响隔离测试。另一处测试直接读取PG bigint事件序号为字符串，与实际JSON接口数字类型不同，改为SQL显式integer投影；归档完整性检查保持不变。环境恢复导致旧句柄和临时日志丢失时，已确认进程退出后重建专用栈，不用旧112场景记录冒充新验证。

事件序号类型修正后，测试SQL的重复列名又触发ORDER BY歧义，最终使用明确表别名e.sequence排序；该问题没有通过放宽归档检查解决，最终脚本在新库复跑。
