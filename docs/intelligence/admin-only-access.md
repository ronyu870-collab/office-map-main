# AI 仅供 admin 使用（本地工作包）

2026-11-13 用户明确要求「这个AI功能只能供admin使用」。本包将当前入口、查询/导出权限链和审计资格收紧到服务端当前角色为 `admin` 的本人账号；既有独立资格和数据范围继续生效。没有生产迁移、真实账号授权、后续main合并或AI正式启用。

## 当前规则

| 身份与资格 | 结果 |
| --- | --- |
| viewer/editor，即便持所有独立资格 | AI主页区域隐藏；查询、恢复、图表、下载、审计接口拒绝 |
| admin，无对应独立资格 | 对应查询/导出/审计动作拒绝；角色本身不授予正文访问权 |
| admin本人，具有有效对应资格 | 仍按当前会话、记录/字段和来源范围执行 |
| 模拟另一账号或模拟本人 | 新查询链与旧解析/推荐拒绝；主页不显示AI区域 |
| admin降级/停用/注销或资格撤销 | 新查询链后续执行、交付、恢复、下载及审计重新检查，不放行旧JWT/结果编号 |

旧 `NEXT_PUBLIC_INTELLIGENCE_PREVIEW=true` 不再放行普通角色。共享判断同时被主页、既有Intelligence/方案界面和解析/推荐服务端使用。F6已有管理员保护保持；本次真实HTTP再次验证其普通角色拒绝路径。原非AI地图、填报、研究资料等权限与导航不变。

前端角色展示可能滞后于数据库更新：实测当前页面在能力刷新后先清除结果并禁用查询，页面刷新重新取得角色后隐藏整个AI区域；不能将此描述成数据库变更瞬间推送到了所有浏览器。服务器按每次授权边界读取可信角色，前端角色不是放行依据。已交付/已复制/已下载的信息无法远程收回。

## 实现与升级

- 追加迁移 `20261113123123_ai_admin_only_access.sql`，不修改旧迁移。查询授权校验当前真实/有效角色均为admin且为同一人；审计授权也要求当前admin、有效会话及独立审计资格。保留原有行锁、实时资格范围、停用与会话检查。
- 权限revision加入 `admin-only/1`，使旧策略版本失效；授权成功及审计读取/准备响应携带策略标识。应用严格要求标识，混用旧数据库响应时拒绝执行或解密交付，不能依靠旧允许结果。
- 请求层拒绝模拟标头，包括目标为本人。权限从服务端可信表获取，不采用客户端metadata/角色声明；原限额内拒绝提问与审计访问留痕继续存在。
- 未新增账号授权或默认授予审计资格；Hang Yu审计仍需明确授予可信账号。原始审计表和服务端RPC不向authenticated/anon开放。
- 后续获准发布时先关闭新AI能力、部署迁移及匹配应用，再做角色矩阵和健康核验，满足门槛后另行获准启用。**不可回滚到旧的宽松授权函数**；回退应关闭能力并保留admin限制。当前没有执行生产发布。

## 实际验证

- PostgreSQL 17.11：6组实际数据库测试。先复现旧实现允许持资格editor查询/审计，与最新限制冲突；应用新迁移后普通角色拒绝。验证admin仍需独立资格、降级后已读审计不能准备返回、真实行锁竞争以及直接RPC保护。
- 实际Supabase SDK/PostgREST/审计适配器：11组通过。使用新迁移和admin样本，仍保持季度170租金/17.5%空置率、跨期与完整3000+行快照等已有结果。
- GoTrue/PostgREST/PostgreSQL17.6/生产构建Next真实HTTP：54组通过。含公开开关true、普通角色持全资格拒绝、admin自模拟拒绝、admin降级后旧JWT/快照/图表/XLSX/交付回执/审计拒绝；保留既有完整原文、同源导出、会话、撤权、故障与分页验证。全是合成数据，无模型或生产调用。
- 组件/协议回归：非admin主页无输入、角色降级后审计控件与旧内容消失、新应用拒绝缺失/旧策略标识。原页面保留测试期望旧普通用户禁用输入，已按最新要求改为无输入，同时保持原导航/账号操作断言。
- 本地全量verify、搜索焦点门禁及源码摘要见 [结构化证据](admin-only-access-evidence.json)。回归已接入现有CI工作流；未推送或执行远端精确head CI。
- macOS Codex内置浏览器：合成admin登录、主页查询CBD最高已知楼宇成功；数据库降为viewer后页面结果清除，刷新主页隐藏AI，直接审计页拒绝；390px窄屏无横向溢出，原业务入口完整。截图在 `docs/verification/admin-only-access/`。引擎版本未独立确认，无真实iOS/Android设备、无独立视觉评审，不代表用户认可新视觉稿。
