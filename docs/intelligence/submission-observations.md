仅进度资格的 RPC 在数据库内就不选择数值；响应 values 为空，记录版本也只按获准元数据生成，避免通过值或隐藏字段哈希带出数据。没有联系人、备注、草稿、任意字段或任意 SQL。当前质量资格授权的是这八个字段的固定包；更细字段子集配置仍需在后续权限管理中实现，不把这一步标为全部字段权限矩阵完成。

## 候选全集、期间与分母

目录采用现有填报管理模块的当前启用、tracked、stock、未合并楼宇，交集还包括既有地图可见性、当前账号获准楼宇/子市场和请求范围。先确定全集再连接分配与提交，不使用 API 默认的 1000 行当统计全集。楼宇、分配和提交计数与数据在一个 SQL 语句快照中读取。

`period=null` 明确指 app_settings 的当前填报季度；不是北京时间日历季度、最后一次有数据的季度或已审定季度。配置缺失/非法则报当前填报季度不可确定。明确年季可独立读取；即使配置未知也不改写所查期间。后续自然语言接入必须区分“当前填报季度”与“本日历季度”，含糊条件澄清。

分配表没有历史季度字段。因此分配始终标为当前关系，明确历史年季只表示该季度提交，不能把今天的负责人当成历史应报人员。

| 统计 | 分子/分母或去重键 |
| --- | --- |
| 楼宇提交覆盖 | 已分配且有该季任一人员提交的楼宇 / 当前已分配楼宇 |
| 人员任务 | 楼宇 + 负责人账号；只由该账号该季提交满足 |
| 未分配楼宇 | 获权目录中没有非空负责人关系的楼宇，单列 |
| 未分配但有提交 | 保留已存在的提交，不挤入已分配覆盖率 |
| 原始提交数 | 该季获权楼宇全部提交记录 |
| 同楼额外提交记录 | 原始记录数 − 有提交的不同楼宇数，不等于认定数据错误 |
| 重复分配 | 同楼同负责人多行仅计一个任务，同时保留原始行和异常数量 |

空白负责人关系单列异常，不伪造人员；同名不同账号保持分开，多个历史标签不擅自选成当前姓名。无人分配时覆盖率为未知，不写 0% 或 100%。

## 最新记录与质量规则

复用季度报告原有整条记录选择器，提取为 `src/lib/quarterly/latestRows.ts`，原模块仍 re-export 原接口。按 created_at（保留微秒）及 id 选最新整条，不按 updated_at 改变提交顺序、不按字段补旧值。任何同楼提交时间缺失时，该楼最新记录无法确定；保留“有提交”覆盖，但不猜测质量结论。

五项输入齐全沿用季度录入：报价、物业费、表面租金、免租期、空置面积。完整性与有效性分开：零值算已填写；负数、非法数值、免租期超过36个月、空置面积超过总面积等另行标记。总面积须大于0；净有效租金为0保留原值，但不作为有效面积加权租金样本。

八项白名单为 total_area、vacant_area、vacancy_rate、asking_rent、management_fee、face_rent、rent_free_period、net_effective_rent。数据库 numeric 先以文本读取，再使用 Decimal 精确计算。填报 vacancy_rate 单位始终为百分数，不按数值大小猜测；与面积重算差超过0.011个百分点标不一致，沿用现有报告容差。净有效租金与表面租金×(36−免租期)/36 的差超过0.005元/平方米/月标不一致，容纳既有两位小数记录。

检查只输出待核查项、原值、参与字段及来源，不修改数据。不完整、无效、不一致和不可用于市场指标分别保留。“已提交”“输入齐全”“可用于某指标”都不等于已经审定。不会读取草稿或 building_metrics 来补交表。
