## 2. 查询与展示契约

既有 `QueryPlan` 操作不变，聚合类操作新增可选 `metrics`，严格要求 2–3 项、唯一且首项等于原 `metric`。原单指标计划和结果保持兼容。未支持的字段、重复指标、不一致首项、SQL／任意工具字段及非法操作组合均拒绝。

执行流程为：原请求接收与幂等审计 → 回读已核权上下文 → 确定性语义／必要时一次受限模型意图 → 指标完整性及字段授权 → 各指标获权期间索引 → 一次现有获权快照 → 复用原聚合计算 → 同源宽表及研究补充 → 原来源／恢复／导出归档。

- `plan.ts` 统一导出指标集合和读取字段；`admission.ts` 与 `snapshotReader.ts` 使用同一集合核权和读取，不只验证第一个指标。
- `executePlan.ts` 只读取传入的一致快照；`multiMetric.ts` 组合原计算结果，检查期间、分组、scope、snapshot、dataVersion 和 source ID 内容一致。次指标值列按指标前缀命名，例如 `vacancy_value`，维度轴不复制。
- `multiMetricView.ts` 只读取经过校验的指标、列映射和已保存分析；`charts.ts` 将图绑定还原到宽表真实列。切换到空置率不能继续引用租金列或只改轴标题。
- `researchAnalysis.ts` 对每个指标分别生成趋势、样本与异常，复用全结果共享的资源／异常上限；不把每个指标的额度相加变成无限输出。
- `semanticPlanner.ts` 区分替换与添加：`空置率呢` 替换指标，`再加上空置率` 保留原指标并添加；普通地区／期间追问继承完整指标集合。模型不能将多指标请求降成单字段列表、排名或未要求的关系分析。
- `availablePeriods.ts` 对多指标最多并发执行三个原有获权元数据 RPC，并在任何读取前验证全部字段；索引逐组重新核权并取期间交集，保存各组期间、读取时间和截断信息。单指标路径仍只需一组。模型提出新获权字段时最多再执行一批，不增加模型调用次数。
- `HomeQueryResult.tsx`、`HomeQueryInsights.tsx`、`HomeQueryArtifacts.tsx` 展示各项口径、样本、结论与指标切换。切换期间清掉旧图；失败可按原指标重试；在途草稿、父轮绑定和账号隔离沿用 P0/P1。

示例：

1. `比较2026Q3 CBD、金融街和望京三个子市场的净有效租金和空置率` → 单次 `group_aggregate`，包含全部三个子市场与两项指标。
2. `再看看最近四季度变化` → 同范围、同指标组合的 `group_trend`，期间由真实可用季度解析。
3. `共同有效样本呢` → 原趋势改为 `paired`，分别核算每个指标的共同楼宇、变化和分母。
4. `2026Q3 CBD、金融街不同等级写字楼的净有效租金和空置率` → 子市场×等级交叉表，不把两个子市场合并成一个等级均值。
5. `CBD最新季度净有效租金和空置率` → 采用两项指标各自存在有效样本的最新共同季度；如果没有共同季度，则澄清，不丢弃其中一项。

## 3. 未开放字段的实际核查

生产只读核查证明 `building_brochure_data.completion_date`、`gfa_total`、`gfa_office` 与 `building_metrics.asking_rent` 已存在，不能再笼统称“数据库没有这些字段”。但它们不在当前独立 AI 字段授权和可信来源路由中。`buildings.completion_year` 的现有界面含义是“入市时间”，数据字典还混有建成／预计入市语义；不得直接据此算楼龄。

本次没有修改 grant、RLS、业务记录或生产数据库结构。更精确的限制文案已经接入。字段数量、缺失和来源状态的只读聚合证据见 [字段核查](../verification/colliers-ai-p1-followup/field-audit.md) 和 [机器记录](../verification/colliers-ai-p1-followup/field-audit.json)；它们是技术诊断，不是正式市场统计，也不代表对原始资料进行了新一轮核验。

新字段真正上线仍须明确其 AI 字段授权、业务日期／面积含义，扩展同一白名单／快照／来源／恢复权限契约，并执行隔离 PostgreSQL 与 Auth/HTTP 回归。这些条件不能通过擅自扩大权限解决。

## 4. 数据与权限保护

没有新增查询数据域或生产迁移。原 admin 本人＋独立资格＋字段／行范围继续生效。任何一个次指标所需字段无权，整个计划在元数据／事实读取前拒绝。会话、conversation、父轮、权限版本和原始请求归属保持，旧键重试回读首次计划与快照，不重新解析“最新”或重新调用模型。

各指标的正式公式未变：净有效租金按有效总面积加权，空置率按本指标有效记录的空置面积合计除以总面积合计，季度总面积按原有效范围合计。空置率变化保持百分点；缺失保持 unknown。跨指标有效楼宇不一致明确提示，不能把样本差异解释成市场原因。

最多三个指标、30 个表列；组合结果在归档前执行 15 MiB 保护，留出原 16 MiB 审计归档空间。补充分析继续受 5,000 观察、15,000 来源引用、4 MiB 补充输出、100 条异常明细和 5,000 个异常证据引用等全结果上限约束；超过时说明未完成／未列举，不改数、不补造。

如果正式组合结果本身超过上限，服务端保存失败审计并返回受控 `413 / scope_limit`，明确建议减少子市场、季度或指标，不声称已有后台任务。客户端保留草稿和编辑入口，停止对同一终态请求的无效重试／恢复。旧请求恢复仅确认 `failed` 而没有原因时，说明没有可恢复结果，不反推容量原因；网络未确认请求仍保留原幂等重试。
