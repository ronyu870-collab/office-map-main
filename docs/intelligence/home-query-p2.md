## 1. 授权与发布边界

用户明确授权 P2 前后端、地图联动、成果导出、本人历史管理及必要测试，在工程检查和分支保护满足后直接合入 main。仅独立视觉评审、人工浏览器视觉审查、真实手机人工验收豁免；自动浏览器行为与性能、真实 PostgreSQL、权限、CI、生产构建均保留。具体 PR 的仓库、分支、当前完整 head、范围与授权说明由既有 Visual acceptance evidence 机制核对。

生产只读核查仍为 admin 本人和独立资格：已开放字段为 `height`、`floors`、`parking`、`totalArea`、`vacantArea`、`netEffectiveRent`。建成年份、GFA、地下层数、未获权数据域不因 P2 卡片而开放。普通账号和管理员模拟身份仍不能使用 AI。

**历史元数据迁移与应用发布是两个独立状态。** 本批准备并隔离验证 `20261115173338_ai_query_own_history.sql`，没有执行生产迁移，也没有改变生产业务记录或 grant。生产未执行该迁移时，查询和正式加密审计继续工作，响应明确 `historySaved=false`；历史面板提示暂不可用，不能宣称跨会话历史已经上线。代码合并或 Vercel Ready 不代表此迁移完成。

## 2. P2-01 楼宇信息卡片

- `buildingIntent.ts` 在已有获权目录中识别明确的介绍问题；依次使用主名称、旧称和既有治理别名／项目映射。模糊残余名称不自动选楼，同名或项目多楼座返回需要确认的候选。
- `buildingCards.ts` 只接受来源中确实绑定 `buildings.id` 和名称的结果行，分组键、季度键不能当成楼宇 ID。P1 趋势／聚合结果只有具有明确的少量 `scope.buildingIds` 和来源时才提供项目入口。
- `HomeQueryBuildings.tsx` 单楼展示核心字段，多楼每组最多 5 栋、按需展开照片与指标。当前授权内的高度、来源口径楼层数、停车位和季度总面积按已有字段注册表展示；不把总面积改称 GFA，不把未区分的楼层改称地上／地下层数。
- 净有效租金、空置率及其分母沿用原快照和原 `aggregateQuarter` 公式。无效、缺失数值显示未知；季度与期间明确，不称为实时。
- 照片只选已有私有照片目录中 `ready`、具有存储路径的真实外观／内景／施工照片，效果图、未分类图片和任意外部 URL 不能作为楼宇实景。照片访问复用现有签名访问、来源署名及许可规则。
- `/api/intelligence/query/buildings` 先恢复本人原结果并复核当前全部来源，再读当前目录中的子市场、等级、位置可用性和照片引用。当前元数据及读取时间单独标识、记录加密审计；照片摘要和来源许可可追溯，签名 URL 不写入审计。不会用当前季度数字替换历史结果。

## 3. P2-02 与原地图联动

入口仅携带受控的 `aiRequest`、`aiBuilding` 和 `aiIntent`，不携带业务数字或凭据。`MapQuerySelection.tsx` 使用同一获权结果接口核对 ID；`MapClient.tsx` 把该集合交给已有地图状态、标记、筛选和 `MapController.fitToBuildings`。没有第二套地图 SDK、标记或楼宇客户端。

单楼沿用居中与详情入口；多楼按有效坐标共同调整视野。没有可靠坐标的项目不会绘点，面板分别说明缺坐标、不在当前地图目录和已定位数量。当前一次最多定位前 500 个查询项目，有更多项目时明确提示缩小范围。原筛选继续在该集合内生效；AI 项目组不无关预读未来供应。

楼宇弹窗在当前本人 AI 资格有效时提供分析入口。地图选中的最多 20 个真实 ID 可以进入介绍、历史净有效租金、同子市场或比较的受控意图；查询仍由服务端重审计划和范围。一般“租金”不自动变成净有效租金，季度不明时沿用 P1 澄清。

返回 AI 先请求本人历史中的原始快照与签名上下文；历史元数据尚未部署时，可以退回原有同会话结果恢复。两条路径都不是重新执行查询。新查询显式提交后才开始，地图进来的 ID 不通过名称模糊重找。

## 4. P2-03 成果操作

`HomeQueryResultActions.tsx` 把复制、摘要与原有 CSV／XLSX／SVG 操作收在轻量工具栏内。`resultOutput.ts` 从已保存结果生成主题、主要结论、关键数字、期间、单位、样本、趋势／异常、范围、版本与限制，不额外调用模型，不生成因果解释或预测。

复制结论／数字／摘要和文件下载一样，走 `/artifact` 并重验 `export:internal`、本人归属、当前字段／来源、最终权限。文字与文件都绑定原 `requestId`、`resultId` 和摘要；服务端不会重新查数替换内容。已载入摘要再次展开只使用当前获权界面的同一内容，账号／资格变化时清理。

关键数字最多展示 20 行，摘要最多 12 项发现和 10 组样本说明，截取处明确总数及省略数；完整明细仍可导出。超过 120,000 字符明确拒绝，不静默裁切正式内容。复制失败提供可选中文字，不谎称剪贴板成功；文件交给浏览器时只提示已发起下载。

`artifactFilename.ts` 提供对象、指标、真实期间、结果短编号组成的中文文件名，使用 RFC 5987 与 ASCII 后备值。接收端继续验证扩展名、结果 ID、文件摘要和路径字符。原有精确值、原始来源与口径工作表保留。

## 5. P2-04 本人工作历史

原审计控制台需要独立审计资格，不能直接充当普通查询者的历史页面。本批新增服务端 `/query/history`，复用原始加密审计事件和结果归档，仅增加三个私有元数据／访问记录表：

| 表 | 保存内容 |
| --- | --- |
| `private.ai_query_history_threads` | 本人会话引用、时间、加密标题、归档标记 |
| `private.ai_query_history_index` | 原始正式查询的引用、所属会话、时间、可读状态 |
| `private.ai_query_history_access` | 本人历史访问／管理的身份、会话、权限版本及结果 |

表均启用 RLS，撤销 public／anon／authenticated／service_role 直接表权限；仅服务端调用受限 RPC。RPC 再核对当前真实会话、admin 本人、独立 catalog 资格、本人所有权和权限版本。既有审计不可变结构、保留策略及原结果不改写。

列表每页最多 15 个会话，对话每页最多 10 个问题摘要，只打开一个完整结果。检索按页处理本人加密标题与最近问题，未匹配时可继续检索下一页，不进行无界全文扫描；每批最多 4 个并发元数据读取。历史标题和最近问题经过当前计划授权后才返回；原来源须重新复核才能返回数字。旧正式问题按有界批次建立引用索引，不重复保存敏感正文。重命名加密标题；归档／移回仅整理本人列表，不删除正式审计。

重新打开显示当时回答、澄清选项、真实期间、来源和版本。跨会话继续分析使用当前身份／认证会话／资格版本绑定、短有效期的签名父轮引用，不放宽原 P1 普通父轮同会话限制。凭据过期或权限变化须重新核对，不能凭历史 ID 继承越权能力。

“重新查询”与“打开历史”明确分开：前者提交新的幂等键和原查询引用，服务端重验并执行原归档 `executedPlan`，读取新的获权数据。相对时间不再二次平移，楼宇 ID、筛选、期间和指标不丢失。客户端不能同时注入另一个计划或楼宇集合。

客户端仅在 sessionStorage 保存已有不透明 request UUID；问题、回答、完整结果、标题和恢复凭据均不写入 LocalStorage。切换账号、模拟身份、会话或权限版本时销毁内存状态与在途请求。

### 迁移与回退

生产迁移须单独获得必要执行授权，并先核对原 audit／authority／context／recovery 依赖、数据库版本和备份。隔离验证采用 PostgreSQL 17，与生产主版本一致。迁移不对历史业务表批量更新，不修改 grant 或原 RLS。

应用回退可以保留新元数据表，原审计与查询不依赖它们。必须撤回新结构时，先停止历史入口和写入、按保留要求备份私有元数据及访问日志，再依次撤回 public／private RPC、元数据索引、三个新增表及其新增序列；不得删除 `ai_query_audit_streams` 或原审计事件。生产回退不是本批已执行的操作。

## 6. P2-05 状态、恢复与有界渲染

客户端增加真实请求截止时间、外部 AbortSignal 传递与资源清理。等待时仅显示已发起查询；后台返回 received／running 后准确提示仍在处理，没有假进度条。停止客户端等待不声称服务端已取消。

网络、超时、权限、条件澄清、服务不可用、没有记录及有记录但无有效数字分别处理。重试同一请求保留原幂等键、上下文和明确 ID；旧请求迟到不能覆盖新结果。确认不可恢复或超出容量后才允许新的正式查询动作。

`resultAvailability.ts` 区分空记录、未知指标和合法零值；空数据不显示空表，未知不补零。现有表格、来源页数边界保留。历史、楼宇卡片和照片按需载入，摘要和来源细节按需展开，不把地图 SDK 或完整 Excel 依赖加到普通首页首屏。

## 7. P2-06 视觉与交互

新区域继续使用既有 `--cd-color-*` 令牌、Button／Input、品牌蓝、白色工作面、灰色辅助说明和明确边框。数值与解释分层，来源可按原入口追溯；没有新装饰图、大型 AI 功能墙、光效或动画依赖。

## 9. 限制

- 当前 grant 不包含建成年份、GFA 等字段；卡片不能补造。真实照片不存在或当前许可不能访问时显示无照片。
- 现有通用楼宇详情依赖地图位置；没有可靠坐标时隐藏不能工作的详情入口，卡片的已有参数及来源仍可查看，不冒用租赁成交专用详情作为通用楼宇页。
- 当前目录的子市场／等级／坐标不是历史时点分类，不用于重写旧统计。
- 地图一次最多 500 栋，结构化比较最多 20 栋；长结果、历史与摘要明确分页或省略数量。
- 无生产新增历史迁移执行授权／记录，因此不能以应用发布冒称完整历史持久化已在线可用。
- 人工视觉、人工浏览器和真实手机验收按用户授权豁免，未冒称实际通过；自动化覆盖仍有设备和网络环境边界。
