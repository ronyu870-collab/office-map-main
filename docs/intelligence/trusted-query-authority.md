## 已实现的实际路径

`既有 Auth 验证 → session_id / 账户 / 当前角色与 grant → 加密问题持久接收 → 当前权限复查 → 完整数据库快照 → 确定性执行 → 加密结果 → 交付前复查`。

目前没有开放 HTTP 查询路由、自然语言解释器或用户结果界面。`verifyQueryIdentity` 复用现有 Auth `getUser` 和模拟身份解析；本包实际网关测试从合成 SQL 会话和服务端身份开始，**未验证真实 GoTrue 登录、注销和浏览器请求**。SQL 会话撤销回归不能代替这项必需验证。

### 权限与撤权

- `20261113023341_ai_query_authority.sql`：私有总开关默认关闭；用户资格未预置。普通管理员没有自动查数权；服务角色不能直接写授权表或给自己授权。
- 资格包含明确能力、字段、子市场、楼宇及有效期；实际与模拟身份取交集。空交集直接拒绝，不解释为不限制。授权版本来自服务端控制/授权记录版本和当前角色。
- 查询检查实际 `auth.sessions` 所有人、存在性和有效期，以及实际/有效账户删除、封禁和角色。锁定同一事务内的配置、账户、角色、会话和资格，串行化撤权；跨边界重查不靠 JWT 旧角色声明或进程缓存。
- 维护授权变更留下前后值，`session_user` 只记执行者，真实业务操作者未知，不把维护连接伪装成人。后续授权管理界面仍需验证实际操作者与独立管理权。
- 服务端只接受通过验证的身份；公开 RPC 为 invoker 壳，仅服务角色调用，私有 definer 设空 search_path。此服务角色信任边界不能移到浏览器。

### 数据快照与口径

- `20261113024629_ai_query_snapshot_read.sql`：先查最新资格/版本，再调用当前地图相同的 `map_building_visible` 记录谓词。在服务端获权目录范围内计数，禁止先计全部楼再过滤。现有主线的楼宇/指标/楼书读策略已核对使用相同谓词；未来来源 ACL 变化必须同步复验，不允许此适配器自动绕开新限制。
- 单条 SQL 的目录、指标和楼书子查询使用同一语句快照；把完整结果作为一个 JSON 返回，避免 PostgREST 行数上限截断。读取期别严格匹配，草稿排除，不以最大季度、锁定状态或入库日期推断审定/业务日期。
- 只投影请求和筛选所需数值字段；记录版本摘要不包含未获权数值。六个字段为高度、楼层、车位、总面积、空置面积、净有效租金；其余字段/数据域保留在完整计划中待接。
- 每行保留楼宇来源，数值来源保留表、字段、记录 ID、版本、原始十进制文本和更新时间；尚无原件关联的明确为 `database_only`、原件/业务日期未知。数据库 double precision 已丢失的原始精度无法恢复。
- 当前楼宇目录不冒充历史目录。楼书有效版本优先级未确定时保留所有候选，不静默选“最新入库”；不同值是冲突，相同值只是数据库一致，不确认当前现实事实。两种限制进入结果说明及导出元数据。
- 当前同步读取超过 20,000 栋明确拒绝并提示需后台任务，绝不返回截断结果宣称全量。后台物化/任务仍待实现；本包不将该错误码当后台任务已完成。

### 执行、图表与审计

- `snapshotReader.ts` 检查条数、唯一 ID、期间、字段集合、实际获权范围和来源记录。缺数据保留未知；越界、多余字段、部分结果拒绝处理。
- `executePlan.ts` 对计划、期间、同一数据版本、同一目录全集和读取参数作绑定检查；再执行目录、排名、聚合或两期比较。AND/OR 按真/假/未知求值，只有明确满足的记录参加结果，未知单列；跨期先各期筛选，再按各期/配对模式选样本。
- 筛选证据保留逐楼状态和条件字段来源，即使条件字段没有展示为表列也可追溯。比较结果同一版本包含两期来源、样本、分母、数值差和变化；空置率变化的单位为百分点。
- `auditStore.ts` 通过真实 Supabase RPC 存储加密问题/计划/授权快照及生成结果，先成功接收再执行；持久接收幂等可跨适配器实例。浏览器取消不取消独立审计写入，写入有有限超时。
- 大结果按 UTF-8 字节分块加密，并写最终清单/长度/摘要，不截断来源。隔离测试实际解密并拼回原结构。尚无用户端恢复接口、审计台读取重组、独立检查点存储或崩溃对账，不能据此宣称审计全生命周期完成。
- `response_generated` 和 `succeeded(delivery=not_yet_sent)` 不表示用户已经看到。当前没有 HTTP/流式交付回执，真实展示审计仍待接。
