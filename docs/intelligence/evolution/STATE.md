## 已确认并修复

本轮从经纪人连续收窄项目清单出发，发现“保存正式快照”并不保证后续任务保留用户选择：

- 同字段下限、上限被当成同一个条件；第二轮覆盖第一轮。现在仅替换同字段同方向条件，保留另一端边界及其他字段，矛盾条件得到空结果。
- `HomeQueryDataTable` 移除一个条件会删除该字段所有条件，且 React key 重复。现在可分别移除上下界，标签带字段、方向与单位。
- “把刚才的结果导出Excel/CSV”复用了完整快照，却丢失已归档筛选与排序。确定性续问现在显式将其传给既有正式导出工具；导出所有匹配行，页码不截断文件。原快照、来源及当前鉴权保持原契约。
- 表格和模型分页工具使用浮点近似值筛选，导出使用精确值，边界可能出现不同名单。两处改用已有 `Decimal`，数字相等不再依赖格式化文字；拒绝空串、十六进制等非十进制数值条件。
- 续接复现：表格只剩 A 座时，图表仍含 A/B/C/D 四栋、地图仍选四栋、模型分页仍返回完整四行。统一通过临时行投影读取当前视图，忽略界面页码但保留筛选与排序；图表/SVG/PNG、卡片/地图、模型分页及正式导出使用同一行范围，原始行和来源不被修改。
- 同轮工具先 `apply_result_view` 后读取时，原只读工作集仍提供旧视图。新增仅在本请求内存在、独立于封存原件的已验证视图；保留全部身份与来源检查。旧地图选择先对完整原件验证，再与当前视图取交集；空视图不恢复原计划范围，外来楼宇仍拒绝。

旧实现在新增表格/HTTP回归中7项失败，模型分页独立回归1项失败。测试使用合成夹具、独立预期名单和真实Excel回读，纳入既有Vitest；实际登录、加密恢复、下载、跨账号和撤权场景纳入 `scripts/verification/ai6-runtime-scenarios.mjs`，由现有真实Auth CI调用。

首轮代码（`a3cdf934`）本地 `npm run verify` 通过：审计覆盖、类型、Lint（0错误、974条警告）、408个测试文件/3,137项Vitest及生产构建；`npm run test:ai-eval` 离线AI独立验收通过。PostgreSQL 17.6、真实GoTrue登录、Data API和构建后Next HTTP的243个场景通过，包括新增连续筛选与实际Excel回读。专用隔离栈已停止并清理。

续接修复前新增三项回归均失败；修复后通过，并增加同轮工具执行、视图隔离、空结果/外来楼宇拒绝及分布统计拒绝混用的回归。真实Auth CI扩展同一连续筛选场景，检查楼宇HTTP名单、实际SVG内容、跨账号读取与撤权下载。续接提交的最终全量工程/HTTP结果以 PR #308 对应精确 head 的CI为准；在检查结束前不声称通过。模型供应商使用合成传输，不冒充真实模型能力评测。
