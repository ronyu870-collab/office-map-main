# Colliers AI 5.0 租赁成交研究

## 工具与数据契约

`query_lease_transactions` 是独立注册的成交工具，不调用季度租金引擎。只接受经过严格验证的来源、日期起止、研究模式、分组、精确行业／行业组合、楼宇规范名／原别名／已获权 UUID、子市场、排序和 Top N；不能接受 SQL、表名、数据单元格、文件地址或来源记录。租赁问题传入 Agent 旧季度自由文本工具时会引导回独立工具。

- `source=live|history|combined` 明确物理表来源；live 表也可能保存较早成交，不等于“近期”。
- `mode=aggregate` 提供记录数、成交面积合计和有效面积样本数；可按季度、楼宇、行业或子市场分组，按面积／笔数／期间排序并保留末位并列。面积使用既有精确 Decimal，成交面积不等于净吸纳量。
- `mode=details` 需要独立明细资格，默认交付楼宇、子市场、行业、期间、精度、匹配状态、来源和面积；财务列还需独立财务资格。公司、租户、经纪人、提交人、备注和导入原始材料本阶段始终不开放。
- 复用 `create_chart`／`modify_chart`／`export_chart` 和现有坐标引擎，可交付成交面积／笔数趋势、行业分布、楼宇排名与 PNG/SVG 来源包。面积与笔数不同单位分别制图。
- 复用 `export_table`、原结果菜单、加密归档、可信下载和审计，生成完整获权 XLSX 或 CSV ZIP，可选择字段／筛选／排序。多个同结构成交结果可纵向并列并保留各自期间与版本，不跨结果重新去重／相加。需要两表联合去重时先查询 `source=combined`，不能靠导出相加。成交与季度结果不能混成一张同口径表；本阶段成交结果不接入 PDF 组合。

日期区间含首尾，只纳入整个已知成交期间均落入区间的记录。未知期间和跨筛选边界的低精度记录明确排除并计数。年份精度可参加完整年度总计，不能分配到季度；季度分组另列排除数量，时间轴只为可靠季度绘制数值，范围内缺期或未达披露阈值的期间保留未知点，不作零点或跨缺期插值连线。缺失面积不当零，面积合计只含有效面积，同时报告有效分母。

行业仅精确匹配已存分类。`industries` 支持用户明确指定的组合，不与单个 `industry` 混用。依据既有[历史行业治理](../verification/history-industry-backfill/README.md)，TMT 不自动归为某个科技、媒体或通信类别；单个 TMT 条件先澄清是仅按原始标签（明确 `industries=["TMT"]`）还是按指定行业组合，不能据此宣称整个 TMT 行业有无成交。可先查询获权行业分组，再确认组合范围；不改写原行业字段。

完整获权数据池上限 20,000 条，不受界面／模型预览分页影响；超过时明确拒绝，不返回前 20,000 条，也不暗称后台任务。大数据池目前需授权维护者收窄正式研究范围，单纯缩短查询日期不会绕过此上限。沿用 8 个工作集结果／合计 50,000 行、导出／归档／图表原有容量限制。

## 两表边界、去重与楼宇身份

生产仅只读核查列元数据，没有读取客户业务行。当前表按 UUID 标识；历史表还含导入 `source_uid`、质量、期间来源、物业费、导入时间及原始材料。工具使用 `(record_source, source_record_id)` 防止相同 UUID 跨表混淆；`updated_at`、历史 `imported_at`、治理映射和完整读层版本进入服务端记录指纹，结果生成时间独立保留。

复用既有 `lease_transactions_read_v1`：历史记录级 `lease_building_record_map` 优先，其后 `lease_building_name_map`，项目使用 `lease_building_project_map`。规范名与原别名精确匹配，不模糊猜楼。exact／reference／project／unmapped 状态保留；project 只作为项目统计一次，不能把整笔面积复制到每个成员楼座。单楼授权只接受可靠 exact/reference 映射，不能凭项目成员关系扩权。未匹配记录仅在同时获权全部相关楼宇和子市场的范围内保留不确定状态。

去重采用私有 `ai_lease_verified_duplicates` 一对一身份关联账本，必须记录独立核验依据、变更引用和双方完整读层指纹。只有关联存在且两个版本仍一致，combined 才在业务／期间筛选之前优先保留当前记录；指纹或映射变化时关联失效，保留两条并提示核验。没有公司名称／面积相似自动去重，也不把公司实体相同等同于同笔交易。

置信度边界为“有效身份核验关联”“版本已失效”“无核验关联”；后两者不自动合并。记录数仅表示上述规则下的获权记录数，未经核验的两表重叠仍可能存在，不声称已完成全部真实交易去重。首次部署不插入任何关联或生产授权。

## 租金口径

当前／历史面价、有效租金分别使用独立列，绝不把历史 `effective_rent` 直接命名为净有效租金。物业费只有历史读层有值；租期、装修期、免租期保留原始月数。没有可靠普通租金或净有效租金定义时不补推；两表不跨口径计算平均租金，不根据字段名字猜公式、扣减费用或推算优惠。当前治理读层不能完整证明租金单位及估算状态，因此租金／物业费明确标作原始单位待核验；数值是原始录入值，不是已审定净有效指标。不同来源不适用的列保留未知，零值与缺失区分。

## 正式授权与模型边界

沿用 admin 本人、有效 Auth 会话、AI 总开关及 `query:catalog` 资格，拒绝模拟身份。另需数据库维护者在**单独授权**后维护私有 `ai_lease_research_grants`，指定有效期、来源、子市场、楼宇及明细／财务／导出等级；范围与现有 AI 范围取交集。没有默认资格，不改变原 viewer/editor 的 live 成交业务读路径或既有 RLS。财务资格要求明细资格，文件还需原 `export:internal` 和新的成交导出资格。

聚合专用资格默认至少 3 条的分组才交付；面积有效样本不足同一阈值时面积值不交付。模型侧无论用户是否拥有明细资格，仍只接收达到上述阈值的聚合项，单记录分组不会变成明细旁路；小组抑制明确计数，不能通过明细工具绕过。这是披露限制，不是差分隐私保证，研究授权仍应由资料责任人限定适当范围。

RPC 固定投影始终不读取客户身份到应用结果；租金仅在财务资格存在时投影。模型只收到获批聚合单元格或明细的列／行数／限制。明细原值不进入外部模型，`read_result_page`、比较、来源、摘要和图表工具均执行这一边界，图表点不能成为明细旁路。获权脱敏明细仅交付当前用户的正式表格与文件。

来源使用不含原始客户值和业务记录 ID 的快照级证据，包含受控计划、权限版本和完整授权投影哈希；原始文件路径、备注、租户名不进入 manifest。每次模型／工具边界、交付前、历史恢复和下载重新读取身份、独立资格及完整快照，版本、源记录、映射或核验关联变化均拒绝旧档案，需重新合法查询。文字续轮和混合任务保留成交权限依赖，不能利用普通历史文本绕过撤权。

私有资格与核验关联启用 RLS、无客户端或 service_role 表权限；service_role 只能执行有身份检查的固定 RPC，不能自行给用户授权。维护使用原 `ai_query_policy_change` 审计前后值、修订版本、执行账号及变更依据，不把数据库执行者冒充已验证的人类审批人。暴露函数为 service-only invoker，实际 definer 在私有 schema 并固定空 search_path。

服务器生成、浏览器发起下载、实际保存继续分开记载。不会自动下载、公开敏感文件或声称磁盘保存成功；对客发布仍须单独权限。

- `ai5-lease-scenarios.mjs` 接入原必需真实 Auth/HTTP CI，使用真实 GoTrue、会话、PostgREST、加密归档、生产 Next artifact 路由与真实文件回读。模型规划为可重复脚本，验证提供者实际收到的消息不含成交明细；不作为线上 DeepSeek 理解准确率证明。涵盖跨用户、字段拒绝、历史续轮、生成前后撤权、源与映射变更，原 Excel／图表／PDF 回归继续运行。
