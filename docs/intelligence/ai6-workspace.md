# Colliers AI 6.0：结构化回答与研究工作空间

2026-11-22。沿用现有 Agent、查询、同源图表、个人历史和服务端授权；无数据库迁移、无业务数据写入、无新增依赖。开发分支 `codex/colliers-ai-6-workspace-redesign`，基于最新 main `46e8578` 开始集成。

## 实际实现

| 范围 | 实现与责任入口 |
| --- | --- |
| 工作空间 | 保留首页紧凑输入、专注和全屏的同一实例；文字阅读宽度 50rem，数据区最高 76rem；14px 正文和 16px 标题、两种常规字重。输入草稿下沉 `HomeQueryComposer`，逐键输入不更新消息树。 |
| 回答协议 | `responsePresentation.ts` 将已验证结果适配为 `response/1` 类型块，正式数据只引用原 resultId。`HomeQueryResponse` 统一当前和历史入口，`HomeQueryResponseBlocks` 注册复用渲染器；摘要、指标、来源共享结果容器及焦点控制。 |
| 文本与状态 | `response-presentation/1` 区分分析、结果摘要及交付状态；旧文件消息依据有效附件描述适配，未知版本保留正文和原生表格。无关键词正则删文；部分完成和受限执行的警告保留。 |
| 楼宇及表格 | 多楼宇以一张表代替逐栋卡片；单楼宇沿用原信息卡。表头固定、精确数值排序、未知值始终最后、延迟本地搜索、真实返回分类筛选、列显隐、跨页多选、每页 25 行、局部横纵滚动及楼宇详情／地图链接。 |
| 文件 | 有正式描述才展示附件；文件名、类型、业务说明和单一下载按钮成组。准备、已发起下载、失败和重试均由组件处理，不把浏览器派发写成本地保存成功。Excel/CSV/PDF/Word/PPT 原有服务端产物路径继续复用。PNG/SVG 沿用图表附件路径。 |
| 范围导出 | 全部结果、当前筛选、已选记录均通过原 artifact HTTP 重新鉴权、恢复完整快照，再以索引选择原行。拒绝重复、越界、空选择及不兼容格式。范围导出不接收客户端数值或额外字段，不重新计算统计。 |
| 文件品质 | Excel 保留真实数值、百分比格式及来源和口径页，增加冻结首行和统一表头。复用 JSZip 修改两个 OOXML 部件；CSV/TSV 保护公式注入。新增完整表格 TSV 复制，超过大小边界明确拒绝。 |
| 来源及限制 | 来源、完整方法和版本默认折叠，保留单元格溯源及关闭后返回触发点。有效样本缺口、未知值、历史来源、当前目录分类与研究资源限制按结构化数据保持默认可见；部分执行警告不折叠。 |
| Markdown 与图表 | 沿用已支持 GFM、断点流式正文、安全链接和清洗的 Markdown；统一两档排版，修正目录拼接句号与等级表达。保留同源图表、改图、逐点来源和真实 PNG/PDF，未另建图表引擎。 |
| 性能与权限 | 不增加模型调用或逐行查询；每张表一份菜单监听器。文件字节缓存限 60 秒、8 项、合计 16 MiB，合并在途相同生成；缓存不包含授权决策，每次 HTTP 仍执行原拥有者、独立导出资格及来源 ACL 检查，并在交付前复核。 |

## 验证与复现

缺陷回归 `home-query-export.test.tsx` 的 restored exported list 用例，在原 main 的 `HomeQueryResult` 上因缺少结果搜索表格失败；恢复本次实现后通过。不是仅验证新增组件存在。已生成文件的摘要值一致性回归曾捕获“生成后添加呈现元数据”的问题，已改为保持成果快照不变。

新增／扩展回归已进入既有全量 Vitest 和搜索焦点门槛，涵盖：

1. 普通知识回答中的“服务器／生成”文本保留。
2. 结构化交付状态及未知版本安全降级。
3. 旧导出历史转为一个附件和一张交互表。
4. 已返回数据持续搜索、中间编辑、空结果和组合输入焦点。
5. 精确数值排序、未知末置及列显隐。
6. 跨筛选多选，原快照不变。
7. 选中及筛选 Excel/CSV 实际回读、来源和注入保护。
8. HTTP 拒绝无导出资格、伪造越界索引，以及暖缓存后的撤权。
9. 复制完整表格，超过 25 行仍完整，保留单位和注入保护。
10. 真实附件按钮、失败重试和浏览器派发语义。
11. 重要限制可见、详细来源默认折叠及焦点返回。
12. 短指标、趋势、图表失败后的数据与操作可用。
13. 历史恢复、身份隔离、工作空间切换和任务状态保持。
14. Markdown、安全内容及模型文件声明与真实产物校验。
15. 已构建页面的桌面／手机宽度、单一编辑器、连续输入、图表和历史；扩展 32 行表格的分页、搜索、排序、多选保持，以及交互期间零新增查询。

本地完整 `npm run verify` 已通过（354 个测试文件、2,618 个测试，类型检查、Lint 和生产构建）；最后文件格式与选择范围调整另经相关回归复核。Lint 为零错误，仓库现有警告仍保留。搜索焦点契约与受影响入口回归通过。工程执行记录以 PR 精确 head 的必需 CI 为合并依据；GitHub 状态在 PR 单独记录。页面回归使用真实生产构建与合成 HTTP，不等同真实生产数据或物理手机测试。未声称生产响应耗时的量化改善。

## 明确边界

- 每次筛选／选中范围导出最多 3,000 条，避免超过现有 HTTP 请求大小；“全部结果”沿用原正式结果边界，不受当前页限制。界面明确说明搜索和筛选仅作用于本次已返回记录。
- 缺失字段不补查、不虚构；有返回字段才提供对应筛选。结果与历史仍为保存快照，不代表实时数据。
- 文件过期、撤权或网络失败均允许重试，当前客户端采用统一失败文案；不推断本机保存状态。服务端仍给出真实拒绝结果。
- 不新增生产开关、模型权限、地图数据范围或 Stacking Plan 资格；真实生产登录与数据可用性沿用已有部署配置。
- 合并、预览部署及生产发布各自核验；文档中的本地测试不证明已经发布。
