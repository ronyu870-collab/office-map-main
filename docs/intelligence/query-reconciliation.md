# 执行中断补记与接收对账：本地检查点

基线1f3e593之后；仅本地/隔离实现。推进A07/A10、G05/G08/G10、AUTH07/AUTH10和R10/R14/R17，原99项及T01–T60全部保留。没有生产迁移、计划任务、AI启用或新账号授权。

## 解决的实际路径

此前请求已持久接收后，如果Next进程在正式终态之前被杀死，审计可能永久留在received/running。现在由原审计事务登记持久执行观察记录；独立进程可以在没有用户重复提交、没有重跑业务查询的情况下，补记中断的请求流程。

`private.ai_query_execution_watch`随审计stream插入/更新的触发器同步：请求、观察记录及首条事件同事务；每次后续事件更新观察序号/哈希和数据库时钟，终态同步settled。迁移为原有未结请求补记录并给完整宽限，不改历史问题、身份或发生时间。

现有HTTP处理器的执行上限为30秒，观察记录采用180秒无进度宽限；这个时间只触发检查，**不证明业务失败、模型未收费或用户没收到**。独立命令按批认领，每批最多100项、默认20项，每项租约60秒。数据库按stream→watch的统一锁顺序、SKIP LOCKED分配；新进度清除旧租约，过期替代进程获得新令牌。

补记时再次锁定原stream和watch，检查租约/执行者、数据库到期时间、原序号/哈希、完整事件链，以及stream状态与最后状态事件一致。正常请求已完成、新进度、旧工作进程迟到时只返回stale，不覆盖。链损坏或状态伪造返回integrity_unavailable，留待独立调查，不能通过补记把损坏历史变成可信。

终态事件与观察记录关闭、补记凭据写入同一数据库事务。任何后一步失败全部回滚；丢回包后用相同租约派生的eventId/内容摘要重试，只得到原凭据。已补记的迟到业务成功写入被原审计状态机拒绝；新结果不交付。

## 终态含义与执行者

原流程state使用现有failed终态表示本次流程没有可交付的确认结果；加密补记内容明确：

- executionOutcome=unknown，delivery=unconfirmed。
- providerCost=unknown_not_zero，不能由此给费用账本记0。
- executor为system_reconciler与具体workerRef/租约令牌，原actor/effective身份保留，不能伪装成用户自己结束请求。
- replayBusinessOperation=false，不重新读业务数据、调用模型、导出或写业务事实。

当前已接通能力是只读查询及受控结果动作。未来正式业务写入、付费调用与多步骤任务必须有各自的事务/outbox、幂等和费用对账；本补记机制不能证明它们没发生，也不能自动重试。

## 对账与访问边界

`ai_query_reconcile_overview(since)`按至多31天范围分别返回入口尝试数、获认证尝试数、不同requestId数、终态/未结/到期数、缺观察记录数和最多100项孤立入口样本。重复尝试与不同请求不能混算。正式审计权限仍独立；这些工具只给可信服务进程，无浏览器路由或普通/admin JWT调用权。私有表RLS开启且服务角色无直接表读写权，特权实现留在private，public仅security invoker外壳。

入口与问答是两个账本，所以可以发现“入口已接收，但尚无问题流”的间隙。它们仍在同一数据库，不是受独立权限保护的外部计数或防篡改锚点；HTTP字节尚未持久化之前的崩溃无法靠这两个表证明已完整接收。当前入口与完整问题持久化之间仍可能存在缺口，孤立记录不能恢复未存下的正文，必须明确告警，不能猜写。这部分仍是A07的未完成项。

补记凭据是追加历史；普通账号不能认领、关闭、删除或读队列。服务进程的调度、秘密供应与监控尚未生产部署，默认不会自动运行。

## 可运行入口与验证

`node scripts/intelligence/reconcile-query-audit.mjs`是隔离环境的一次性命令，要求显式配置AI_QUERY_RECONCILE_ALLOW_LOCAL=disposable、仅本机的AI_QUERY_RECONCILE_URL、单独提供AI_QUERY_RECONCILE_SECRET与既有审计keyId/两个密钥；可指定AI_QUERY_RECONCILE_WORKER。不读取环境中的生产URL作为默认值，不输出问题/答案/密钥，临时编译文件退出清理。生产调度及专用凭据属于后续发布材料，不把此命令当已部署服务。

已执行两类不同证据：

- PostgreSQL17.11独立合成库11组：升级、事务登记失败回滚、真实worker、未知结果、正常进度/成功竞争、认领进程真实SIGKILL、租约替代与幂等、4并发进程/锁跳过、终态凭据失败回滚、链/状态/已结重放篡改、孤立入口及权限拒绝。测试对时间边界仅在合成库调整到期时间，没有修改生产时钟或放宽业务函数。
- GoTrue/PostgreSQL17.6/PostgREST/Next真实HTTP42组：新增正式问题落库→数据库锁阻止后续授权→Next真实SIGKILL→独立CLI补记→Next重启→恢复返回failed且无结果→同幂等请求202、不重跑→新请求正常。原问题与真实账号上下文保留，原41组同时运行。

原有13组审计身份、幂等、8写入者并发和防篡改回归也已在新触发器生效后全部通过。

前者已接现有Verify的PostgreSQL工作流，后者沿用既有真实Auth工作流。原始输出、源码摘要与最终全量结果见本包evidence；本包没有视觉/浏览器交互变更或样式变更，HTTP恢复行为有实际回归，不把构建成功当故障路径验收。

## 尚未完成与运维边界
