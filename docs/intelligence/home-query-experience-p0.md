## 范围与显示规则

主页使用克制的留白、清晰角色与结论优先的研究结果层次，保留 Colliers 品牌令牌，不引入外部品牌资产、字体或动画依赖。首次进入/新对话展示当前会话姓名及职责，缺少可靠姓名使用“你好”。名字只用于本地显示，不发送给语义模型或用于授权判断；账号变化继续卸载旧工作区。

获权示例移至主输入框后方，最多四个；其他能力说明按需展开。用户气泡在右，助手正文在左，资料来源为次级层次。短历史回答直接展示；大型旧结果保留摘要，按需挂载原组件。原始资料、未知值、样本、口径、导出权限均保留。

输入框不因响应重挂载。发送同步清空本次草稿，返回不会清掉后续输入；失败可重试原请求或编辑已发送问题。中文输入法确认不发送。空会话仍可恢复仅保存在 sessionStorage 的不透明请求引用。新消息/结果使用 180ms 淡入及 4px 位移；等待点仅表示请求处理中，不表示虚构研究步骤。reduced motion 下关闭动效。

## 非事实交流的边界

`assistantHelp.ts` 只识别完整短句问候、身份/能力介绍及致谢。混合业务问题、未知指令不被吞掉，继续原语义处理。原入口先验证身份、角色、独立资格、当前权限及原父轮；纯帮助不读取楼宇/季度快照、可用期别，不调用模型，不生成或导出数字。

为兼容现有加密说明/恢复链，响应保留 `status: clarification`，使用共享 `reason: assistant_help` 与 HTTP 200；UI 将其显示为普通助手回答。原业务澄清保持 HTTP 422。审计沿用原 denied 说明事件（未执行事实查询），不改 SQL 状态机、不把它当作用户权限拒绝。幂等重放与本人历史从加密 response 恢复帮助文案；业务 pending 保持不变。跨会话历史继续遵循原来的重新授权限制，不扩大权限。
