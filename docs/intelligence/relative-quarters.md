# 相对季度、同比环比与明确滚动期间

本地工作包，AI仅当前admin本人可用，独立查询、字段、来源、导出及审计资格保持。无生产迁移或启用、真实资料出站或模型调用。

## 可查询的表达与时间口径

以应用接收本次请求时的服务器时钟为基准，固定`Asia/Shanghai`，不使用浏览器时区、请求Date标头、客户端日期或数据库里最新有值的季度。每次请求只捕获一次时钟，避免跨季执行中改变期间。完整语法版本`bounded-business-question/8`；相对日期展开之后仍校验整个问题，任何未消耗条件均澄清。

- 本季度/这季度/当前季度：接收时北京时间所在的日历季度。
- 上季度/上一季度/上个季度：上一日历季度，跨年正确转到上年Q4。
- 去年同期：当前日历季度往前4季；今年/去年Q1–Q4或第几季度按对应年份解析。
- 明确目标季度的同比、环比：分别往前4季/1季；必须选择各期样本或配对样本，指标计算仍使用原季度引擎。
- 最近2–40个已结束季度：截至上季度的连续期间，不代表填报或审定完成。
- 最近2–40个季度（含本季度）：截至当前季度；趋势仍需各期样本/全期间共同样本，按子市场或等级分组沿用既有语法。

例：2026年11月北京时间提交“上季度CBD净有效租金”，解析为2026Q3；“上季度CBD空置率同比配对样本”比较2025Q3与2026Q3；“CBD净有效租金最近4个已结束季度趋势各期样本”包含2025Q4至2026Q3。“去年同期”单独以当前季度为基准，若想比较上季度与去年相同季度，应使用明确目标的同比语法。

“最新季度”“最新已审定季度”“今年”而没有季度，以及未说明含本季与否的“最近4个季度”仍澄清；不猜测业务发布状态、财年或不完整年度汇总。数据库某期无值就保持未知，不退回上次有数据的季度。本季、未来明确季度亦不因没有数据自动改条件。1900–2200边界、反向/超长区间按原契约拒绝或澄清。

## 结果、审计和跨季重试

已解析的绝对计划与`questionTimeResolution`进入首次加密接收审计；包括策略版本、时区、应用开始接收请求的UTC时刻、锚定季度与完整展开问题；此时刻与数据库审计落库时刻分别保留，跨季期间慢请求不会混淆。原始问题、输入内容、实际操作者、入口及每次尝试记录不变。结果在首次生成审计前附加相同`parameters.timeResolution`和可见限制，保留原不可变result_id、数据/来源及原数值。页面明确显示绝对季度，CSV/SVG manifest与Excel口径快照保留同一上下文。

相对问题的幂等身份绑定完整原始请求、原问题及语法版本，不绑定随时钟移动的派生季度；首次明确计划仍完整加密保存。相同请求号跨季重试只检查当前权限并返回已接收，不再次执行或覆盖第一份结果；恢复读取首次计划/结果。修改问题、请求内容或语法版本不能被当作同一提交。每次HTTP尝试仍进入独立入口审计；不采集未提交草稿。结构化显式计划保留原有内容冲突判定。

反向回归先复现重复请求在字段资格撤销后仍返回already_received的旧行为；它未返回数据，但准入状态不够严格。现在重复请求在报已接收前也按当前工具/字段资格检查，撤权直接denied；原结果恢复还会重新检查原始计划、范围和来源。

这不是缓存授权：admin降级/注销、字段/区域或来源撤回仍按现行链重新核验。新问题应使用新的请求号，才能按新的当前日期解析。客户端不能提交解析上下文/时钟以伪造本季度。语法版本改变仍沿用既有内容冲突保护，不把新解析器当作旧请求续算；原结果通过恢复入口读取。

本包无数据库迁移。未来获准发布/回退时保留admin与审计保护；退回前一应用版本会停止解析新增相对语法，不能静默改查其他期间。既有绝对计划与来源快照仍是恢复依据。
