## 页面与运行边界

沿用已上线主页的连续工作面：查询输入 → 原位答案、表格与来源 → 原业务入口 → 团队动态。无大幅 AI 图片、深色横幅或卡片墙。色彩复用现有令牌：工作区 #f5f7fa、工作面 #ffffff、柔和分区 #f8fafc、主文字 #172033、次级文字 #667085、操作强调 #003e7e；边框也沿用原令牌。一套系统字体，标题 20px/正文 14px，常规字重 400/500；结果不额外增加数字字号。文字与表格共享左边界，数字右对齐。来源按单元格或全部候选展开，相关信息连续排列。

`HomeQuery` 从现有 Auth/session 与模拟身份上下文取得会话，只向同源服务端查询能力；前端角色不授予查询权。默认环境或独立数据库资格未开启时不接收问题。主输入不随加载、结果或错误重建，查询期间可继续编辑；中文组词不触发快捷提交。新账号、会话或模拟身份切换会卸载旧会话的结果和待处理请求。前端资格刷新是界面收起措施，真正数据准入及结果恢复仍由服务端逐次检查。

正式提交才记录问题，不采集草稿；页面明确说明问题及回答留存供获权审计人查看。未调用任何外部模型。原有地图、季度、成交、资料、企业报告及管理员业务智能入口及角色规则保留。

- 同一不可变结果的表格（25 条展示分页）、逐格来源、全部候选来源（10 条展示分页）、数据版本与原始资料关联状态。分页不改变完整统计范围。

## HTTP / 审计约定

- `GET /api/intelligence/query/capabilities`：真实 Auth 身份及当前数据库资格；仅返回本人可用示例与资格版本，不读取楼宇或披露受限记录数量；私有 no-store。
- `POST /api/intelligence/query`：兼容原显式 plan；省略 plan 时受控解析。显式 null/非法 plan 不回退到自由解析。保留完整正式提问和原有幂等规则。
- 澄清 HTTP 422，`status=clarification`。审计终态仍为 denied，但原因明确为 `clarification_required`，表示条件不成立、尚未准许执行查询，不能混同权限拒绝。保存具体澄清答复与响应准备记录；同键重试重查当前资格，不新增查询执行或重复终态。它不是事实结果，不走成功快照恢复。
- 提交与恢复采用 HTTP Host 与请求协议校验浏览器 Origin，忽略 X-Forwarded-Host。Next 内部监听名可能是 localhost，与浏览器真实 Host 不同，不能用内部 URL 误拒合法请求。缺 Origin 的 API 调用仍必须通过独立 Bearer 身份、资格、审计和范围检查。
- 接口拒绝、服务故障、无有效数据、尚未完成与澄清分别呈现。停止等待只终止浏览器等待，明确服务端可能继续；不虚称已取消。网络丢响应重试原问题和原幂等键，即使草稿已改，也不把新草稿冒充原请求。
- 服务器仅记录生成及准备响应；还没有客户端实际接收/呈现回执，不称用户已见或已读。审计台、会话关系、崩溃/outbox 对账、独立检查点、轮换/保留与后台治理继续待完成。
