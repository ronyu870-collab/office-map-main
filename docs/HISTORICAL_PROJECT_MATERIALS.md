# 历史项目资料与佣金

地图楼宇卡片通过“项目资料与佣金”打开已收录的原件、楼宇参数和历史政策。该入口只读，使用既有登录、角色与楼宇范围校验。原件存储在私有 bucket，服务端签发 5 分钟链接；浏览器不能直接写表或访问原件路径。

## 历史资料契约

- schema_version=2 的 historical_context 必须保留 period_label、evidence、not_current=true，且 extraction.historical_import_authorized=true。未知日期留空；文件名或目录年份仅作为带说明的历史来源线索，不能当作业主确认、数据截至或有效期。
- 历史资料只允许项目参数和佣金，details 必须为空，不能进入当前房源、季度指标、分配或填报。
- 历史同系列的所有版本均可见，上传新版本不隐藏旧政策。佣金有效期和计算条件按原页记录；没有年份或有效期时明确未知，不推断当前有效。
- 只有楼宇身份和适用范围确认的记录可发布。多楼座或未知归属先留在本地证据清单，不能为了数量复制到所有楼座。
- 原件保留原始字节及 SHA-256；PDF、图片、XLSX、PPTX、PPTM 均支持归档。PowerPoint 可下载，系统不执行宏；内容只展示已核对的结构化数据。最大单件512MiB，生产上传还受目标项目实际存储限额约束。

## 操作

先核对并生成符合 model.ts 的 manifest，通过 ingest.mjs --manifest 文件.json --file 原件 --target supabase 预检；显式 --apply 才写入。服务端配置沿用现有环境，不将密钥写入参数或 manifest。

原件经上传后重新下载哈希一致才将记录由 pending 发布为 ready；中断保留 pending，重跑按原件和解析哈希恢复。发布后回读楼宇、原件、政策和来源，再验证地图展示。楼书字段补空独立写入已有字段来源表，不使用历史房源覆盖当前指标。

本专项中的历史导入用于用户明确授权按历史资料收录的批次；现行业主销控仍执行 DATA-01 原有日期确认流程。

## 仅导入结构化历史数据

本地原件已经归档且核对哈希时，可使用 `--original-mode local_archive`。仍需传入归档原件供校验，但不上传Storage。数据库保留原文件名、MIME、大小、原件与解析SHA-256及逐项来源页码，`storage_path=NULL`，`archive_reference=sha256:<原件哈希>`。此模式仅限已授权的历史参数与佣金，不允许当前房源。原件本地归档不作为阻断已核对数据入库的条件；没有在线原件时API返回空链接，界面隐藏原件按钮，来源与政策备注仍可展开查看。
