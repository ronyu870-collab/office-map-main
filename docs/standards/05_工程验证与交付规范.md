# 高力国际工程验证与交付规范

版本：V2.3｜日期：2026-11-02｜本文件负责验证与交付；仓库命令、分支、CI 与合并门槛只在 [仓库 AGENTS](../../AGENTS.md) 维护。

## 1. 开始工作与范围控制

- 明确本轮交付是规范、审查、方案、实现、验证还是发布；明确授权任务中的必要实现与验证持续完成，不把下一阶段视为自动授权。
- 核对当前路径、Git 分支、版本、实际入口及未提交工作，保留既有修改；优先复用合适工作区，需要隔离时再建立。
- 规则正文在本仓库内，独立检出使用同版本文档。跨媒介材料与当前排期按对应任务加载，不要求恢复本机父目录才能开发网页。
- 缺失关键业务答案或环境时只暂停依赖部分；已经明确的事实、技术默认值与授权不重复确认。

## 2. 实现与迁移

- 共用参数在 `src/styles/tokens.css`，全局入口在 `src/app/globals.css`，基础 UI 在 `src/components/ui/`；数字、角色与行为按 01／02，依赖与状态按 07。
- 新参数按语义映射共同来源，再接入真实使用处；组件缺失变体如实标为待实现。不得靠文档引用宣称代码已经具备能力。
- 普通 CSS 限定组件或模块作用域；后台主题不输出全局滚动条覆盖。SDK 必需覆盖采用命名适配，不把 DOM 层级、旧内联 style 字符串或连续 `!important` 作为长期接口。
- 公共能力与代表业务一起完成，按实际接口依赖分批迁移，遵守 ARCH-05。兼容记录调用方、原因、撤除条件和回退方式；不把“整项基础任务必须全部完成”当作无关能力的前置。
- 手机布局与交互适配保持业务含义、权限及持久状态；适配要改变后端或业务规则时明确单列范围。

## 3. 按风险验证

### VERIFY-01

| 改动类型 | 最低验证与完成边界 |
| --- | --- |
| 纯规范／说明 | 责任入口、引用／锚点、规则冲突、旧条款保留、版本状态及源码未变；不运行应用测试 |
| 单个视觉页面 | 最终真实渲染、相关正常／边界状态、适用角色、桌面与手机操作；有代码则同时执行仓库门槛 |
| 共用令牌／组件／适配 | 受影响的代表表单、表格、地图／详情、后台和手机组合；枚举已迁移调用方和未覆盖范围 |
| 实质代码或样式 | 运行现有适用回归及仓库验证；根据新增行为、修复问题和实际风险补必要测试，不强制为每个样式参数新增测试 |
| 数据／身份／权限／数据库 | 隔离环境核对允许与拒绝的访问、归属、并发／失败和回读；数据库实际执行按 VERIFY-03，显示正确不能代替数据边界正确 |
| 生成报告／展示／导出 | 检查最终产物全部页面、内容、数据及可编辑要求；网页预览和控制仍按手机能力验收 |

要求按实际变更叠加。纯文档不启动业务测试；公共组件只覆盖实际影响的组合，不为无关能力扩测。修复失败或新改动产生风险时再扩大验证范围。

- 网页布局检查使用 1280px 桌面、390px 手机视口；长文字和资料卡补查 320px，涉及的断点在两侧检查。用户放大后关键内容和动作仍可达。固定画布产物用自己的媒介规范，不套网页画布。
- 正常、空白／零、禁用／只读、错误、进行中、失败等仅按组件适用能力检查。关键操作不能只测试成功静态状态。
- 同一业务对照使用隔离且等价的数据、角色和期间，区分布局变化与业务输出变化。禁止用真实删除、真实密码修改、对外消息或未授权生产写入充当测试。
- 每批界面变更提供相同页面、视口、角色、数据和状态的前后对照，说明原问题、保留细节及变化；公共改动核对受影响调用方。缺少前画面或浏览器时明确缺证，不能宣称视觉验收完成。
- 自动无溢出、Lint、测试和构建不代替视觉判断；整体检查按 VERIFY-04 执行。验证最终交付版本，不能用旧截图或源文件预览冒称最终产物。

### VERIFY-03

#### 实际执行与缺陷回归

适用于改变运行行为的代码、数据库迁移、函数／触发器／RPC、权限策略，以及动态加载或第三方库调用。按实际影响选取场景，不要求无关模块全量重测；纯规范、文字和低影响样式参数沿用 VERIFY-01。

1. **先列执行路径与间接依赖。** 从用户操作追到请求、持久化及回读，列出本次受影响的路径和已有调用方，包括自动触发的审计、权限与约束。新增和编辑、无变化保存和实际修改分别判断，不能以其中一个成功推断其他路径可用。新增／修改的函数和库 API 按目标版本文档或可执行探针核实名称、签名及导入方式。
2. **数据库必须执行真实操作。** 在隔离的、与目标数据库相同主版本的真实 PostgreSQL 中加载实际迁移／函数定义及必要前置依赖，执行能到达受影响分支的 INSERT／UPDATE／DELETE／RPC，再回读结果。只创建函数、SQL 文本包含断言、Mock 或内存兼容引擎不能代替这项验证；兼容引擎可补充快速回归。权限相关场景使用对应应用角色／身份及必要授权上下文，不能仅以数据库超级用户成功证明业务角色可用。
3. **核对成功、边界和失败的业务结果。** 按受影响契约覆盖实际字段修改、空值／无变化、允许与拒绝、失败回滚；涉及审计时核对前后快照、变更字段／数量、身份及无变化时的既有约定，保证业务写入与审计的一致性。并发、幂等、重试及保存成功但回读失败按实际影响验证，不为通过测试停用触发器、放宽权限或吞掉错误。
4. **修复须证明测试能抓住原错误。** 用同一隔离夹具和业务断言，先确认旧实现因本次缺陷失败，再确认修复后通过，记录命令及关键结果。基础设施或夹具错误不算复现；测试不得只检查新代码字符串，也不得只让 Mock 返回预期成功。已应用的迁移通过后续迁移修复，保留升级路径与历史追溯，不能只改旧文件冒称目标库已修复。
5. **必需回归进入持续验证。** 可重复的执行测试、隔离夹具及实际运行入口随改动交付，并接入仓库现有 CI；检查最终提交的工作流确实运行这些测试，且失败能够使检查失败。仅临时手测、跳过测试或未引用的测试文件不能作为持续防护。验证命令与合并门槛仍只由仓库 AGENTS、package.json 和工作流定义。
6. **应用链路验证到可观察结果。** 涉及用户操作的运行行为变更，在隔离／预览环境以实际构建完成受影响关键闭环，例如“打开已有记录 → 修改字段 → 保存 → 重新读取 → 核对历史”。第三方导入、文件或导出变更核对实际库及最终产物，Mock 应与已核实版本接口一致；生产构建成功不等于该运行路径已通过。禁止用未授权生产写入充当测试。
7. **证据明确到版本与覆盖范围。** 记录被测提交或本地差异、数据库／依赖版本、角色、夹具、执行入口、预期／实际结果及未测项。数据库不可用、缺角色或无法复现时保留未验证状态，继续不受阻部分，按仓库门槛交付；现有 CI 的绿色结果不能证明其未运行的路径。发布另按授权范围核对目标迁移／函数版本和适用业务结果，不从预览成功推断生产已修复。

### VERIFY-04

#### 整体视觉验收

适用于网页及任务涉及的报告、演示、图表等需审美设计的最终输出，中英文使用同一标准；跨媒介参数仍遵循对应专项，不套用网页像素。视觉规则由 01 维护，本节负责验收方法：

1. 先看整页，再看局部：核对默认可见的文字块数量、阅读顺序、分组和共同对齐边界；相关信息不能被大留白切开，图表标签遵循图形自身的秩序。
2. 对照 01 的文字选用，核对实际字号与字重的分布及必要例外；检查正文、按钮、图例、说明和数值是否复用档位，不能用“每种角色内部一致”代替整页统一。
3. 对照相邻章节、代表页面及适用桌面／窄屏，确认组织规则连贯；精简重复文字和控制项后，单位、来源、数据边界、完整内容入口和关键动作仍可达。
4. 记录具体问题、修改及最终画面证据。即使没有溢出、数值正确、检查通过，只要画面仍散乱，就继续修正或明确保留未通过项；不能以机械检查替代审美判断，也不能把用户否定的候选作为已认可母版。

本条不等于用户已认可具体配色、字号参数或整套视觉；用户对某段动效或某个交互的认可，只覆盖其明确对象。缺少最终渲染证据时准确说明未完成视觉验收。

## MOB-05

### 手机平台与证据

手机完整能力由 03 的 MOB-01 及模块矩阵定义，交互执行 02 的 MOB-02—MOB-04。本节只定义验收方法，不能缩减模块功能。

| 平台 | 验收基线 | 证据要求 |
| --- | --- | --- |
| iOS Safari | 验收时可用的正式稳定版本 | 记录手机型号、iOS 与 Safari 实际版本、代码版本、角色及测试步骤 |
| Android Chrome | 验收时可用的正式稳定版本 | 记录手机型号、Android 与 Chrome 实际版本、代码版本、角色及测试步骤 |
| 桌面 | 任务实际使用的浏览器 | 记录浏览器版本与视口；桌面与手机对照同一业务契约 |
| 微信等内置浏览器、其他浏览器及旧版本 | 根据用户环境或专项任务补入支持矩阵 | 未纳入或未测须明确，不能宣称所有浏览器均已通过；不影响上述两类手机平台的必需验收 |

iOS Safari 与 Android Chrome 是本轮制定的工程默认基线，不冒称用户逐一指定了设备／版本；用户明确的实际环境应补入验收范围。完整模块验收覆盖这两类真实手机上的受影响关键闭环，桌面调整视口、设备模拟及截图只是补充证据，不能代替软键盘、触控、文件处理与系统切换的实际结果。

### 手机检查表

1. 对照 03 模块矩阵列出全部既有业务动作；按权限差异选取适用的可写、只读和管理身份，分别记录允许／拒绝结果，不通过前端显隐扩大权限。
2. 完成进入、定位对象、查看完整内容、编辑／选择、校验、提交或保存、结果核对、取消与返回；无编辑能力的模块检查其真实完整任务。
3. 检查软键盘、横竖屏、放大、安全区域、固定动作、滚动、菜单与叠层；已有 hover／右键／拖拽操作均有可用触控路径。
4. 对有文件与批量能力的模块完成选文件、上传／预览／下载／导出、取消、部分失败和重试，核对对象与范围。
5. 对有写入或草稿的模块检查断网、应用切换、返回和重复点击后的既有保护；请求未确认不显示成功，也不重复写入。
6. 记录实际版本、设备、角色、输入场景、步骤、预期／实际结果、截图或日志、未测和遗留。布局通过、功能通过、全部模块通过分别判断。

缺手机、未登录、缺权限或目标环境不可用时继续可以完成的工作，交付受限结果并保留未验证项，不宣称该模块手机验收完成。浏览器不支持某原路径时须提供同业务结果的替代路径并验证；没有替代路径就保持未完成，不能用普通视觉例外或“请用电脑”豁免。

## 4. 证据与门槛

### VERIFY-02

| 证据 | 能证明什么 |
| --- | --- |
| 文件生成／导出 | 产物已产生；不等于内容、渲染或可编辑性正确 |
| 静态检查 | 指定结构／规则符合；不等于真实交互、授权或性能通过 |
| 隔离测试 | 指定模型、输入和环境行为；不等于生产会话或手机真机结果 |
| 本地 verify | 本地脚本列出的检查完成；不包含未运行的 CI 额外任务 |
| 精确 PR head 的 Verify | 对应该提交的 CI 工作流结果；不代替手工及手机验收 |
| 真实浏览器／手机操作 | 指定版本、角色、设备与步骤的结果；不外推未测平台或模块 |
| PowerPoint 原生／MAXHUB 真机 | 对应文件与硬件上的实测；其他渲染器、模拟或虚拟计时不能冒充 |
| 部署 Ready | 目标部署健康；不代替 CI 和业务核验 |
| 已授权目标库回读及页面核对 | 本次操作的实际结果；不从本地成功推断生产已更新 |

失败处置、基线证据和合并门槛遵守仓库 AGENTS。必要检查未通过或未执行时准确说明受限状态，不把“已说明失败”计为通过。

## 5. 版本与记录

分支、推送、验证命令及 CHANGELOG 要求由 [仓库 AGENTS](../../AGENTS.md) 唯一维护。仅本地文档整理不自动提交或部署；本仓库规范进入后续提交时确认新文件及必需引用被一并携带。

规范决策写 06，工程记录简述影响与验证并引用；一般措辞和链接修正沿用豁免。当前阶段和排期只在任务计划维护，不复制到长期正文；已提交、已推送、预览就绪和生产发布分别记录。

## 6. 文件与可复现交付

- 本仓库 `docs/standards/` 保存网页规范正文；历史规范按 06 留存。根项目的导航、阶段计划与媒介资料独立维护，不作为网页仓库运行依赖。
- 原始资料保留，来源可定位；生成 HTML、报告或导出文件记录真实入口与内容源／样式源。修正源并重生成，不只手改产物。
- 需要可编辑时保留文字、图表和表格对应编辑能力；整页图片不能替代可编辑正式稿。文件名说明主题、期间、用途及版本，不伪称最终版。
- 交付提供可点击入口，简要说明变化、验证、限制及遗留；技术制作过程不塞进一般用户界面。

## 7. 完成条件

| 任务 | 可以宣布完成的条件 |
| --- | --- |
| 规范修订 | 责任、范围、依据、例外、索引与必要决策明确，引用／冲突／保护检查完成 |
| 审查或计划 | 范围明确，问题与依赖有依据，建议、现状及未验证部分分开 |
| 本地实现 | 授权范围内的行为和相关验证完成；手机相关模块按 MOB-05 取得对应证据 |
| 资料更新 | 按 04 DATA-01 在授权目标完成日期确认、写入、回读、展示及原件关联；仅解析任务不得冒称入库完成 |
| 发布 | 已获明确授权，仓库门槛通过，目标环境真实结果确认 |

关键答案或必要验证缺失时交付已完成部分，准确保留未完成状态。全系统手机能力只有模块矩阵全部覆盖并取得对应证据后才能声明完成。
