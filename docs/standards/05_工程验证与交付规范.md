# 高力国际工程验证与交付规范

版本：V2.9｜日期：2026-11-27｜命令、分支及合并条件见[仓库 AGENTS](../../AGENTS.md)。

## 1. 范围

核对当前版本、实际入口和未提交工作；只验证本次受影响路径和共享调用方。保留业务含义、权限、数据、草稿及失败恢复，生产写入与对外发布按授权执行。必要信息缺失时只暂停依赖部分。

## 2. 实现

复用 `src/styles/tokens.css`、现有基础组件及共享数据入口；保持样式作用域和接口兼容。共用能力用代表业务验证，不扩成无关模块的全量改造。手机适配保持同角色完整业务能力。

## 3. 按风险验证

### VERIFY-01

| 改动 | 必要验证 |
| --- | --- |
| 纯说明文档 | 内容、链接和规则一致性；不运行应用测试 |
| 文案／低影响样式／客户端局部小交互 | [FAST-01](../../AGENTS.md#快速更新fast-01) 快速检查；相关组件可读性、可达性与现有回归，不强制新增测试 |
| 运行行为／共用组件 | 受影响操作、适用角色及关键成功／失败状态；已有测试可直接复用 |
| 搜索／文字筛选 | VERIFY-04 的连续输入和焦点回归 |
| 数据／身份／权限／数据库 | VERIFY-03 的实际执行、允许／拒绝、失败回滚和必要并发回归 |
| 文件／导出 | 检查实际库与最终产物的字段、内容及可编辑要求 |

自动组件、接口、数据库及浏览器功能测试按风险组合使用，不要求每次另做手工浏览器巡检或截图报告。界面实现者沿用设计规范，布局相关问题可用桌面及手机视口检查；只有专项问题确需设备能力时才测试目标平台。已有适用回归足够时不重复造测试；出现失败或新风险再扩大范围。

### VERIFY-03

#### 实际执行与缺陷回归

适用于改变运行行为的代码、数据库迁移、函数／触发器／RPC、权限策略，以及动态加载或第三方库调用。按实际影响选取场景，不要求无关模块全量重测；纯规范、文字和低影响样式参数沿用 VERIFY-01。

1. **先列执行路径与间接依赖。** 从用户操作追到请求、持久化及回读，列出本次受影响的路径和已有调用方，包括自动触发的审计、权限与约束。新增和编辑、无变化保存和实际修改分别判断，不能以其中一个成功推断其他路径可用。新增／修改的函数和库 API 按目标版本文档或可执行探针核实名称、签名及导入方式。
2. **数据库必须执行真实操作。** 在隔离的、与目标数据库相同主版本的真实 PostgreSQL 中加载实际迁移／函数定义及必要前置依赖，执行能到达受影响分支的 INSERT／UPDATE／DELETE／RPC，再回读结果。只创建函数、SQL 文本包含断言、Mock 或内存兼容引擎不能代替这项验证；兼容引擎可补充快速回归。权限相关场景使用对应应用角色／身份及必要授权上下文，不能仅以数据库超级用户成功证明业务角色可用。
3. **核对成功、边界和失败的业务结果。** 按受影响契约覆盖实际字段修改、空值／无变化、允许与拒绝、失败回滚；涉及审计时核对前后快照、变更字段／数量、身份及无变化时的既有约定，保证业务写入与审计的一致性。并发、幂等、重试及保存成功但回读失败按实际影响验证，不为通过测试停用触发器、放宽权限或吞掉错误。
4. **修复须证明测试能抓住原错误。** 用同一隔离夹具和业务断言，先确认旧实现因本次缺陷失败，再确认修复后通过，记录命令及关键结果。基础设施或夹具错误不算复现；测试不得只检查新代码字符串，也不得只让 Mock 返回预期成功。已应用的迁移通过后续迁移修复，保留升级路径与历史追溯，不能只改旧文件冒称目标库已修复。
5. **必需回归进入持续验证。** 可重复的执行测试、隔离夹具及实际运行入口随改动交付，并接入仓库现有 CI；检查最终提交的工作流确实运行这些测试，且失败能够使检查失败。仅临时手测、跳过测试或未引用的测试文件不能作为持续防护。验证命令与合并门槛仍只由仓库 AGENTS、package.json 和工作流定义。
6. **应用链路验证到可观察结果。** 涉及用户操作的运行行为变更，在隔离／预览环境以实际构建完成受影响关键闭环，例如“打开已有记录 → 修改字段 → 保存 → 重新读取 → 核对历史”。第三方导入、文件或导出变更核对实际库及最终产物，Mock 应与已核实版本接口一致；生产构建成功不等于该运行路径已通过。禁止用未授权生产写入充当测试。
7. **证据明确到版本与覆盖范围。** 记录被测提交或本地差异、数据库／依赖版本、角色、夹具、执行入口、预期／实际结果及未测项。数据库不可用、缺角色或无法复现时保留未验证状态，继续不受阻部分，按仓库门槛交付；现有 CI 的绿色结果不能证明其未运行的路径。发布另按授权范围核对目标迁移／函数版本和适用业务结果，不从预览成功推断生产已修复。

### VERIFY-04

搜索、文字筛选、可搜索选择器及其状态容器的相关变化，保持 [UI-03](02_组件与交互规范.md#ui-03)：首字符输入后跨过结果／标签更新，继续输入而无需重新聚焦；核对值、光标／选区和结果。涉及中文组合输入、清除、加载或空结果时覆盖受影响状态。

优先复用真实控件及父组件的自动回归；必要用例在 CI 实际执行，不能以静态截图或绕过原渲染路径的替身代替。自动测试已覆盖时不再追加人工桌面／手机记录。入口登记与实际执行检查见[搜索焦点回归](../verification/search-focus-gate.md)。

### VERIFY-05

#### 界面质量

保留 [01](01_系统设计语言.md)／[02](02_组件与交互规范.md) 的简约统一、文字分组、对齐、可读和操作可达要求，由实现者按改动范围落实。独立视觉评审、前后对照截图、评审者签字、PR 视觉记录及对应 CI 门槛已撤销；无需填写“不适用”或申请豁免。现有浏览器功能回归全部保留；常规 CI 执行适用的代表性功能检查，完整回归在敏感／未知变更及每日或手动完整 Verify 执行。已知受影响缺陷仍须修复，不得以定时检查替代必要业务验证。

### VERIFY-06

#### 按需性能验证

- 修复明确的慢问题或进行性能专项时，选择代表操作，比较同条件下的前后结果，保留失败与数据规模，说明改善及剩余瓶颈。没有实际计时就不声称量化提升。
- 日常改动不要求固定 20 次 A/B、P50／P90 报告、统一耗时预算或额外批准；仅任务明确要求量化验收时采用该任务约定的样本与目标。已有专项脚本默认值仍可用于诊断，不自动成为新任务合并条件。
- [按需性能工作流](../../.github/workflows/performance.yml) 保留原高样本采集和完整性断言，通过手动运行指定套件。常规 Verify 保留核心工程与适用功能回归，严格局部 UI 使用差异 Lint／相关测试，无法确认覆盖即全量。完整 Verify 的数据库与应用／浏览器独立并行，真实 Auth／HTTP 回归保留；确认为已合并 PR 的 main 推送不再重复 GitHub Build，由 Vercel 执行生产构建。
- 无有效收益或瓶颈超出当前范围时说明依据并停止；不通过放宽权限、隐藏错误或伪造样本换取速度。

## MOB-05

### 手机能力检查

保留 [MOB-01](03_模块规范.md#mob-01) 的同角色手机完整业务能力及 02 的触控、键盘、文件和中断保护。与本次改动相关时，使用已有组件／自动浏览器回归或手机视口检查受影响操作。

不要求 iOS Safari 与 Android Chrome 双平台真机证明，不因缺手机、截图或独立评审阻止提交、合并和本地交付，也不要求逐项登记未测设备。只有明确的兼容缺陷或用户指定设备专项才在目标平台实测。模拟视口不冒称真机，未实际验证的平台不宣称全覆盖。

## 4. 结果与交付

### VERIFY-02

检查结果只证明其版本和实际覆盖：静态检查不等于行为验证，Mock 不等于真实权限／数据库操作，视口模拟不等于真机，部署 Ready 不等于业务正确。必要工程检查失败仍阻断合并；已撤销的人工审查无需再列为待办或申请豁免。

交付简要说明改动、验证和实际影响交付的限制；区分本地实现、已提交、已合并与已部署。优先引用 CI 和已有回归输出，不重复制作验收报告。普通小修无需额外日志；稳定规则和实质工程变更按 AGENTS 轻量记录。

原始资料和业务日期保持可追溯，产物检查实际最终文件；需要可编辑时保留对应编辑能力。本地实现完成取决于必要工程及行为验证，发布完成还需已有授权和目标环境结果；不再附加视觉、截图或双平台真机条件。
