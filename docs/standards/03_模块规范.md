# 高力国际模块规范

版本：V2.1｜日期：2026-10-25｜共用视觉遵守 [01](01_系统设计语言.md)，组件行为遵守 [02](02_组件与交互规范.md)。

本文件明确各模块应解决的任务、结构与保护边界。这些是长期模块契约与目标，不表示已经逐项实现；业务动作、权限及数据含义的改变仍需在具体任务中明确授权。手机为完成同一业务任务重排布局与交互路径时，在具体已授权适配范围内执行。

## 1. 跨模块共同规则

- 相同对象沿用相同名称和身份；从地图到成交、对比和方案不能丢失楼宇或项目上下文。
- 返回目的地、当前范围、只读状态和必要数据日期可识别；不要用重复大标题和每行标签补救上下文缺失。
- 面向一般业务读者时，模型实现、规则版本、内部 ID 和调试状态默认按需展开；影响数据判断的来源、范围、缺失和待核验保持可见。数据关联、审计、数据库和诊断中的技术标识本身是工作对象时可以直接展示，不受“隐藏技术细节”限制。
- 视觉改造不改变筛选权限、分页读取、计算、导出范围和数据归属；确需改变时独立列入需求。
- Viewer 与 Editor 在相同授权条件下保持相同业务读取范围；Viewer 不得新增、修改或删除业务数据，Editor 写入仍受归属及模块规则约束。账号设置、会话维护和审计按各自权限执行，不与业务写入混同。
- 用户模拟同时核对真实操作者与有效业务身份，不得借管理员身份扩大被模拟用户的数据范围。预览不隐含代办授权；未明确采用的新代办流程仍是候选。
- 模块间复用同一套控件和反馈。需要特定布局时使用命名变体，不能另起一套颜色或交互习惯。

## 2. 首页

**主任务：** 进入常用业务并查看团队动态。

- 保留地图主入口、可用时的 Intelligence 入口、常用工作列表和团队动态的分工；容器使用 01 的首页例外。
- 模块访问权按真实角色决定；无权限状态不伪装成系统坏了。用户模拟状态保持明确。
- 团队公告、市场交流、问题与建议是次级工作区，不能挤占主要业务入口。
- 不增加没有业务用途的欢迎大屏、全站数字卡片、重复模块介绍。
- Intelligence 试用状态使用一个稳定的“内部试用”标签；后续统一迁移时替代各处自行拼写的 Pilot Preview，不暗示已经正式发布。

## 3. 登录与设置

**主任务：** 完成身份验证或账户设置。

- 登录保留既有企业邮箱、手机号、密码与信任设备规则，不在视觉任务中取消验证字段或自动勾选信任设备。
- 标签、输入、密码显示、加载和错误遵守 02。登录失败保留可安全保留的输入，说明下一步。
- 首次强制改密状态与普通设置区分；页面返回能力仍受既有认证约束。
- 更改密码、账户权限等实际操作遵循当前授权；审查或展示不得提交真实修改。

## 4. 地图

**主任务：** 在地理位置中检索、比较和理解楼宇。

- 采用全屏数据布局：紧凑应用页头 → 搜索／筛选与模式入口 → 地图主体 → 必要图例及指标。
- 主地图、列表、楼宇窗口、关联成交、趋势、联系方式、资料与客户方案入口共享对象上下文。
- 定义默认项目、租金、空置率、LEED、对比组各自的颜色语义；模式切换同步图例，不能把状态色和数据色混用。
- 信息按主次展开：默认楼宇窗口突出核心经营数据与必要动作，成交记录放非模态侧面板，原件和历史资料按需进入。
- 窄屏筛选与列表能收起，地图仍有可用面积；不缩小所有文字和控件来塞满。
- 保护地图容器高度、低／中／高缩放标记层级、选中连续性、视口与已有筛选语义；不得借换皮改变渲染策略或制造重复标记。
- 原生 HTML、图表和 SDK 窗口必须经过样式适配，不遗漏在公共规范之外；内部层级执行 02 的局部映射。

## 5. 楼宇对比

**主任务：** 保留目标楼宇与候选项目，逐项比较经营及楼书字段。

- 使用全屏数据布局；桌面为选择／筛选面板与比较表，窄屏将选择面板收起，给比较表可用空间。
- 保留目标、竞品、经营数据期间和字段来源；目标高亮是身份区别，不能误读为质量排名。
- 固定指标列、分组折叠、“仅看差异”“隐藏空指标”、搜索与指标条件继续存在。
- 现有选择契约为最多 5 个竞品，目标楼宇单独计数；目标也被选中时最多显示 6 个项目。依据为 [当前比较工作台](../../src/app/compare/BuildingCompareWorkspace.tsx) 的 `MAX_COMPETITORS` 与选择逻辑；视觉改造保持此行为。
- 空字段按 04 的值／状态映射显示，不自填 0；不同季度数据必须可识别，避免比较造成同期间假象。
- 返回地图保持已有上下文能力；分组展开与项目选择支持键盘。

## 6. 季度数据填报

**主任务：** 按分配与配置期间，填写、保存并提交楼宇季度数据。

- 使用全屏紧凑表格变体；顶部集中分类、季度、进度、保存／提交与历史恢复，表格为主体。
- “保存草稿”与“提交本季数据”保持不同语义；本地已保存、云端已确认、提交未确认不得混称完成。
- 已收起的历史参考不重新变成常驻大横幅；恢复入口继续保留原内容、来源、时间与确认流程。
- 保护分类切换、未保存提醒、冲突隔离、跨标签页保护、幂等提交、只读预览和原始恢复记录。
- 普通表格单元格执行紧凑文字／控件规则；不能靠 11px 小字或大面积彩色底压缩复杂错误。
- 草稿异常、请求未确认、配置不可用和分配未就绪都明确呈现，不假设可写、不自动补季度。

## 7. 租赁成交填报与团队监控

**主任务：** 新增／编辑个人成交、查阅团队记录与必要进度。

- 使用业务工作台；主操作为新增成交，记录是主体。本周任务进度可保留；会话健康等技术状态转为实际请求反馈，不占据装饰性大卡片。
- 我的记录、团队汇总、个人目标分别说明范围；角色决定可见操作，视觉统一不扩大修改权。
- 新增／编辑用统一 Drawer 变体；详情、变更记录和转交使用匹配任务的公共浮层与确认。
- 保留字段校验、楼宇选择、日期与租金含义、编辑历史、转交归属和导出精度。
- 团队监控复用团队记录与进度的视觉规则，不重复建立新的指标、筛选和提示体系。
- 租金显示与原始精度按 04 的成交字段契约执行，不在模块文档重复维护精度规则。

## 8. 成交历史查询

**主任务：** 通过企业、楼宇、来源和条件找到成交，并按需查阅细节。

- 延续连续工作面：搜索／来源切换／高级筛选 → 条件与结果 → 记录 → 分页；不要重新加回无助检索的 KPI 卡片和重复英文标题。
- 首要字段优先可见，完整明细放详情抽屉；同企业／同楼宇追查入口保留。
- exact／project／unmapped 等身份边界只在影响理解时突出，精确匹配不逐行重复装饰标签。
- 保留分页、稳定排序、来源过滤、历史与实时数据权限和失败时不伪装完整结果的规则。

## 9. 研究资料库与后台资料库

**主任务：** 按目录、关键词与类型定位、查看和下载资料；管理者按权操作。

- 前台与后台继续复用同一资料库组件及内容逻辑。
- 路径 → 搜索／类型／排序 → 结果 → 适用操作形成连续层级。默认搜索范围是当前目录，不暗示全库搜索。
- 桌面表格、手机列表使用同一事实；保留名称、类型、大小、修改时间、完整详情及适用操作。
- 上传、重命名／移动、重复名称、批量删除和部分失败按真实结果反馈。未完成不能写成全部成功。
- 修改时间、收录时间与业务数据日期不能混为一谈；下载原件不代表内容仍有效。
- 阅读者不显示无权执行的管理动作；删除仍按真实后果确认。

## 10. 房源、佣金与项目资料

**主任务：** 对照同一楼宇的真实业主资料，比较可核实条件并回看原件。

- 保留房源、佣金政策、项目资料的类别与各自版本。楼书不能替代房源，不按上传先后覆盖业务日期较新的资料。
- 房源的默认顺序为楼层／单元 → 面积与租金 → 对齐的必要属性 → 备注与依据按需展开。
- 房源卡片采用 01 已列的专项列数／断点例外，共享同一份内容；实际面板不足时按该规则减列，不把全局断点误当成现有卡片断点，也不退回两套重复事实或全字段表格。
- 共同日期与计价说明集中一次，行级不同日期保留独立依据。原件、历史版本、归属未确认、组合方案和冲突信息不因减负而删除。
- 佣金主界面突出摘要、基数和有效期，详细条件展开；未给有效期不能宣称有效。
- 新资料日期确认执行 04 和子项目 AGENTS 的专项流程。等待确认时，更新任务仍未完成。

## 11. Intelligence 与客户方案

**主任务：** 输入客户需求，获得可解释候选，由业务人员审核后形成方案。

- 阅读顺序为需求 → 推荐结果 → 选择与核验 → 客户方案。首次进入突出需求和主操作；有结果后候选占主要视野。
- 硬条件、偏好、系统假设和待核验分别表达；不能压缩成一个不透明的“匹配度”。
- 保留 AI 预选与人工确认的区别，缺失的实时房源不参与伪精确判断。
- 模型品牌、规则版本等放必要的技术信息中；界面优先说明业务限制与下一步，不用算法实现说明填满首屏。
- 候选卡片用于真实项目比较，保留证据和可展开的权衡；不为每条理由嵌套一张卡片。
- 客户方案明确“候选／待审核”状态、数据期间、限制与来源；打印隐藏操作控件但不隐藏会改变判断的限制。
- 返回明确为“返回业务智能”或来源，不能写“主页”指向模块，也不放重复同义返回入口。

## 12. 管理后台

**主任务：** 在明确权限下管理数据、人员、填报、资料与系统记录。

| 栏目 | 必须保留的主任务与设计约束 |
| --- | --- |
| 数据库 | 表选择、搜索／列筛选、编辑、锁定、导入导出、备份；AG Grid 通过适配使用共同主题 |
| 用户 | 用户定位、角色与状态、必要账户操作；身份模拟与真实权限明确分开 |
| 填报 | 分配、期间配置、市场看板／原始记录、进度与导出；不得让屏幕筛选改变未说明的导出范围 |
| 数据关联 | 清楚说明对象、字段和关系；允许技术标识与必要分类色，控件和标题仍用共同语言 |
| 资料库 | 复用第 9 节；保留相同目录和真实操作范围 |
| 公告 | 已生效内容与待发布草稿分清；真实发布需要授权，不在视觉审查时操作 |
| 备忘录 | 列表／编辑／历史形成连续工作区，保存与冲突状态明确 |
| 需求反馈 | 问题列表、状态、详情、沟通记录与下一步；状态标签只表达真实处理阶段 |
| 更新日志 | 模块、需求、版本、状态、验证和发布记录；代码完成不等于已上线 |
| 审计 | 业务动作、对象、人员、时间和结果清楚；低风险访问轨迹与业务审计的分工保留 |
| 用户模拟 | 模拟身份与真实权限可识别；不因前端隐藏标识制造真实登录错觉 |
| 数据诊断 | 技术内容可密集，但真实异常与正常数据有明确区分；不靠彩色堆叠制造告警 |
| 显示覆盖规则 | 原值与展示覆盖分开，来源和作用范围明确，不把显示改写当成原始数据修正 |

所有栏目统一标题、工具条、控件、反馈和表格状态；不能因为属于后台就另起亮蓝／绿色按钮和多套 Toast。必要的危险确认、审计及权限检查保持。

## 13. 网页展示与固定快照入口

- `/md-20260928/map` 是会议冻结快照入口，保留冻结数据标识、筛选、消息控制和嵌入接口；不把快照当成正式实时地图，不因日期较旧就视为废弃。
- 其网页端已有的可交互功能同样纳入手机完整操作验收；地图触控、控制面板、返回与接管保持可达。专用投屏画布和真机能力另由媒介任务验收，不虚构手机没有的物理硬件功能。
- 网页中的预览、播放、暂停、返回、重开与文件操作遵守 02；自动轮播仅在明确展示模式启用，输入框的空格不得误触全局暂停。
- 报告原件及 MAXHUB 专用源由对应任务提供，网页规范不复制其专用参数或某次报告的固定页数。

## MOB-01

### 所有模块的手机完整能力

用户已明确所有网页模块，包括复杂后台编辑，均须支持手机完整操作。以同一角色在桌面可用的业务动作及结果为基准：手机可以换布局、分步或逐项操作，不能降为只读、减少字段、隐藏动作或要求使用电脑。这里的完整不授予更多权限，也不新增桌面本来不存在的业务能力。

下表是功能验收覆盖下限；实现前补查该模块当前入口的实际动作，发现表中未列出的既有动作须一并纳入任务验收。每项均使用 02 的 MOB-02—MOB-04 交互契约及 05 的 MOB-05 证据要求。功能尚未实现、设备未测或环境受限时标记未完成，不能据文档直接标为已支持。
