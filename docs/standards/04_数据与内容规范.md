# 高力国际数据与内容规范

版本：V2.1｜日期：2026-10-25｜本文是数据含义、缺失值与资料日期流程的唯一完整维护处。

适用于所有涉及业务数据与可见内容的任务。视觉整理保持事实及业务契约；明确授权的数据修正、导入、计算或权限任务按专项要求执行，记录前后口径、来源与验证。本规范不扩大生产写入或对外发布的授权。

## 1. 事实、口径与身份

- 原始数值、计算结果、展示格式分别处理。视觉改造不得更改原始数据、统计口径、权限、对象归属和导出范围。
- 每个关键指标应能确认对象、期间、单位、样本范围、分母、来源及数据性质。影响理解的限制须在图表或字段附近出现，不能只放很深的附件。
- 真实 0、缺失、未知、未确认和不适用分别表达；不能用 `value || fallback` 抹掉 0，不能用“0 条”代替加载失败。
- 楼宇、楼座、项目和子市场不是同一层级。保持现有主键、映射和 exact／project／reference／unmapped 等边界，不为展示整齐自动合并。
- 同名企业或人员按真实身份区分；离职与历史记录的署名保持，不将当前账号状态代替历史事实。
- 用户提供的新信息优先核对来源和适用范围；与原件冲突时保留双方依据，不悄悄改原文以求一致。

### 值与读取状态的显示映射

| 实际状态 | 默认显示 | 约束 |
| --- | --- | --- |
| 真实零值 | `0`，单位及精度按字段 | 不替换为占位 |
| 空白／null 且没有更具体业务含义 | `—` | 编辑控件保持空输入；只在只读展示中用占位 |
| 明确未知 | `未知` | 已知存在该信息但尚不能确定内容 |
| 需要业务核验 | `待确认`／`未核验`，按字段给原因 | 不与普通缺失混为一谈 |
| 不适用 | `不适用` | 不暗示数据遗漏 |
| 尚未加载 | 加载状态 | 不先显示 0 条或 `—` 后让用户误读 |
| 读取失败 | 错误及下一步 | 保留适用的旧结果，并标明不是本轮新结果 |

字段已由现有明确契约规定更具体的名称时沿用，并记录对应关系；不得自行把“缺失”升级成“已核验不存在”。

## 2. 核心指标与单位

| 内容 | 必须区分的含义 |
| --- | --- |
| 租金 | 净有效租金、表面租金、报价、成交价及含税／物业费口径不能互换 |
| 日租／月租 | 不直接并排当作同单位；按对应业务公式换算并说明依据。不得随意采用 30 天替代现有模型 |
| 空置率 | 比例水平与变化分开；变化用百分点时明确 pp／百分点，不能写成同义百分比 |
| 净吸纳量 | 不是成交面积、新租面积或潜在需求；采用已核实的高力指标含义 |
| 面积 | 建筑／使用／办公／空置／标准层／可租单元面积分别标明；季度空置不代表实时房源 |
| 分级 | 甲级含超甲级、仅甲级、超甲级与乙级按真实分类说明，避免交叉相加 |
| 全市参照 | 使用已核验的全市指标；不能用已展示子市场的简单平均替代 |
| 行业占比 | 说明按面积还是笔数、统计期间及是否含续租；不能扩展成所有需求结构 |
| 租金显示精度 | 成交模块沿用一位小数显示；不连带舍入存储、计算或数值导出 |

不同报告或页面的“平均租金”如口径不同，必须按来源分别命名。专项资料中的术语与本表冲突时保留来源、期间与差异，按业务授权核实，不能假定所有数据已核验。

## 3. 时间与时效

| 时间 | 含义 | 不得替代 |
| --- | --- | --- |
| 数据截至 | 数据对应的业务时点 | 接收或入库时间 |
| 业主确认 | 实际确认条件／资料的时点 | 文件印刷日期或用户收到日期 |
| 收到资料 | 用户或系统收到资料的时点 | 数据截至、业主确认 |
| 文件日期 | 原件记载的日期 | 未经核实的当前有效日期 |
| 收录／解析入库 | 系统处理时间 | 业务更新时间 |
| 有效期 | 政策或条件明确适用的区间 | 任一单独日期 |
| 报告期间／预测期 | 指标统计或预测所属时期 | 文件生成／导出日期 |

- 用户只提供月份时保留月精度，不擅自补成某一天；未知年份和无时区精确时间按专项校验处理，不自行猜测。数据截至、接收、确认等已发生事件不得伪填未来日期；预计入住、政策未来有效期、未来供应和预测期可以在未来，须保留其业务性质。
- 修改日期、上传日期和重新解析不得刷新成新的业主确认日期。资料新旧按业务规则，不仅按文件上传顺序。
- 日期与时间面向用户按本任务时区显示；记录精确时点时保留时区。历史季度不跟着今天的季度自动改名。
- 相对时间如“距今几天”必须能找到其依据日期；依据未知时显示未知，不显示伪精确时效。

## 4. 业主资料导入的强制流程

**DATA-01：资料日期与发布门槛。** 本节维护唯一完整业务流程，由 [子项目 AGENTS](../../AGENTS.md) 强制引用。技术字段、命令、目标环境与回读方法以当前检出版本的实际导入机制为准；专项手册须与实现一并入库，不能另设日期豁免或把尚未发布的机制当成已具备。

- Hang Yu 每次交来业主销控图片时，Codex 必须主动询问这份数据的日期及日期含义（数据截至、业主确认或收到资料），即使原图已有日期也要确认。不要求用户自行填写表单或修改 JSON。
- 用户在当前会话已经明确给过日期和含义时直接沿用，不反复询问；保留用户原话及确认依据，不能冒称日期印在原图上。
- 在用户回答前可以解析、核对楼宇和归档原件；解析草稿的 extraction.uncertainties 必须包含“等待 Hang Yu 确认资料日期及含义”，作为不得发布的阻断条件。对应导入器必须校验该条件；当前版本未接入导入器时由任务记录保留同一阻断，不能冒称已自动校验。资料更新任务仍未完成。不能用“时效未核实”、系统收录时间或视觉演示替代这一步并宣告交付。
- 得到回答后，Codex 负责把日期与依据写入对应资料及每条房源，重新读取本任务授权目标库并核对对应地图展示与原件关联，完成后才能报告该目标的交付。收到日期不能冒充数据截至或业主确认日期；月份不能擅自补成某一天。

上述流程也适用于本系统已接入的 Excel、PDF、文字等业主房源／佣金／项目资料。日期答复补齐业务依据，不自动授权生产发布：按当前任务已授权的目标库写入和回读；本地入库任务按当前实现的本地目标库重开回读及本地预览验收（实现采用 SQLite 时按 SQLite 核验），生产更新按目标生产库和对应页面回读；若仅获解析／准备授权，只报告准备结果，不能宣称目标系统资料更新已完成。

未知、矛盾、组合方案、楼座归属待确认等状态必须保留。多条房源不能因面积相加方便就认定为独立可累计可租单元；资料没有有效期时不能宣称政策仍有效。

## 5. 真实、预测、估读与演示

- 真实记录、预测、原图估读、历史示意和演示数据明确标识，分别保留来源；不因改成正式报告语气隐藏性质。
- 设计样稿标题准确写对应季度和样稿状态，不能把 Q2 资料命名成已完成的 Q3 正式报告。
- 静态分组差异不直接写为因果；单季变化不自动概括为长期趋势、全面改善或投资价值。
- 没有坐标、起终点、样本或方法依据，不生成伪热力、企业迁移、综合评分与机会排名。
- AI 理解、规则筛选、系统假设、AI 预选、人工确认和已核验事实分别表达；推荐不冒充业务人员已经确认。
- 不将示意数据混入正式统计、导出或生产库。验证数据应与业务数据隔离。

## 6. 文案与命名

- 使用清楚中文，正式指标沿用核实名称；保留 CBD、LEED 等必要缩写与“东城商务区”等专名，不机械统一所有词。
- “子市场”不得随意改成“商圈”；名称范围不能扩大，如中服地块不代表整个 CBD。
- 操作名称沿流程稳定：保存草稿、提交数据、发布公告、下载原件分别表达真实后果；“提交”不能被成功反馈写成“已上线”。
- 成功说清完成了什么；失败说清问题及下一步；空状态说明当前范围。删除“系统正常”“数据健康”等无帮助的装饰文案。
- 面向一般业务读者的正文不塞规则版本、模型实现、内部 ID 和制作流程；需要追溯的业务来源、口径与限制保持可见。技术管理页中这些字段本身是工作对象时，按 03 的模块范围直接展示，不与业务页的按需展开规则混用。
- 联系人、姓名及敏感字段按当前任务和原有显示权限处理。既有报告中明确排除的联系人不得因套用旧模板重新出现。

## 7. 来源与交付内容

- 原始资料保留，改稿另存。来源能够定位到对应文件、页、表或记录，详细对照放工作记录。
- 面向读者的图表保留必要来源、单位、期间与限制；“原稿第几页”“沿用原图”等制作说明不当作正式正文。
- 友商资料仅按已核实内容用于设计和方法比较，不混淆机构、期间和统计口径，不照搬法律声明或专有素材。
- 导出与界面同一指标的单位、精度及范围如有不同，必须有明确业务理由并记录；不得以“统一格式”为由改变导出事实。
