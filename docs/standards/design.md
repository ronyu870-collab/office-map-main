# 高力国际系统 设计与交互规范

版本 0.5，2026年10月15日。仓库规范基线，保留条款的确认状态。已确认以现有系统经过打磨的设计为基础，保留合理细节与场景差异，修正累积的不协调；字号、行高和间距依据实际呈现确定。先完善公共组件，再分批调整页面，每批提供前后对照。标注“沿用基础”的内容继承现有基础，具体实施细则仍供审阅，编号保持稳定。

**执行状态：** 标注“沿用”或正文明确“已确认”的内容按其适用范围执行；同一条款中的建议细则仍保留建议状态。“建议”“待定”不因入库自动成为已批准的强制要求，也不授权改变现有业务、权限或整体外观。后续修改以用户最新明确要求及已确认的适用规则为准，确认新规则时同步更新状态、理由和适用范围。

本规范提炼并延续高力国际系统现有合理的视觉与操作习惯，适用于地图、表格、填报、资料阅读和后台管理。各类页面按任务保留合适的布局和密度，共用适用的组件与交互含义。每项优化需指向具体问题，并保护已有设计的协调性和使用体验。

## 视觉方向与基础参数

### D-01 整体风格 方向已确认

本轮已确认：现有各模块包含经过反复打磨的设计，规范以保留这些成果为起点。保留现有品牌、页面结构、合理的信息密度、操作位置与视觉层级，局部修正反复修改积累的不协调。不能仅因不同页面的参数不同就认定为缺陷；先核实用途、实际呈现和既有设计理由，再判断是否需要统一。每项调整说明原问题、修改理由与预期收益，并用前后对照核对。

新设计应说明它帮助了哪项任务。大面积渐变、玻璃效果、过度圆角、强阴影和无业务意义的动画，不作为默认做法。

### D-02 配色与样式变量 沿用基础并建议统一用法

沿用 `src/styles/tokens.css` 的品牌色、背景、文字、状态色和基础尺寸。样式变量是颜色和尺寸的统一名称，例如 `--cd-color-brand`。

| 用途 | 当前基础值或规则 |
| --- | --- |
| 品牌主色 | #003e7e |
| 工作区背景 | #f5f7fa |
| 内容表面 | #ffffff |
| 主文字 | #172033 |
| 成功、警告、错误 | 使用对应语义变量，并配合文字或图标 |
| 小、中、大圆角 | 4px、6px、8px；已有 10px 变量用于适当的大容器 |
| 交互时长 | 轻反馈 120ms，普通过渡 180ms |

建议：新增常规界面优先使用变量，不重复写相同色值。同一语义在所有模块保持一致。地图分级、图表系列等专业配色可独立定义，但须有图例和可复用的配色表。确认本规范后，统一配置中的重复定义，避免多个来源各自演变。

### D-03 字号与行高 基准原则已确认

| 内容 | 基准选取与统一方式 |
| --- | --- |
| 页面主标题 | 从现有同层级标题中选取清晰、协调的样式，保留主次层级 |
| 区块标题 | 以现有区块标题与正文的合理层级关系为依据，同类区块统一 |
| 正文、输入内容 | 参考现有清晰易读的正文和表单，共同核对字号、行高与控件高度 |
| 表格、紧凑控件 | 结合现有表头、单元格和行高确定适用样式，保持扫描与比较效率 |
| 辅助说明、时间、次要标签 | 保留次要层级，同时保证实际可读性；同类用途统一 |
| 关键统计数值 | 沿用现有合理的强调方式，结合周边内容检查协调性 |

已确认字号与行高根据目前系统的实际样子确定，以和谐统一为目标。统一按内容用途和组件类型进行，标题、正文、表格、说明保留合理差异。局部字体过小、拥挤或明显失衡时，结合所在页面修正；数据较多时综合检查列宽、分组和详情展开，避免通过缩字硬塞内容。图表轴标签、地图标记等专业场景保留有依据的局部适配并检查可读性。

已于2026年10月15日完成代码基线核查，结果见“代码核查基线”。现有字号变量及控件高度可以沿用，但部分字号类名存在解析问题，声明值与最终显示值须分开记录。以代码证据确定适用档位后，结合代表页面的计算样式和前后对照验证整体协调。选定参数落实到公共样式或组件，并记录参考页面和用途；字体沿用现有字体栈。本规范不将发现的代码数值直接强制推广到全部页面。

### D-04 间距与布局 建议

优先复用现有间距变量，结合当前页面的实际边距、区块间距和控件内边距，形成同类场景的共用标准。通过对齐及局部间距修正解决不协调，不为统一而整体放大、缩小或重排页面；不同任务布局保留合理差异。

阅读和短表单采用适当最大宽度；地图和宽数据表可使用可用宽度。不能把所有内容都拆成独立卡片，也不能仅为统一布局而增加空白或重复标题。

### D-05 页面结构 建议

每页至少有明确标题、主要工作区域和操作反馈。主操作一般放在标题或工具栏区域；次要操作靠近对象；低频管理操作可放菜单。一个工作区域通常只有一个最突出的主动作。

页面、侧栏、抽屉和弹窗的滚动归属要清楚。固定头部、底部操作区不得遮挡表格、输入框或弹出的菜单。

## 公共组件与任务布局

### D-06 组件复用 建议

按钮、输入框、表格基础元素、表单字段、弹窗和状态提示优先复用 `src/components/ui/` 及现有公共实现。同一语义、尺寸档位和交互状态使用一致样式。需要变化时先判断能否通过现有属性或合理扩展实现，避免为每页复制一套相似实现；页面特有的业务逻辑保留在相应模块。 后续新增和修改界面沿用已提取的字号、行高、间距及组件变体；新增变体须有具体场景依据，写入同一套公共定义和适用说明，避免另起一套标准。

新公共组件应由实际业务需求驱动。地图控件、表格列头和内联编辑可采用专用组件；常规尺寸、焦点、状态和禁用含义仍遵循本规范。例外在改动说明中记录，不必为常规实现逐次请求批准。

### D-07 按钮与可点击元素 建议

主要动作使用品牌强调，次要动作使用边框或轻样式，危险动作表达具体后果。按钮必须具备悬停、键盘焦点、按下、禁用和处理中的适当反馈。

纯图标按钮要有可访问名称，必要时提供提示。移动端重要触控区域建议至少 44px；紧凑图标本身可以更小。禁用操作需在用户需要时解释原因，不能让用户猜测。

### D-08 数据表格 建议

数据表优先保证扫描和比较效率。文字通常左对齐，数值通常右对齐，单位放在列头或明确位置。精度按业务规则统一，空值使用一致占位，零值正常显示。

筛选、排序和分页共同作用于同一数据状态。已选条件可见，可单项清除或重置，记录数含义清楚。筛选导致当前页失效时返回有效页。宽表允许在表格容器内横向滚动，页面主体保持稳定。

### D-09 表单与草稿 建议

字段应有标签；必填、格式、单位和例子在需要时说明，不能仅靠占位文字。错误放在对应字段附近；提交失败时保留输入并提供重试。多字段长表单按业务含义分组。

草稿、保存中、已保存、保存失败、提交中、已提交使用清楚且一致的状态。历史参考与本次可编辑值应可区分。离开页面可能丢失已输入内容时，按实际保存机制提供可靠保护，不能一律弹窗打断。

### D-10 弹窗与抽屉 建议

简短确认用弹窗，保留列表上下文的详情或编辑可用抽屉，复杂长流程可使用独立页面。覆盖层必须有标题、明确关闭方式、键盘焦点管理及内容滚动边界。

默认支持 Escape 关闭并恢复焦点；提交中的关键操作是否允许关闭，按业务后果决定。删除、覆盖等确认应写明对象与结果，按钮使用“删除这条记录”等具体文案。业务流程逐步替换原生 `alert()`、`confirm()`。

### D-11 加载与请求结果 建议

加载、无记录、无权限、筛选无结果和请求失败分别处理。加载时保留页面结构；已有数据刷新的状态不应无理由清空整个页面。

失败时说明影响范围并提供适当重试。不能把读取失败显示为“暂无数据”，也不能只在控制台记录后让页面看似正常。

## 移动端与交互反馈

### D-12 移动端适配 建议

移动端保留核心查询、阅读和填报能力。长表单采用单列；复杂表格可选择保留横向滚动、精简列或卡片视图，按任务逐页决定，不能静默隐藏关键业务信息。

重要操作在触屏可完成；不能只依赖鼠标悬停。虚拟键盘打开后，当前输入和提交、取消动作仍应可达。

### D-13 地图与可视化 建议

地图颜色、气泡大小、筛选、选择和图例表达同一套含义。选中、悬停和普通状态应可区分，切换渲染方式后保持一致。图表显示单位、时间范围和必要口径，避免颜色相近到难以辨认。

列表、地图与详情联动时保留用户已选对象及筛选上下文，业务需要清空时给出可理解反馈。

### D-14 动画 建议

默认以轻量状态过渡为主。动画应帮助辨认切换、展开、保存和选择，不能延迟操作、造成页面跳动或阻塞输入。优先使用不引起大范围布局变化的过渡，支持系统“减少动态效果”设置。

长时间循环、自动滚动和大量地图元素同时运动需单独验证阅读与性能。动效强度可在待定事项中调整。

### D-15 可访问性 建议

键盘能到达并操作主要功能，焦点清楚且不被覆盖。输入框有标签，图标按钮有名称，状态变化有适当读屏反馈。颜色不能成为传达错误、选择和业务状态的唯一方式。

检查文字与背景的对比、200% 页面缩放、较长中文和键盘导航。个别专业视图的限制需说明替代操作方式。

## 一致性与例外

### D-16 新旧界面迁移 顺序已确认

本轮已确认先完善公共组件，再分批调整页面。执行建议：先记录代表页面的实际画面、计算样式、关键操作及需要保留的细节，形成现状基准；再从现有良好用法提炼共用样式和必要变体。先在一至两个代表场景验证组件兼容性，再逐批迁移已确认存在问题的区域。不得通过直接修改全局默认值，使尚未核对的页面同时改变。每批范围应能说明、验证和单独回退；共享改动涉及的所有实际受影响页面纳入检查，每批提供修改前后对照供余航反馈。其他差异按保留、待修复、待核实记录，不自动列为整改项。

普通表单、紧凑录入、阅读表格、地图标签等可具有各自合理的尺寸和密度。已核实的场景差异记录用途、参考页面及需保留的细节，作为规范中的适用变体。新增差异说明具体需求，优先复用现有变体；原因不明且未发现实际问题时先保留并核实，避免为形式一致破坏成熟设计。

### 字号解析问题的核实依据

[依赖锁文件](https://github.com/ronyu870-collab/office-map-main/blob/96b7415c2facf9a08d14ccc67b179f8916084ed8/package-lock.json)锁定 Tailwind CSS 4.3.0。该版本的[候选解析](https://github.com/tailwindlabs/tailwindcss/blob/v4.3.0/packages/tailwindcss/src/candidate.ts)仅在类名提供类型提示时记录明确类型；[类型推断](https://github.com/tailwindlabs/tailwindcss/blob/v4.3.0/packages/tailwindcss/src/utils/infer-data-type.ts)对 var(...) 返回未知，随后 [text 工具类规则](https://github.com/tailwindlabs/tailwindcss/blob/v4.3.0/packages/tailwindcss/src/utilities.ts)走颜色分支。其[官方测试快照](https://github.com/tailwindlabs/tailwindcss/blob/v4.3.0/packages/tailwindcss/src/utilities.test.ts#L26363)也区分了无类型的颜色变量和带 length 类型的字号变量。

因此，现有写法本身不会生成预期的 font-size。可考虑的明确写法例如 `text-[length:var(--cd-font-size-sm)]`，或将用途映射到统一的语义类。此处已完成源码与官方解析规则交叉核查，未运行本仓库的完整构建，也未测得各元素的最终计算样式。

先记录代表页面的现有效果及最终计算样式，再确定普通表单、紧凑录入、阅读表格、长文和地图标签的适用基准。修复字号解析问题时逐项比较实际显示值与代码声明值，保留用户已经熟悉且合理的视觉比例。

公共组件变更检查全部实际受影响的使用页面；首批重点包括登录及设置表单、成交主页面与编辑弹窗、季度行内录入，以及管理员弹窗。涉及筛选、输入、保存、关闭或权限状态的变化，按实际影响验证相应流程。

后续新页面复用已核实的公共样式和组件变体，验收时核对最终样式及前后对照。现有 `module-styles-verification.test.tsx` 检查模块权限样式类名和可访问性属性，不能据此证明字号、行高已经在浏览器正确呈现。
