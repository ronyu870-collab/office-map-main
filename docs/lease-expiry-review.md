## 当前范围与入口

用户明确把功能收敛为：看看哪些企业预计到期。当前页面为桌面只读时间图、手机简洁列表，左侧成组显示企业、原成交楼宇、成交时间、租期、面积、行业及该成交楼宇的子市场，右侧显示较窄的预计到期时间轴，不提供 AI 分析、核实结论、跟进建议或保存步骤。

- 主入口：**租赁成交 → 最上方操作栏「租约到期」→ `/lease-submission/expiry`**。成交数据库工具栏提供同名入口。
- 业务智能移除该入口；旧地址 `/intelligence/lease-expiry` 重定向到新地址，同样执行管理员校验。
- 当前范围为真实管理员试点。成交填报和成交数据库共用管理员入口判断；普通账号和模拟账号直达时返回成交填报，不显示到期页面或发起读取。未登录账号进入登录页。见[管理员可见性验证](verification/lease-expiry-admin-only/README.md)。新读取地址 `/api/lease-transactions/expiry` 只导出 GET，复用原服务端授权，调用仅 service_role 可执行的 `lease_expiry_context_list`。
- 后端 `LEASE_EXPIRY_REVIEW_ENABLED` 必须严格为 `true` 才开放。入口可见不替代授权；详情升级仅增加只读 RPC，不修改原成交、RLS、开关或模型配置。
- 只展示未来六个日历月观察窗口内的成交记录，25 条一页；同一企业多条成交不擅自合并，计数标注「条成交记录」。无搜索、导出或额外处理流程。
- 「待核对」仅表示较晚同名成交、已有来源冲突标记或来源指纹变化，不阻止查看，不自动确认合同或客户归属。
- 既有补充记录、旧保存 API、审计与并发保护继续保留兼容；下文保存相关契约描述这一兼容层，**不是新时间图的界面操作**。不删除既有数据。

**D-F6-03（2026-11-13，用户明确采用）：** 替代此前进入 AI／业务智能进行核实或分析的产品流程。简单查看预计到期企业即可，不要求重复填报、逐条核实或调用模型。

**D-F6-04（2026-11-13，用户明确采用）：** 左侧补充原成交信息、右侧收窄时间轴。用户所说合同信息是当时的时间与租期，不是合同附件；系统只掌握成交日期／期间，因此按实际精度标注「成交时间」或「成交期间（推定）」，不改称合同签约／起租日。用户后续明确本轮完全忽略联网行业补充，已有行业优先，缺失显示「未记录」，无外部模型请求。

## 数据与日期

- 使用现有 `lease_transactions_read_v1` 的 `live`／`history` 身份及期间；日常填报直接来自 `lease_transactions`，历史附加来源字段来自 `lease_transactions_history`，不另建或复制成交库。
- 观察窗口从服务端北京时间当天起，至加六个日历月（结束日不含）；候选区间与窗口相交即入选，不按整月或 180 天替代。
- 仅具体日期／季度精度、1–120 的整数录入月份进入候选计算；该范围是首轮核实筛选阈值，不是合同合法租期上限。没有合格期间或租期的原始记录保持原值，本版不单列全库缺失资料队列。
- 候选区间＝成交期间起止分别加录入租期。即使原始期间为某一天，结果仍只是估算，不能推定起租日或真实到期日。
- 保留原租期文本、录入月份、期间来源、原信息日期、文件／表／行定位及楼宇关联范围。原件租期单位并未由程序确认。
- 同名企业＋同名楼宇存在较晚成交只作提示。不会据此认定同一客户、同一合同、续租、迁移或合并记录。
- 不自动修正 W0 发现的来源差异，不把真实样本写入代码或测试。
- 兼容 API 的 saved 范围保留旧补充记录查询；新时间图只读取 window 范围，稳定排序并分页（每页 25 条）。

## 角色与数据边界

| 情形 | 读取 | 兼容 API 保存（时间图无此控件） | 处理 |
| --- | --- | --- | --- |
| 真实、有效 Admin | 两类成交候选与已存补充记录 | 可以 | 不代表获得客户负责人身份 |
| Editor / Viewer / 未知角色 / 匿名 | 拒绝 | 拒绝 | 不因能读日常成交而开放历史库 |
| 管理员模拟其他用户 | 拒绝 | 拒绝 | 需退出模拟 |
| 撤销管理员角色、账号封禁或删除 | 拒绝 | 拒绝 | 每次 RPC 按当前目录与 auth.users 检查，包括重试 |
| 两位有效管理员／跨团队管理员 | 相同管理员范围 | 版本一致才可保存 | 当前系统没有本模块团队隔离，不虚构团队权限 |
| 已离职操作者的历史记录 | 有效管理员仍能追溯 | 新操作者另存新版本 | 保留原操作者 UUID 和共享审计身份快照 |

客户端只传 bearer token 与核实内容，不接受操作者 ID。服务端核验 token 及真实角色后，把可信 actor ID 交给仅 service_role 可执行的 RPC。数据库再次查角色、账号删除与封禁状态；事务持有对应共享行锁，让权限变更与保存有明确顺序。匿名和 authenticated 均无 RPC 执行权限，也无两张新表的直接权限；新表开启 RLS，无宽泛授权策略。

当前既有认证负责会话维护；本模块没有另造一套 session_id 规则。有效 token 仍须通过当前角色／账号状态检查。已下载到浏览器的信息无法物理撤回；页面每分钟及返回标签页时重新校验，收到拒绝立即清空，账号／角色／模拟状态变化立即隔离旧组件和在途结果。

## 草稿与原子保存

兼容既有存储状态 `pending`（界面显示未标记问题）、`missing_info`（资料不足）、`source_conflict`（来源差异），不迁移或清空已有记录。没有补充记录时直接展示估算结果；三个状态都不阻止候选显示。主动标记后两项时才必须写原因，避免留下无法理解的标记。依据定位最长 1000 字，备注最长 4000 字；原件内容不上传，不执行依据中的链接或指令。

- `lease_expiry_reviews` 按 `(source_kind, source_id)` 保存当前补充记录；不同来源即使 UUID 相同也独立。任何保存都不回写历史成交，不插入任务、客户或合同到期记录。
- 每次保存附带预期 revision 和当前来源快照指纹；版本或来源改变时返回 409，界面保留当前输入，要求人工重新载入并核对。指纹用于变更检测，不作为权限或密码学签名。
- 首次保存也锁定源记录，防止“尚无草稿行”时两个管理员同时覆盖。成功的每个新逻辑保存 revision 加 1；即使内容相同也表示一次明确保存，不当作重复网络请求。
- request_id 绑定操作者和完整请求内容。相同请求重试返回原结果，不重复新增版本和审计；相同键不同内容拒绝。重新改内容会获得新的 request_id。
- 当前草稿、`lease_expiry_review_events` 的前后快照与请求结果、既有 `audit_logs` 同一事务提交；任一审计失败全部回滚。
- 共享审计 action 为 `LEASE_EXPIRY_REVIEW_SAVE`，中文描述和数据库变更分类已接入。共享审计只含状态、版本与 request_id；详细来源与备注在受限的专属事件表，不复制到通用日志。既有数据库触发器产生操作者类型及姓名快照。
- 历史来源仍用 RESTRICT 保留原边界；日常来源使用独立可空外键，删除成交时仅清空引用，不删除补充记录或审计。已删除日常来源退出候选，在“全部已补充记录”中按原快照只读展示，不能继续保存。
- 输入在组件内存中；不会把客户核实资料写入浏览器持久缓存。保存失败保留输入及重试键；链接离开、刷新／关闭、切换对象或筛选提供未保存提示。F6 入口与返回使用文档导航，浏览器返回／链接离开统一触发原生提示；页面内切换继续确认，手机系统返回和后台恢复仍需真机验证。参见 [完整页面验收](verification/lease-expiry-auth-20261111/acceptance-followup.md)。

## API

`GET /api/lease-transactions/expiry?page=1&scope=window` 为当前页面专用入口，只接受 window；在原候选上增加独立 `details`：`area_sqm`、`industry`、`sub_industry`、`sub_market`。按 `(record_source, source_record_id)` 关联统一视图，不能用历史 read_id 或裸 UUID 拼接。子市场为当次成交楼宇的 `sub_market`，不是搬迁前地址的 `old_sub_market`。只对当前页补充，保留排序、计数和原 review snapshot/fingerprint；不返回租金或联系人，不新建缓存或数据表，不调用外部服务。


`GET /api/intelligence/lease-expiry?page=1&query=…&scope=window|saved`
返回 items、total、page、page_size、as_of、window_end。每个 item 含 source_kind、source_available、最小来源快照、估算区间、较晚同名成交提示及已有草稿；不返回联系人、租金、面积或其他无关字段。查询日期由服务端给出，客户端不能扩大时间范围。

`POST` 必须明确 source_kind（history／live），不根据裸 UUID 猜测来源；其余接受 source_id、expected_revision、source_fingerprint、request_id、status、notes、evidence_reference。未知字段一律拒绝。所有响应 private/no-store；错误不会泄漏数据库内部或原始业务行。401 为登录无效；403 为不开放／无权限／账号停用；400 为输入错误；409 为来源、版本或幂等键冲突；503 为服务失败或结果未确认。
