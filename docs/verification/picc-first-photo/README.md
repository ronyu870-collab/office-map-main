# PICC 大厦首图生产验证 · 2026-11-13

范围：正式地图「PICC 大厦双塔外观」。终点是实际照片完成解码并显示到浏览器帧。桌面首开 P90 预算 1500 ms，同页重开 250 ms，反馈 100 ms。旧生产部署 `09f380796f62e978ebd1e267e6c8b3efedd3bfe3`。

- 最初在桌面 Chrome 逐次手动测量首开：3290、2277、2937 ms；分别观察到预览请求 1856、1683、2335 ms。三次均使用 1120 × 694 WebP。一次同页重开 34 ms。双击与原图下载成功，Chrome 显示 242 KB。
- [正式站基线 20 次](production-before.json)：同一桌面 Chrome 与实际网络；每个样本在同源的新地图文档中打开一次，浏览器连接可复用，同文档再重开一次，未人工限速。首开 P50 942 ms、P90 1261 ms，零失败；最慢两次 1811／1937 ms。同页重开 P90 50 ms。与手动数据分开，不把复用连接误称为冷网络。
- [Storage 分段](storage-probe.json)：同一张原件 247878 B，1600 × 991。六次 1120 px 签名预览均为 CDN MISS，WebP 85734 B，下载完成耗时 1020–2206 ms；640 px 虽仅 32628 B，最慢仍为 1974 ms。单独访问私有鉴权变换，同一 1120 px 预览首个请求 MISS、随后五次 HIT。本机探测含跨网络连接，不代表 Vercel 到 Storage 的耗时。Vercel 照片 API 与 Storage 均在新加坡。
- 第 1 轮：保持 1120 px，应用在楼宇、照片和身份验证成功后从固定的私有 Storage 变换路径取 WebP，在同源 API 内一次返回预览和来源信息。浏览器无需连接第二个图片地址；沿用只读访问审计，不共享缓存照片 API 响应。老客户端可继续读取 JSON；原图、外链及试点的路径保持。1.5 秒上游超时、格式错误、超过 512 KiB 或读取失败，回退原图；可用 `BUILDING_PHOTO_INLINE_PREVIEWS_ENABLED=0` 恢复此前的签名预览。
- [第 1 轮受控 A/B](controlled-round1.json)：每档前后各 20 次、零失败，桌面 P90 605 → 867 ms、模拟手机 754 → 1029 ms。两档虽未超预算，却出现实质退步；第二个浏览器请求被移除，但 API 仍要读图并等待完整返回。
- 第 2 轮：每个实例只在授权后按对象路径、变换参数和原件 SHA-256 复用预览字节。5 分钟有效、最多 128 张／16 MiB，淘汰最久未访问的预览。每次重新核对角色、楼宇范围和照片状态并写入原审计；不缓存来源信息、授权结果、下载链接和异常响应。新实例或已淘汰对象仍走私有变换。
