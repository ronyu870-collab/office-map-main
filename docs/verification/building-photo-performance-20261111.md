# 地图首张照片加载 · 2026-11-11

基线为 `d898a8c` 上本地已完成的照片查看器和交互改动（未含本轮提速）；候选只改变目录照片的加载链路。已入库的 2026-11-05 批次清单含 50 张原图，文件大小 P50 379,876 B、P90 5,941,110 B，最大 11,874,528 B；该清单不代表当前生产总量。

第一轮根据原图体积和接口请求顺序处理瓶颈：私有大照片优先签发保留比例的轻量预览，楼宇和照片查询在身份校验后并行。小文件、外链、试点、原件下载和既有授权路径保留。预览不可用时回退一次原图，撤回／越权仍按原范围拒绝。

两组各 20 对交替采样，0 个失败。首次点击反馈 P90 为桌面 56 ms、手机 15 ms；同一弹窗再次展开分别 48／49 ms。样本原件 5,982,552 B，预览 269,738 B。主要收益来自减少图片传输：桌面图片请求 P90 1,760 → 144 ms，手机 4,992 → 341 ms；未把桌面接口 P90 单独声称为提速。

Chrome 157.0.8103.50 使用本地生产构建 API、同版本画廊源码和模拟 Storage／认证，固定服务间请求延迟 45 ms；本机 Sharp 按签发参数产生预览。证据只证明受控条件下第一轮达到预算，不是生产 Supabase、真实办公室网络或真机测速。复跑入口与预算见[性能采集](../../scripts/performance/README.md#地图看图-ab)。

`npm run verify` 通过：174 个测试文件、1129 项和 Next.js 16.2.12 生产构建。真实 Chrome 回归在 1280／390／320 px 验证预览返回错误时只回退一次、最终显示原图，以及下载字节与交互；浏览器夹具与生产的 hidden 显示规则一致。接口执行回归覆盖授权后并行、私有路径、尺寸上限、签名失败回退及下载继续签原件；沿用仓库 Verify 工作流入口，远端尚未执行。

目标 Supabase 的图片变换设置与实际签名返回未验，未推送、合并或发布；手机真机未测。生产验收需核对目标私有对象能返回预览并按相同终点测量，不默认调整套餐／开关。若禁用，可通过 `BUILDING_PHOTO_PREVIEWS_ENABLED=0` 恢复原图链路。
