## 回归矩阵

1. 管理员 A／B、Editor、Viewer 真正登录并生成 Auth 会话。
2. 未登录 401；Editor／Viewer 读写 403；真实管理员模拟他人时读写 403。
3. 普通账号修改自身 metadata 为 admin 不能提权；直接改 `user_roles.role` 被拒绝。
4. 登录用户直接访问核实表或冒充管理员调用 RPC 被拒绝，包括 Admin 浏览器自身的普通 JWT。
5. HTTP 保存与重新读取一致；相同请求重试只生成一个版本和审计；相同键不同内容 409。
6. 两个真实管理员同时编辑、首次同时创建，均一笔 200、一笔 409；同请求同时重试只保存一次。
7. 加载后原始来源变化，旧指纹保存 409。
8. 撤权已提交后，同一枚尚未到期的 JWT 读、写、重放旧成功请求均 403；草稿和两份审计计数不变。
9. 撤权事务先持有角色行锁：在途保存等待撤权提交，随后 403；不留下草稿或审计写入。
10. 保存先取得身份锁：撤权等待这笔原子保存结束；此笔草稿、详细事件与共享审计各加一，撤权完成后后续请求立即拒绝。
11. Auth 封禁后旧令牌不可读写；服务端退出后 `auth.sessions` 已删除，旧 JWT 被拒绝；删除测试账号后旧 JWT 被拒绝。
12. 实际登录页输入邮箱／手机号／密码 → 核实清单 → 修改保存 → 刷新重新打开 → 内容一致；保持页面打开时撤权，下一次权限重查后清空已加载草稿。

第 10 项不是“点击撤权瞬间撤销已经提交的数据”。系统采用事务顺序：已先取得权限锁的请求允许完整结束，避免草稿与审计半成功；撤权事务成功返回以后，旧身份的后续访问均拒绝。

## 可重复执行

脚本：[verify-lease-expiry-auth.mjs](../../../scripts/verification/verify-lease-expiry-auth.mjs)。隔离配置：[auth-config.toml](../../../supabase/tests/lease-expiry/auth-config.toml)。CI：Verify 中的 `lease-expiry-auth` 独立作业，失败会使检查失败。

1. 在空临时目录复制隔离 config，不复制生产 `.env` 或 Supabase remote link。
2. 启动 Auth／PostgREST／Kong／PostgreSQL，本机使用时将暴露端口限制为 loopback；不要用 `supabase stop --all`。
3. 将该本机实例的 `supabase status -o json` 写入权限为 600 的临时文件，不输出或提交密钥。
4. 设置 `F6_AUTH_TEST_ALLOW_LOCAL=disposable`、`F6_LOCAL_SUPABASE_STATUS` 和 `PERF_PLAYWRIGHT_MODULE`，运行脚本。脚本拒绝任何非 127.0.0.1 地址以及非专用端口，创建新账号与独立样本 UUID。
5. 脚本结束删除所建账号和样本；停止本任务专用实例，清理临时凭据。共享审计随该一次性实例销毁，不触及其他环境。

## 实际布局下发现的滚动问题

真实页面使用 `html.h-full > body.h-full.flex.flex-col`，旧合成夹具没有复现这个外层布局。首版核实页面缺少独立的纵向滚动容器；在手机视口中，保存按钮位于 y=1535，而可视高度只有 900，鼠标滚动后仍无法到达。Playwright 的控件自动定位可以程序化滚动 overflow:hidden 的区域，因此此前“点击成功”不能证明用户能完成操作。

已为该页面固定视口高度，并在内容区加 `overflow-y-auto`；没有改变共同 WorkspaceShell、权限或保存行为。相同探针旧版失败、修改后通过；1280／390／320 px 均通过，见 [滚动前后结果](scroll-results.json)。合成浏览器回归已复现真实外层布局，要求滚轮滚动后保存按钮实际进入视口。真实账号脚本也增加桌面和手机视口的滚动检查，随原链路一起接入 CI。真机触控与软键盘仍未验收。
