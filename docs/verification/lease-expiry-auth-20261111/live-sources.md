# F6 日常成交接入

日期：2026-11-11。依据：用户明确授权将日常新增成交接入预计到期清单。实施于 `codex/lease-expiry-review` 本地修改，基线 `d898a8c6d49b5a5259b76b3524126181fa1e30f3`；本轮后续交付已重新 fetch origin main，远端基线仍为上述提交；这只证明 Git 基线，不代表生产发布状态。

## 用户流程

照常填报成交 → 写入现有 `lease_transactions` → 管理员下次读取预计到期清单时自动计算。预计区间与未来六个日历月重叠才入选；例如刚填报三年租期的成交通常不会立即出现在六个月清单。无需另填表、人工补合同或额外定时同步。

修改成交年份／季度或租期后，下一次读取按新值计算；来源指纹变更阻止用旧依据保存补充。删除日常成交后退出候选；如已有补充记录，在“全部已补充记录”中保留原快照，只读展示，不阻断原成交删除。日常输入缺失或不满足当前估算条件时不编造日期；已有补充仍可找回。

管理员权限、默认关闭开关、六个月窗口、1–120 个整数月筛选口径不变。未增加 Broker 可见、分派、推送、导出、模型调用或外部信息发送。

## 数据与身份契约

- 复用 `lease_transactions_read_v1`，同时读取 `live` 与 `history`。数据源显示为“日常填报”或“历史导入”；不把日常记录伪装成旧 Excel 原文。
- 候选、React key、保存请求、补充表主键、事件外键均按 `(source_kind, source_id)` 区分。两张表即使恰好有同一 UUID，也不共享备注、版本或更新结果。
- 日常记录只读取最小字段；不把填报人等同客户负责人，也不返回租金、面积、联系方式等无关内容。
- 历史来源快照字段保持兼容，旧指纹和旧幂等请求体不改写；默认 history 的 SQL 调用可重试升级前的历史请求。新 HTTP POST 必须显式传来源，缺失或未知值返回 400，旧页面应刷新。
- 日常源引用为独立外键 `ON DELETE SET NULL`；不可变来源 UUID、原快照、补充和事件保留。已删除来源不允许新增保存；罕见的人工重用已删除 UUID 也不会接管旧补充记录，正常新增使用新 UUID。
- 公开 RPC 仅作 invoker 包装；private 实现持有权限与源记录锁，仍在同一事务保存补充与两份审计。private helper 无普通用户或匿名执行权，补充／事件表 RLS 与无直接授权保持。
