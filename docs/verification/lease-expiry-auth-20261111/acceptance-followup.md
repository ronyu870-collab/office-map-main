## 实际发现及修复

### 疑似重复成交确认绕过数值转换

通过实际成交表单填写必填项、租期 3 个月，装修期和免租期留空；遇到疑似重复后确认继续，旧实现提示“装修期格式错误”，不能提交。原因是确认分支直接使用 `getValues()`，跳过原 Zod resolver 的空值转换，原始 NaN 进入提交服务。此前直接调用提交服务的联调无法发现这条表单分支。

确认后现重新经过同一 `handleSubmit`／schema 校验，空白选填数字仍转换为缺失值；校验失败恢复正常重复检测。保留重复警告、取消、编辑差异确认和原服务端数值约束。

组件回归在旧代码中收到 NaN 而失败，修复后收到 null 并通过。实际浏览器回归也经过原新增表单、重复确认、正常服务／HTTP／数据库，再打开原编辑表单修改租期并确认；F6 下一次查询立即重算。

### 浏览器返回丢失未保存备注

从业务智能通过原 Link 进入 F6，填写备注后浏览器返回，旧实现直接离开，提示次数为 0，输入消失。原 `beforeunload` 只覆盖文档卸载，不能拦截这次 Next 客户端路由返回。

仅将 F6 入口和返回链接改为原生文档导航，继续使用 `beforeunload` 的离开保护，移除重复的捕获点击确认。代价是该管理员试点入口多一次整页加载；未改全局路由、历史栈或持久缓存，也不把备注写入浏览器存储。页面内切换对象／筛选仍用原未保存确认。

新增真实浏览器检查：返回时取消保留输入、点击返回链接只提示一次、确认后正常离开。浏览器取消文档导航不会产生 load，测试等待实际离开提示而非等待页面加载完成。以后新增到此页的路由入口必须保留文档边界，或提供经过同等回归的导航保护，不能直接恢复软导航。
