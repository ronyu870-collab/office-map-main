# 搜索与筛选焦点回归检查

[VERIFY-04](../standards/05_工程验证与交付规范.md#verify-04) 对应 Verify 工作流中的 **Search and filter focus coverage**。纯说明文档由 CI 范围选择直接跳过；其他改动运行该任务，没有相关入口变化时给出通过结果。

- 比较 PR 的精确基线与实际检出树；从两版代码识别查询控件、调用处、局部样式和静态依赖。受影响入口必须在 [覆盖登记](../../scripts/search-focus-coverage.json) 中有对应的真实组件回归。已有入口即使未登记，受影响时也会阻断，不能用别处的回归代替。非标准入口应主动登记；静态检查无法推断运行时注入或任意动态依赖。
- 首批登记地图搜索、完整列表搜索、列表常用筛选和共用侧栏文字筛选。改动共用控件时会检查它的受影响调用处。新增或迁移入口时，登记实际入口文件、运行用例文件及用例名，并验证逐字输入跨越一次状态更新、焦点与光标保持、最终结果正确。缺登记、删除已有覆盖、缺失／跳过用例或断言失败均返回失败。
- CI 读取 Vitest 的实际执行报告，不依赖 PR 模板文字、文件命名或测试命令是否曾被调用。测试必须经过实际输入与父级状态更新；已有真实控件回归足够时不追加手工浏览器、截图或真机材料。

GitHub main 的必需检查以[仓库 AGENTS](../../AGENTS.md)为准。工程汇总状态会拒绝适用任务失败、取消或意外跳过；不要求人工视觉批准，不增加“分支必须最新”等独立审批。
