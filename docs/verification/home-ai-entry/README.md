# 主页统一入口验收

基线：`a39750f3cae8ec1d818de4dd2f1ea50a99796de9`。分支：`codex/home-ai-entry`。此记录仍在更新，尚未声明合并或生产发布。

## 改动与范围

对话区域与原业务入口共用一个连续工作面，地图与四项工作按同一边界组织。管理员原业务智能入口保留，标记“内部试用”；新对话明确未开放，输入和发送禁用，不接受问题、不调用新AI服务。保留用户菜单、统一搜索、报告可见范围、早期地图导航、按意图预取与团队动态延后加载。

团队公告和交流放在主入口下方。公告取消固定日期列，保留完整正文、展开和失败重试。交流仅改变首页摘要的呈现及消息滚动容器，不改变发送、审计、最近50条上限、全屏和历史返回契约。无数据库迁移、模型调用或权限变更。

设计依据与局部变体见[设计记录](design.md)。

## 行为回归与缺陷证据

实际浏览器发现原`scrollIntoView`在消息加载后会同时滚动首页。相同合成管理员与数据下，390px视口初始滚动390px，`initialScrollTop === 0`断言失败；见[修复前画面](scroll-regression-before-390.png)。旧组件的新增执行测试同样失败：消息viewport应滚到1200，实际为0，滚动发生在祖先路径。修复改用消息viewport的`scrollTo`，初始加载和实时新消息均只控制内部滚动。

- 修复前组件测试：1失败、5通过；失败为新回归，已有发送/重试/返回用例通过。
- 修复后首页相关测试：5文件、36用例通过，包含只滚动消息容器、失败发送保留、单次审计、重复发送防护、全屏返回、公告重试、角色入口、地图焦点保持和未开放查询。
- 新增浏览器初始滚动、三视口、交流开关、菜单焦点、报告导航返回和禁用查询检查已接入Verify的真实构建浏览器阶段。CI使用现有固定版本Playwright依赖，数据完全合成并拦截远端请求。
- 首轮全量verify：审计覆盖、类型及Lint通过（有既有警告）；1,257项中3项失败。已更新与新要求冲突的“所有按钮启用”断言；首页延后加载等待扩为3秒。另一个未改动PDF组件用例在并行负载中超时，单独复核2项通过，未以此豁免最终全量门槛。
- 最新完整verify曾通过199文件/1258用例与生产构建；最后断点对齐后一次复验中，两个未修改的墙钟性能用例触发阈值（500ms、50ms），其余1256项通过。保留阈值和全部用例，以 `VITEST_MAX_WORKERS=2 npm run verify` 完成最终复验：退出码0，199文件、1,258项全部通过，审计覆盖、类型、Lint和生产构建通过（Lint仍有826项警告、0错误）。最终生产构建的10组浏览器场景已通过。降低本地并发仅用于避免CPU争抢，不删测试或放宽阈值；远端仍执行原Verify流程。

- 独立真实浏览器检查通过：[6组认证与地图冷启动](cold-start.json)、[5组意图预取/省流/慢网/触控](prefetch.json)。无未获权地图提前读取，主页静置无无意图路由预取，原地图与资料库导航可达。测量为本地合成延迟环境，不作为生产响应时间承诺。
- 搜索/筛选执行门禁通过：25文件、213项用例，未省略登记的入口。
