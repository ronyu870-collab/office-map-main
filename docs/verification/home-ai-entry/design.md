# 主页统一入口设计与验证范围

基线：a39750f。2026-11-13；用户授权主页先完成并在通过门槛后合入main。后续AI生产启用独立授权。

## 设计决定

使用frontend-design skill并遵守项目长期审美偏好。主要用户是北京办公楼业务人员，首页任务是快速进入现有业务，并承接未来可信查询。采用一个连续工作区：上方紧凑对话区域，下方地图与四项业务导航；管理员原业务智能入口保留在对话区域。团队公告和交流移到下方并列，减少窄侧栏把长公告挤成多行的问题。

基色复用系统token：背景#F5F7FA、表面#FFFFFF、次表面#F8FAFC、正文#172033、次文字#667085、强调#003E7E；仅对话工作面使用柔和次表面，不增加整块深色或插图。字体沿用系统中西文栈，字号从20px标题与14px正文两档组织；常规/中等两种字重，相关文字共边对齐。个别现有弹层保留原完整交互，不作跨模块重设计。

## 保护与验证

- 保留所有角色下原路由、可见范围、拒绝审计、身份模拟、强制改密和退出行为。
- 早期地图入口保持DOM身份和焦点；其他入口等待完整身份。保留按意图预取与团队动态延后加载。
- 新对话未接通，不接受输入、不请求AI、不伪造回答。现有AI入口按既有配置与角色显示；未开放状态不增加真实服务端能力。
- 公告全文/展开/重试、交流全文/返回/键盘、反馈既有流程保留。不向真实系统提交测试消息。
- 真实生产构建使用同一合成账号/公告/交流，在1280、390、320视口对照；实测导航、焦点、菜单、空白/失败、无横向溢出及请求边界。真机验证与模拟分开登记。
- 适用行为回归、npm run verify、精确PR head CI、独立视觉结论和部署回验分别取证，未执行不算通过。

主页工作面采用16px外边界与10px输入边界，属于本次统一入口的局部视觉变体；不更改全局token或其他模块。桌面地图以20px强调主目的地，手机收回14px以保持列表同组对齐。
