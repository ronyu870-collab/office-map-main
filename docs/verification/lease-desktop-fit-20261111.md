# 桌面团队成交表格适配验证

- 基线：`fb66b36`。范围：租赁成交填报的「团队成交汇总」和团队监控的「团队全量明细」所共用的表格；周度统计表不在范围内。桌面宽度以浏览器的 CSS 视口为准，1024px 起由表格容器分配列宽，窄屏保留横滑。没有改动数据、权限或排序与筛选口径。
- 使用编译后的实际页面，认证与数据替换为本地夹具，共 632 条合成记录。Chrome `157.0.8103.50`、1280×900、管理员、保留 15px 纵向滚动条时，旧版表宽 1460px、可视宽 1223px，末列超出 237px；修复后两者均为 1223px，16 个列头完整可见。打开管理后第 17 列和两个按钮同样可见。
- Chrome 在 1024、1280、1440、1600、1920px 下核对了普通查看、管理、全屏及展开详情：没有横向溢出，表头不截断，公司和楼宇列保有较多空间。另验证提交人筛选、面积排序、分页、调整窗口宽度、楼宇抽屉打开和关闭后焦点恢复，以及团队监控的共享明细表、只读角色和空表。WebKit `26.0` 在 1024、1280、1600px 下验证了查看、管理、全屏及展开详情的列宽。
- Chrome 320、390、1023px 保留原横滑布局，页面本身没有溢出，可滑到最后一列；320 和 390px 到达末端后提示隐藏。手机是视口和触控模拟，未做真机验收。
- 既有年份／季度回归改用渲染后的表格验证列顺序及对应值；列筛选和焦点沿用既有回归。
- 最终 `npm run verify` 通过：类型检查、Lint 零错误、179 个测试文件的 1144 项测试及 Next.js 16.2.12 生产构建。搜索焦点门槛和 `git diff --check` 通过。初次全量验证因旧测试读取已去重的列头源码失败，改用同一实际渲染路径断言后通过。本记录覆盖本地验证，远端检查与发布状态另行核对。
