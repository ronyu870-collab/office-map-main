# 地图 100 项实施与验收

基线：`254df5d`。本轮按五批推进：1–20空间与聚焦、21–40返回与导航、41–60动画与视觉、61–80搜索与业务、81–100异常与跨端验证。

“已实现/修复”表示本轮代码变更；“已核查”表示复用的既有行为及相应执行回归；“部分覆盖/外部限制”明确保留未验条件，不代表100项已全部无条件完成。没有数据库迁移或生产业务写入，保留现有权限与数据计算口径。

## 证据索引

- E1：Vitest全量与相关执行回归、类型检查、Lint、生产构建；最终结果在文末更新。站点/阅读快照及超长历史用例曾在原实现失败。

- E4：[真实高德专项](../../scripts/performance/verify-live-amap.mjs)：真实SDK/瓦片，601项目，隔离业务/鉴权；串行CPU timeline抓栈，并采集四模式选中态。桌面、手机及减少动态效果共52次操作全部通过，本次采样无超过50ms长任务，三份完整CPU profile及四模式截图已保留；不把功能夹具时序当作真实SDK性能，也不将本次结果外推为永久消除偶发任务。

## 未完成的验证条件

- L1：缺有界面桌面浏览器的原生125%/150%/200%缩放操作记录；响应式宽度覆盖不能冒充原生缩放。
- L2：无界面Chrome的原生中键未产生新标签；auxclick快照与window.open新标签可执行验证，系统菜单/原生中键仍需有界面操作。
- L3：缺目标低帧率/GPU设备的逐帧录像；CPU trace、最终画布健康和中断动画断言不能证明所有GPU帧均完美。
- L4：缺iOS/Android真机及VoiceOver/TalkBack运行记录，软键盘、地址栏、刘海安全区和系统手势不能由桌面视口仿真代替。
- L5：缺真机温控/后台恢复及长时堆快照；本轮重复操作和清理测试只能覆盖当前观察窗口，不宣称不存在长期增长。
- L6：AMap公开API不能异步切分内部样式解析，也不能禁止V8正常GC。保留完整CPU证据，应用可修部分继续修；历史未捕获栈不能事后精确归因。
