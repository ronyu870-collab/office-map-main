## 行业依据与精度

| 方法 | 回填记录数 | 含义 |
| --- | ---: | --- |
| 原始行业别名规范化 | 115 | 将明确的旧行业名称映射到现有一级分类 |
| 历史同名一致行业 | 184 | 已有历史记录与原始行业证据的一致分类 |
| 原名称明确业务描述 | 1,151 | 原记录明确律师、银行、医药等业务；属于名称推断，不冒称工商核验 |
| 公开业务资料 | 1,029 | 一次性核查公开主营业务，并记录对应来源 URL；不证明租期时点的工商行业 |
| 人工复核名称变体／短名 | 39 | 核对名称变体与历史来源记录，应用时重新检查来源分类仍一致 |

科技／TMT、投资、综合集团等不足以唯一确定分类的词不自动映射。基金会与金融基金、软件供应商与其客户行业、通信运营服务与设备制造分别处理。少数历史行存在行业错误或冲突，本轮不重写已有分类，不机械扩散冲突值。名称与公开品牌的匹配仍有推断成分，后续可以依据更可靠资料修正；审计保留本次依据及精度。

## 一次性维护工具

- [内部依据计划](../../../scripts/data-maintenance/history-industry-plan.mjs)：按原始分类、明确别名、已有二级分类及同名历史一致值，生成只补空白的计划。
- [私有复核清单入口](../../../scripts/data-maintenance/history-industry-manifest.mjs)：清单在运行时从受限文件传入；检查 ID、预期企业名称、现有分类字典、来源 URL／历史来源 ID。私有清单和企业关键词匹配工作文件不提交仓库。
- [原子写入及回滚](../../../scripts/data-maintenance/history-industry-batch.mjs)：事务、短锁等待、预期条数、重复批次拒绝、写后校验和逐行审计；使用既有 `DATA_UPDATE`，执行者为 `codex`，真实审计类型为 `tool`。

上述文件不被应用导入，不在应用构建、页面访问或 CI 中执行生产回填。CI 仅运行合成数据库验证。合并代码不会再次执行已完成的数据写入。

执行方式为在已授权目标库上运行 `buildIndustryBatch({batch, expectedCount, manifest})` 生成的 SQL；内部依据批次可不传 manifest。实际执行前先查看计划并核对条数。清单结构仅在私有位置保存：`id`、`expected_company`、`industry`、`method`、`evidence`。不得把真实数据复制进示例或日志。

生产批次：`history_industry_20261113_internal_v1`（299）；`history_industry_20261113_reviewed_01` 至 `_08`（各180）；`history_industry_20261113_reviewed_09`（65）。另有全量检索后的 `history_industry_20261113_research_01` 至 `_03`（各180）及 `_04`（174）。每批独立原子提交，14批汇总已在生产回读确认。

如需回滚，使用同一批次号和实际条数生成 `buildIndustryBatch({batch, expectedCount, mode: 'rollback'})`，经当前任务授权后在对应环境执行。它从既有审计恢复原行业、原清洗说明及原更新时间，并写回滚审计；若这些字段随后被修改，整批拒绝，不覆盖后续工作。没有删除审计或业务记录的步骤。

7. 私有清单的身份、已有值、分类、重复ID、URL和应用／回滚保护实际执行。
8. 历史佐证必须仍存在且分类一致；企业名称中的引号和换行不作为SQL执行。
