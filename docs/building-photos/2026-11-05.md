## 上传与启用

- 复核通过的原文件经临时批次函数上传至既有私有 bucket `building-sales-materials`，限定在清单的 50 个独立路径。函数仅接受固定 ID、MIME、尺寸和 SHA-256 匹配的字节，另需批次随机口令和有效 JWT，口令只保留散列及短期截止时间；不允许覆盖。
- 服务端 Storage 下载校验与独立签名 URL 下载校验均按字节和 SHA-256 比较，回执不保留口令、项目密钥或临时签名 URL。已有同路径原图仅在字节完全一致时接受幂等重试。
- 数据库迁移必须先通过精确 PR head 的真实 PostgreSQL 17 CI。数据维护在单个事务中检查管理员、楼宇、50 个存储对象、唯一性和完整性，然后插入 ready 记录与 `BUILDING_PHOTO_IMPORT` 审计。
- 审计记录真实维护账号，`details.executor=codex`，来源为 server，并关联批次、50 个图片 ID、清单摘要、字节数和回读验证结果。维护脚本不声称浏览器登录。
- 成功后临时函数改为仅返回 410，不保留继续上传能力。原两栋试点文件与记录不变。

本文件和 JSON 是批次内容与执行约束，不能单独证明已上线。实际执行状态以生产 `building_photos`、Storage 对象及批次审计回读为准；应用发布以精确提交的 Verify 和生产部署状态为准。
