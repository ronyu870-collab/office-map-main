# 楼宇常规更名执行回归

业务契约见[楼宇身份治理](../../../docs/historical-lease-building-alias-governance.md#管理员常规更名契约)。

`npm run test:db:building-renames` 复用已有 localhost-only PostgreSQL 17 隔离库入口，使用合成身份和记录。它从原迁移加载楼宇、未来供应和名称映射结构及原统一成交读取视图，执行本次实际迁移；不接受远程数据库 URL 或环境中的生产凭据，结束时删除生成的数据库。认证签发、与本任务无关的表及权限不是完整生产复刻。

测试刻意保持楼宇表对 authenticated 的 SELECT-only 权限，private schema 没有 USAGE，复现旧后台写入的 `42501`；另用隔离维护角色复现直接改名造成未来供应/别名未同步。修复后通过限定的管理员 RPC 验证：

- 双向唯一关联回填，歧义不回填；原 ID、业务状态、成交原文、分配和填报不变。
- 迁移自带 5 秒锁等待、45 秒语句超时，以及原楼宇/未来供应业务字段不变量检查；注入旧触发器副作用后，验证全部 DDL 和数据回滚，新增列也不残留。
- 正常更名、重复保存、响应丢失后的重试、多次更名与改回原名、手工补充别名、legacy 空值。
- 其他楼宇名称/别名、项目级映射冲突、过期请求、空名及异常列表的拒绝。
- editor/viewer/anon 无法更名；管理员仍不能直接 UPDATE 楼宇表，也不能直接修改映射表。
- 未扩大表写权限或 private schema USAGE；公共 invoker 和私有 definer 包装实际执行。
- 未来供应直改/更换关联被拒绝；同步或审计失败整笔回滚；两楼宇并发争用同名时只有一笔成功。

运行器还必须执行 `ui.integration.tsx` 的真实手机编辑组件 → 共享 Supabase SDK → 本机 HTTP Data API 测试适配器 → PostgreSQL 的保存/回读、数据库冲突后保留输入与重试、多行别名保存三项测试。这里的 HTTP 适配器是测试替身，不能冒称真实 PostgREST；数据库行为和组件/SDK 均实际执行。

Verify 工作流已增加本命令，使用它的 PostgreSQL 17 服务端口 `LEASE_TEST_PG_PORT`。本地须明确设置 `LEASE_TEST_ALLOW_LOCAL=disposable` 和专用测试服务端口；主版本不为 17 时拒绝运行。普通 `npm test` 保留快速组件、模型和地图搜索回归，集成文件仅由数据库运行器专用配置执行，必需验证没有被 skip。

## 本地生产构建浏览器补充

可设置 `BUILDING_RENAME_BROWSER=1`，同时明确提供 `PLAYWRIGHT_MODULE`、`CHROME_PATH`、`POSTGREST_PATH` 和证据目录 `BUILDING_RENAME_BROWSER_EVIDENCE`，运行同一命令。它在现有合成库上启动实际 PostgREST、独立 Next production webpack 和 Chrome，验证真实 AG Grid 全行编辑、多行别名、保存/刷新及 390px 手机布局。客户端使用生产共享 Supabase 单例；认证用户端点与客户端行为日志在测试外壳隔离，不使用生产账号。

`BUILDING_RENAME_VISUAL_PAIR=1` 补充等价数据的前后截图：只在隔离工作区临时加载 HEAD 的两处原显示适配器，构建后恢复，分别截图且不提交业务写入。该模式是视觉对照，不是生产业务验收或绕过正常回归的方式；运行时不要在同一工作区并发编辑被替换的两处文件。

浏览器补充测试退出后关闭浏览器、Next/PostgREST 和临时外壳；数据库由父运行器清理。桌面 Chrome 的触控/手机布局不能代替真实 iOS Safari、Android Chrome 或生产会话验收。

## 发布顺序与回退

迁移先增加可空的固定关联及唯一 FK，并只回填确定的双向唯一关系，再安装受保护 RPC、触发器和原子审计。发布前用目标库只读预检列明未关联/多候选记录，保留对应原件和恢复依据；不能为赶进度把歧义指向某个楼座。新建或尚未核实的未来项目，必须先按身份治理建立可靠关联，未建立前更名会被拒绝。

先在隔离/预览中应用迁移及匹配代码，通过回归，再按项目授权和恢复门槛决定生产启用。界面代码先于迁移时 RPC 会明确报错并保留输入，不会退回到无保护写入；迁移先于界面时旧入口仍没有楼宇表写权限。任何生产应用都须独立授权和回读。

紧急撤回时先停用更名入口，并撤销公共及私有更名 RPC 的 authenticated EXECUTE，再回退对应界面；保留已有 ID、旧名、映射和审计，不用回退代码批量恢复历史名称。是否移除触发器或固定关联是另一次受控数据库变更，不能在仍有更名请求时删除保护。
# 合并回归

本目录 `run.mjs` 在既有更名场景后执行 `merges.mjs`，同一CI入口 `npm run test:db:building-renames` 不跳过新增合并。使用同主版本真实PG17、实际迁移与权限，验证旧实现缺少解析/指标分裂，完整前像冲突、同期间指标拒绝、意外FK、审计失败后的数据/触发器回滚、锁定指标时间和精度保持、分配填报不变、幂等、owner限定、归档不可写/删除/多级合并，以及旧ID写入和更名。

并发组使用两个真实PG连接：维护事务暂不提交时，authenticated调用者用旧ID新增季度填报，确认被父身份行锁阻塞；维护提交后必须落到主档，并验证调用者仍无楼宇UPDATE授权。该场景防止“先读旧ID、等待FK、提交到归档ID”的竞态。

UI集成运行真实GridPanel、共享SDK、回环HTTP测试适配器和PG；新增旧ID解析、归档列表排除及真实Next趋势处理器→SDK→HTTP适配器→PG读取，认证上下文为隔离夹具，不冒充生产管理员会话或真实PostgREST。手机布局与真机证据、生产恢复和应用/数据发布分别记录。
