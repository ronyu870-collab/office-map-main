## 二、AI 数据治理：如何保证 100 个值可追溯

生产事务在每条写入前均检查：真实 `building_id`、在用/跟踪/存量/未合并身份、楼书对应的 `building_id`、允许写入的目标表和字段类型、字段确实为 SQL NULL、不存在现行来源记录、来源资料行与楼宇归属一致、来源事实文本未发生改变、目标主键+字段唯一。

每条入库字段在同一事务内同时建立：
1. `building_data_field_provenance` 一条当前来源记录，含目标表/字段、新值、来源类型及可信度层级、原始记录 ID、资料原件名/页索引（适用时）、单位、楼宇口径、查询时间、批次号和 `AI_ASSISTED_INTERNAL_BACKFILL` 标签。
2. `audit_logs` 一条 `AI_FIELD_FILL` 操作，`user_id='codex'`、`actor_kind='tool'`、`request_source='codex_mcp'`，含唯一 `event_id`、原值 JSON NULL、新值、独立 `evidence_group_id`、`ai_assisted=true`、`reversible=true`、批次 ID。
3. 对外 GitHub `manifest-references.csv` 仅保存业务主键、字段、证据和审计 UUID 等**引用**，不导出任何 Broker 原始业务填报明细、私人信息、密钥或需保密的实际业务字段值；实际值只留在生产数据库与现有 AI 来源/审计表。

本批所有来源的 `verification_status='legacy_backfill'`，档案来源 `source_type='brochure'`、`source_tier='secondary'`，其余内部同步 `source_type='other'`、`source_tier='legacy_unknown'`。**未宣称** `cross_verified`、官方人工确认、正式 LEED 查询或外部独立资料核验。
